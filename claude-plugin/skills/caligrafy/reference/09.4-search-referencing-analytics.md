# 9.4 Search Referencing and Analytics

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.4-Search-Referencing-and-Analytics
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

Search engines read three things Caligrafy helps with: the **description** of each page (the line under its title in
the results), the proof that the site is yours (**Google Search Console**), and, once people come, **Google
Analytics**. The description comes from `metadata()` ([rich cards](https://github.com/caligrafy/caligrafy-quill/wiki/9.3-Metadata-&-Social-Rich-Cards));
analytics is one setting of `.env`.

## With Claude

```text
Make Bookshelf ready for Google: a description for every page, and Google Analytics with the id G-XXXXXXX in production
```

Claude sets the `description` of `metadata()` in `application/config/config.php` and tells you to put
`GOOGLE_ANALYTICS_ID` in the production `.env` (on Caligrafy Cloud: `php caligrafer.php cloud secret set <app>
GOOGLE_ANALYTICS_ID=G-...`). It does not sign in to Google for you.

**Check**

+ The page source has `<meta name="description" ...>`.
+ Online, with `APP_ENV=production`, the source has `googletagmanager.com/gtag/js?id=G-...`; locally it has none.

## By hand

**1. A description for every page.** Set `description` in the `metadata(...)` call of `application/config/config.php`
(the whole call is in [rich cards](https://github.com/caligrafy/caligrafy-quill/wiki/9.3-Metadata-&-Social-Rich-Cards)):

```php
metadata(array(
    'site_name' => 'Bookshelf',
    'title' => 'Bookshelf: your books, lent and returned',
    'description' => 'Know who has your books and when they come back.',
));
```

Every page of `default/master/site` then has
`<meta name="description" content="Know who has your books and when they come back."/>`. A page gets its own
description as in [a card per book](https://github.com/caligrafy/caligrafy-quill/wiki/9.3-Metadata-&-Social-Rich-Cards#card).

**2. Prove the site is yours to Google.** In [Google Search Console](https://search.google.com/search-console), add a
**URL prefix** property with the app's address (`https://bookshelf.example.com`) and choose **HTML file**. Download the
file Google gives (`google<code>.html`), put it at the **root of the project** (next to `index.php`), commit it and
deploy. Apache serves a file that exists as it is, so `https://bookshelf.example.com/google<code>.html` answers the
file; press **Verify**. A **Domain** property is verified with a DNS record at your domain's registrar instead.

**3. Google Analytics.** Create a Google Analytics property and copy its measurement id (`G-...`). In the `.env` of
the production server:

```text
APP_ENV=production
GOOGLE_ANALYTICS_ID=G-XXXXXXX
```

Every page of `default/master/site` then loads `https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX`. With
`APP_ENV=local` the tag is never printed, so your own visits while you develop are not counted.

**Check**

+ The source of `/` has the description.
+ Search Console says *Ownership verified*.
+ Online, the source has the `gtag` script with your id; Analytics shows your visit in its real-time view.

## Reference

| What | Where it comes from | Printed by |
|---|---|---|
| `<meta name="description">` | `metadata()`'s `description`, or the view's `$metadata` | `default/modules/metadata.pug`, in every master |
| Google Analytics (`gtag`) | `GOOGLE_ANALYTICS_ID`, only with `APP_ENV=production` | `site.pug` always; `layoutblocks.pug` when the view gets `'google_analytics' => true` |
| `keywords()` | `keywords('books, lending')` | not printed in pages; given to Vue apps as `env.keywords` |
| Search Console proof | an HTML file at the root of the project, or DNS | Apache, as a file |

+ `keywords($value)` keeps a string of keywords for the request and returns it. Google ignores the `keywords` meta tag,
  so the masters do not print one.
+ The layouts print no `google-site-verification` meta tag: use the HTML file or DNS.
+ Files at the root of the project, such as `robots.txt` or a `sitemap.xml` you write, are served as they are, except
  dotfiles, `caligrafer.php`, `composer.*`, `docker-compose.yaml`, `package*.json` and `.sql`, `.log`, `.bak`, `.ini`,
  `.sh`, `.env` files, which `.htaccess` denies.

## Other ways

**The older masters.** A view on `default/master/layoutblocks.pug` gets analytics only when its route passes it:
`view('default/index', array('metadata' => metadata(), 'google_analytics' => true))`. Pages on `site.pug` need nothing.

## Common mistakes

+ **No analytics online.** `APP_ENV` is not `production`, or `GOOGLE_ANALYTICS_ID` is empty in the server's `.env`
  (on Caligrafy Cloud, set it with `cloud secret set`, then deploy).
+ **The verification file answers the app's 404.** It is in `public/` or `application/`: put it at the root of the
  project.
+ **Search results show an old description.** Google reads the page again on its own schedule: ask for a new crawl in
  Search Console (URL inspection).
