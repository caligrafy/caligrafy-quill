# 9.7.5 Validations

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.5-Validations
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - With a non-2xx status (`http_response_code(422)` before `api()`), axios rejects: read the payload in `error.response.data` (G21).

**Validation** decides whether what a person typed is acceptable. In Caligrafy it happens once, on the server, in the capability's `$rules`: the same rules answer the Vue app, the Pug pages, REST and AI agents, and the messages come back one per field. A Vue app shows those messages; it can also check the obvious cases before sending, from the same rules, so the person waits less.

## With Claude

Ask for the rule, not for the screen: "a book's title needs at least 2 characters". Claude changes `$rules` in the capability (`/caligrafy-quill:new-capability` knows the [rules](https://github.com/caligrafy/caligrafy-quill/wiki/6.-Validation)), runs `php caligrafer.php client` again, and the forms show the new message with no change.

**Check** before you say OK:
+ The rule is in the capability's `$rules`, not only in the Vue script.
+ `php caligrafer.php call create_book title=D author_id=2 published_year=1987` answers `invalid` with the message.
+ The Vue form shows that message under the field.

## By hand

You add a rule to `create_book` and show it in the Bookshelf app of [Forms](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms), then add a check before sending. Commands run in the project folder with the Docker server.

**1. The rule.** In `application/services/Bookshelf/CreateBook.php`, change the title's rule in `$rules` to:
```php
        'title' => 'required|min_len,2|max_len,200',
```

**2. Try it from the command line.** Run:
```bash
docker compose exec dev-box php caligrafer.php call create_book title=D author_id=2 published_year=1987
```
Expected:
```json
{
    "error": {
        "code": "invalid",
        "message": "Some of the inputs are invalid",
        "fields": {
            "title": "The Title field needs to be at least 2 characters"
        }
    }
}
```

**3. Update the client.** Run `docker compose exec dev-box php caligrafer.php client public/js/capabilities.js`. The rules are on the server, so the functions do not change, but `GET /capabilities` now describes `title` with `"minLength": 2` (and `published_year` with `"minimum": 1450, "maximum": 2100`).

**4. See it in the app.** Open `http://localhost:8080/bookshelf`, type `D`, choose an author, type `1987`, press **Add book**: `The Title field needs to be at least 2 characters` appears under the title. The `addBook()` of [Forms](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms) already puts `e.fields` in `errors`.

**5. Check before sending.** In `public/bookshelf/scripts/main.js`, add this function above `const app = Vue.createApp({`:
```js
// The obvious cases, from the capability's own description: the server still decides
function check (schema, input) {
    const errors = {}
    for (const [field, rule] of Object.entries(schema.properties)) {
        const value = input[field] === null || input[field] === undefined ? '' : String(input[field])
        if ((schema.required || []).includes(field) && value === '') errors[field] = 'Required'
        else if (rule.minLength && value.length < rule.minLength) errors[field] = 'At least ' + rule.minLength + ' characters'
        else if (rule.maxLength && value.length > rule.maxLength) errors[field] = 'At most ' + rule.maxLength + ' characters'
        else if (rule.minimum !== undefined && value !== '' && Number(value) < rule.minimum) errors[field] = 'At least ' + rule.minimum
        else if (rule.maximum !== undefined && value !== '' && Number(value) > rule.maximum) errors[field] = 'At most ' + rule.maximum
    }
    return errors
}
```
At the end of `mounted()`, after `await this.load(1)`, add:
```js
        this.schema = (await this.api.capabilities()).find(c => c.name === 'create_book').input
```
At the start of `addBook()`, before `this.errors = {}`, add:
```js
            const found = this.schema ? check(this.schema, this.book) : {}
            if (Object.keys(found).length) { this.errors = found; return }
```
Reload, type `D`, choose an author, type `1987`, press **Add book**: `At least 2 characters` appears at once, without a call (the network panel shows no `POST /capabilities/create_book`). A year of `987` shows `At least 1450`.

**Check**
+ Removing the check of step 5 still refuses the book, with the server's message: the server is the rule.
+ The Pug page `/books` and `curl -X POST ... /capabilities/create_book` refuse the title `D` with the same message.

## Reference

### Where each part lives

| Part | Where | Effect |
| --- | --- | --- |
| `$rules` | the capability | GUMP rules per input: `required`, `max_len,255`, `min_len,2`, `integer`, `valid_email`, `exists,authors,id`, `unique,books,isbn`... ([all rules](https://github.com/caligrafy/caligrafy-quill/wiki/6.-Validation)). Only these inputs reach `handle()` |
| `$filters` | the capability | applied before the rules: `trim`, `sanitize_string`... |
| `$descriptions` | the capability | what each input is, in the schema clients and agents read |
| `ServiceError::invalid(['author_id' => 'There is no such author'])` | `handle()` | a refusal decided by code, with the same shape |
| `e.fields` | the Vue app | `{field: message}` of a `CapabilityError` whose `code` is `invalid` |
| `capabilities()` | the Vue app | each capability's `input`: a JSON schema with `required`, `maxLength`, `minLength`, `format` (email, uri), `enum`, `type` |

### Messages

Each field gets one message, the first rule it breaks, in GUMP's words with the field's name: `The Published Year field is required`, `The Title field needs to be at least 2 characters`, `The Published Year field needs to be a numeric value, equal to, or higher than 1450`. The whole refusal is `422` with `{"error": {"code": "invalid", "message": "Some of the inputs are invalid", "fields": {...}}}`.

## Other ways: a controller that validates

A controller route can still validate with `$this->check()` and answer with `api()`:
```php
$errors = $this->check($this->request->parameters(), array('title' => 'required|max_len,200', 'author_id' => 'required|integer'));
if ($errors !== true) {
    http_response_code(422);
    return api(array('error' => true, 'message' => 'Some of the inputs are invalid', 'errors' => $errors));
}
```
`fetch` then gets `response.status === 422` and the payload from `await response.json()`; axios rejects and puts it in `error.response.data`. The rules then live in that controller only: a capability gives them to every channel.

## Common mistakes

+ **The rule only in JavaScript**: REST, agents and anyone with `curl` skip it. Put it in `$rules`.
+ **A client check stricter than the server**: people are refused for no reason. Build it from `capabilities()`, as in step 5.
+ **An input sent but missing from `$rules`**: it is dropped before `handle()`. Add it with `''` (no rule) if it needs none.
