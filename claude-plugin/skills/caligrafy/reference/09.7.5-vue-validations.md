# 9.7.5 Validations

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.5-Validations
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - With a non-2xx status (`http_response_code(422)` before `api()`), axios rejects: read the payload in `error.response.data` (G21).

Validation is an important piece from the moment there is an exchange of information between a user and system. Nowadays, validation can either take place on the server side or on the client-side or both. The preferred - and more robust - way is to validate on both ends. 

## Server-Side Validation
Caligrafy provides a robust server-side validation with a flexible way of formatting the response to be sent back to the client.

> Learn more about Caligrafy validation [here](https://github.com/caligrafy/caligrafy-quill/wiki/6.-Validation)

In Caligrafy, validation typically takes place in the `Controller`. This is an example of how the response can be formatted to be consumed by the client:
```php
// Input validation
$parameters = $this->request->parameters();
$validate = $this->check(array_merge($parameters, $_FILES), array('title' => 'required|alpha_space|max_len,18',
                                                       'short_description' => 'required|max_len,200',
                                                       'category' => 'required|alpha',
                                                       'description' => 'required',
                                                       'image_url' => 'required_file|extension,png;jpg;gif;jpeg'
                                                       ));

// invalid inputs
if ($validate !== true) {
   http_response_code(422);
   return api(array('error' => true, 'status' => 'danger', 'message_header' => 'Whoooops, something went wrong', 'message' => 'Some of the inputs are invalid. Make sure all the required inputs are entered properly', 'errors' => $validate));
}

```

When the `api()` method is called for returning a response to the client, you can send any information back. All the information sent back can be retrieved by `Vue` in the `response` variable and used accordingly in the markup. With an error status such as `422`, `axios` rejects the promise: the payload is then in `error.response.data`, for example `.catch(error => (this.error = error.response.data))`:

```html
<template v-if="error">
    <div class="error">
         <p>{{ error.message_header }}</p>
         <p>{{ error.message }}</p>
    </div>
</template>

```
