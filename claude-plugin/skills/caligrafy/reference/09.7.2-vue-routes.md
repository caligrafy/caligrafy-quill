# 9.7.2 Routes (data routes vs page routes)

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.2-Routes
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - Page-route pattern verified in `ClientController` + `views/Client/app.pug`: the path must END with the app folder name; `appName`/`app` view vars select `public/<appName>/<app>.php` (names limited to `[A-Za-z0-9_-]`); all other view vars are injected (escaped) into JS `env` via `loadEnvironment` (gotchas G15).

A Vue app as a library needs two kinds of routes on the server, both in `application/config/routing/web.php`: a **page route**, which serves the app's markup with its `env`, and the **capability routes**, which the app calls for its data. Routing between screens inside the browser is the job of a single page app ([Routing for single page apps](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.2-Routing-for-Single-Page-Applications)).

## With Claude

`/caligrafy-quill:new-app app <name>` adds the page route; `/caligrafy-quill:new-capability` adds capabilities and keeps `Route::capabilities('/capabilities')` in place. To change a route, ask: "serve the bookshelf app at /shelf, for signed-in people only".

**Check** before you say OK:
+ The page route is a `Route::page(..., 'Client/app', ...)` above `Route::run();`, with `appName` the folder in `public/`.
+ `Route::capabilities('/capabilities');` is in `web.php` once.
+ Opening the address while signed out does what was asked (the app, or the sign-in page).

## By hand

You serve the Bookshelf app of [Setting up Vue as a library](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.0-Setting-up-Vue.js-as-a-library) three ways and give it its first books from the server.

**1. The ready-made address.** The template's `web.php` serves every client app at `/apps/<name>`. Its line names the example controller; write the same address declared, and open it:
```php
    Route::page('/apps/{appName}', 'Client/app', ['query' => ['app' => 'index']]);
```
Replace the `Route::get('/apps/{appName}', ...)` line with it. Open `http://localhost:8080/apps/bookshelf`: the app opens with no route of its own. It serves any folder of `public/` whose name is made of letters, digits, `-` and `_`.

**2. Your own address.** In `application/config/routing/web.php`, above `Route::run();`, write:
```php
    // BOOKSHELF: the Vue app (public/bookshelf/index.php)
    Route::page('/bookshelf', 'Client/app', ['with' => ['appName' => 'bookshelf', 'app' => 'index']]);
```
Open `http://localhost:8080/bookshelf`: the same app, and in the console `env.authorized` and `env.user` say who is signed in.

**3. The first books from the server.** Change the route to:
```php
    Route::page('/bookshelf', 'Client/app', ['with' => ['appName' => 'bookshelf', 'app' => 'index'], 'data' => ['books' => 'list_books']]);
```
Reload, and type `env.books` in the console: `{data: Array(...), total: ..., page: 1, per_page: 20, pages: ...}`, the answer of `list_books`, in the page itself. The script can show it at once (`this.books = env.books.data`) and call the client for the next pages.

**4. The data routes.** Check that `web.php` has, once:
```php
    Route::capabilities('/capabilities');   // the capabilities for the JS client of the Vue apps
```
Run `curl -H "Accept: application/json" http://localhost:8080/capabilities`: `{"data":[...],"csrf":"..."}`.

**Check**
+ `http://localhost:8080/bookshelf` and `http://localhost:8080/apps/bookshelf` open the same app.
+ `http://localhost:8080/apps/nothere` answers `This client app does not exist...`.

## Reference

### Page routes

| Route | What it does |
| --- | --- |
| `Route::page('/bookshelf', 'Client/app', ['with' => ['appName' => 'bookshelf', 'app' => 'index']])` | serves `public/bookshelf/index.php`. Takes every option of [`Route::page`](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#parameterview): `data` (read-only capabilities, their answers in `env`), `signedIn` (visitors go to `/login`), `level`, `notFound`; `env` gets `authorized` and `user` |
| `Route::page('/apps/{appName}', 'Client/app', ['query' => ['app' => 'index']])` | serves `public/<appName>/index.php`, or `public/<appName>/<file>.php` with `?app=<file>`. `query` lists what `env` gets of the query string |
| `Route::page('/bot/{appName}', 'Client/app', ['query' => ['app' => 'index', 'botSkillId']])` | a bot app: `?botSkillId=` is its assistant |
| `Route::page('/ml/{appName}', 'Client/app', ['query' => ['app' => 'index']])` | a machine learning app |
| `Route::get('/apps/{appName}', 'Caligrafy\\Controllers\\ClientController')`, and the same for `/bot/`, `/ml/` | what the template's `web.php` ships: the same result, and `env` gets the whole query string |

`appName` and `app` must be made of letters, digits, `-` and `_`, and only files directly inside `public/<appName>/` are served; anything else shows `This client app does not exist`.

### Data routes

| Route | What it serves |
| --- | --- |
| `Route::capabilities('/capabilities')` | `GET /capabilities`: the capabilities the caller may use and the CSRF token; `POST /capabilities/<name>`: calls one. The generated JS client uses it |
| `Route::capability('GET', '/api/books', 'list_books')` | one capability at a REST address, for other programs ([Build once: REST](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#rest)) |

## Under the hood

+ **`ClientController`** (`application/controllers/core/AI/ClientController.php`) takes the last part of the path as `appName` and `?app=` as the markup file (default `index`), then returns `view('Client/app', ...)` with the query string. A page that first chooses what to show is a web-only capability: `return Web::view('Client/app', ['appName' => 'bookshelf', 'app' => 'index', 'shelf' => $shelf]);`.
+ **A closure** `Route::get('/bookshelf', function () { return view('Client/app', ['appName' => 'bookshelf', 'app' => 'index']); });` works too, without `authorized` and `user`. `Route::page` replaces both.
+ **Controller data routes** (`Route::get('/api/shelf', 'BookController@index')` returning `api([...])`) still answer JSON, in code that has them: see [Requests, other ways](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests). Capabilities replace them.

## Common mistakes

+ **`appName` that is not the folder name**: `This client app does not exist`.
+ **A `data` capability that writes**: `Route::page` accepts only read-only capabilities (`500` on every visit).
+ **Expecting the query string in `env` with `Route::page`**: only the names listed in its `query` option reach it.
+ **Two `Route::capabilities` lines**: keep one.
