# 9.9.8 Languages

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.8-Languages
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A Caligrafy project can speak several languages (Caligrafy Quill 2.28.0+): its pages, its form messages and its
numbers, dates and amounts follow each visitor's language, and Arabic, Hebrew or Persian pages are laid out right to
left. One file per language holds the app's words; one setting lists the languages.

## What it is made of

| Part | What it does |
| --- | --- |
| `APP_LOCALES=en,fr,ar` in `.env` | The app's languages, in order. Empty means English only |
| `APP_LOCALE=en` | The language of a visitor who asks for none. Empty means the first of `APP_LOCALES` |
| `application/lang/<code>.json` | The words of one language, as nested objects: `{"home": {"title": "Good food"}}` is the key `home.title` |
| `t('home.title')` in a view | The word in the visitor's language |
| `html(lang=locale(), dir=lang_dir())` | The page's language and direction: `rtl` for Arabic, Hebrew, Persian, Urdu and a few others |
| `lang_url('fr')` | This page in another language, for a language menu |
| `Caligrafy\Lang` | The same in PHP, plus `money()`, `number()` and `date()` in each language's way |

The master layouts of a new project (`site.pug`, `layout.pug`) already set `lang` and `dir`, and Caligrafy's
stylesheets use logical properties, so a right-to-left page mirrors by itself.

## The files

`application/lang/en.json`:

```json
{
  "home": {
    "title": "Good food. Better hours.",
    "hello": "Hello {name}"
  },
  "tables_left": "{count} table left|{count} tables left",
  "fields": { "email": "Email" },
  "validation": { "required": "Please fill in {field}" }
}
```

`application/lang/ar.json`:

```json
{
  "home": { "title": "أكل طيّب، بأوقات أحلى", "hello": "أهلاً {name}" },
  "tables_left": "بقيت طاولة واحدة|بقي {count} طاولات",
  "fields": { "email": "البريد الإلكتروني" },
  "validation": { "required": "الحقل {field} مطلوب", "valid_email": "{field} غير صالح" }
}
```

- `{name}` is replaced by the variable of that name: `t('home.hello', ['name' => $user->name])`.
- With a `count`, `"one|other"` or `"zero|one|other"` picks the form: `t('tables_left', ['count' => 3])`.
- A word missing in a language shows in `APP_LOCALE`'s language, then as its key: a page never shows nothing.
- `php caligrafer.php doctor` says when a language has no file, a file is not valid JSON, or words are missing.

## The visitor's language

In this order:

1. `?lang=fr` in the address: used, and remembered in the cookie `lang` for a year.
2. The cookie `lang`, from an earlier visit.
3. The browser's languages (`Accept-Language`): `fr-CA` matches `fr`.
4. `APP_LOCALE`.

Only the codes of `APP_LOCALES` are ever used. The command line, scheduled jobs and background jobs use `APP_LOCALE`;
a job that writes to a person in their language calls `Lang::set($person->language)` first.

A language menu:

```pug
nav.cq-lang
  each $code in locales()
    a(href=lang_url($code), aria-current=$code === locale() ? 'true' : null)= strtoupper($code)
```

## In a view

```pug
extends ../default/master/site

block content
  section.cq-hero.cq-hero--page
    h1.cq-display= t('home.title')
    p.cq-lead= t('tables_left', ['count' => $deal['tables_left']])
```

A page's script gets the words it needs as JSON, kept small with a prefix:

```pug
script window.LANG = !{lang_json('app')}
```

## Form messages

The capabilities' validator speaks the visitor's language when its library (GUMP) has it: French, Spanish, German,
Italian, Portuguese, Turkish, Persian, Hebrew and others. It has no Arabic: put the messages in the file's
`validation` object, keyed by rule (`required`, `valid_email`, `max_len`, `min_len`...), with `{field}` and `{param}`.
Any message there replaces GUMP's, in every language. The `fields` object names the fields in each language.

## Money, numbers and dates

```php
use Caligrafy\Lang;

Lang::money(1234.5, 'USD');          // $1,234.50 in English, 1 234,50 $US in French
Lang::money(45, 'AED', 'ar');        // in Arabic numerals and its currency's way
Lang::number(1234.5, 1);             // 1,234.5 / 1 234,5
Lang::date('2026-11-25', 'long');    // November 25, 2026 / 25 novembre 2026
```

They use PHP's `intl` extension (in the Docker image); without it, plain `1,234.50 USD` and `25 Nov 2026`.

## Good to know

- Caligrafy's own pages (sign-in, sign-up, the welcome page) are in English: an app that needs them in other
  languages copies them into its views with `t()`. `Route::auth`'s `messages` option takes `t(...)` values.
- A project made before 2.28.0 keeps its own `site.pug`: change `html(lang="en")` to
  `html(lang=locale(), dir=lang_dir())` there.
- The helpers `t`, `locale`, `locales`, `lang_dir`, `lang_url` and `lang_json` are only defined when the app has not
  defined a function of the same name.
