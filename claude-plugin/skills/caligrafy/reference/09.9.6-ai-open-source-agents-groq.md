# 9.9.6 Open Source Agents (llama, Mistral, etc.)

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.6-Open-Source-Agents-(llama,-Mistral-etc.)
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - `AGENT_PROVIDER` (empty = groq) picks the provider; keys `GROQ_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`, `OPENROUTER_API_KEY`, then `AGENT_API_KEY` (`Agent::settings()`). `delegate()` is positional/named: `delegate(model:, messages:, response_format:, stream:, tool_choice:, tools:)`; an empty model uses `$agent->model()` (Groq `openai/gpt-oss-120b`, vision `qwen/qwen3.8-27b`; per-provider defaults in api-reference.md). Audio is Groq only (G17, G33).

Open models (Llama, gpt-oss, Qwen, Mistral and others) run at several providers that speak the OpenAI API: Groq,
Together AI, Fireworks AI, OpenRouter, a local Ollama, or your own endpoint. `Caligrafy\Agent` talks to all of them with
the same code: only `.env` changes. You put the call in a capability, so it reaches a web page, a Vue app, the REST API
and AI agents. In the Bookshelf example, `recommend_books` suggests books to read and `describe_cover` describes an
uploaded cover image.

## Choosing a provider

| Provider | `AGENT_PROVIDER` | Key | Default text model | Default vision model | Audio (`transcribe`, `translate`) |
|---|---|---|---|---|---|
| [Groq](https://console.groq.com) | empty or `groq` | `GROQ_API_KEY` | `openai/gpt-oss-120b` | `qwen/qwen3.8-27b` (preview) | yes, `whisper-large-v3` |
| [Together AI](https://www.together.ai) | `together` | `TOGETHER_API_KEY` | `openai/gpt-oss-120b` | `Qwen/Qwen3.5-9B` | no |
| [Fireworks AI](https://fireworks.ai) | `fireworks` | `FIREWORKS_API_KEY` | `accounts/fireworks/models/gpt-oss-120b` | `accounts/fireworks/models/glm-5p3-flash` | no |
| [OpenRouter](https://openrouter.ai) | `openrouter` | `OPENROUTER_API_KEY` | `meta-llama/llama-3.3-70b-instruct` | `meta-llama/llama-4-maverick` | no |
| [Ollama](https://ollama.com) (your machine) | `ollama` | none | `llama3.2` | `llama3.2-vision` | no |
| any OpenAI-compatible API | `custom` | `AGENT_API_KEY` (optional) | `AGENT_MODEL` (required) | `AGENT_VISION_MODEL` | no |

**Where is Llama?** (October 2026) Groq retired its Llama chat models in August 2026. Together AI and Fireworks AI serve
Llama only on dedicated or on-demand deployments, so their defaults are `gpt-oss-120b`. For Llama pay-per-token choose
**OpenRouter**; for free Llama on your own computer choose **Ollama**. Models change often: `docker compose exec dev-box php caligrafer.php doctor
--only agent` lists those of your key.

Costs: Groq has a free developer tier with rate limits; Together, Fireworks and OpenRouter bill per token (OpenRouter
from prepaid credits; models whose id ends with `:free` cost nothing but have daily limits); Ollama is free and as fast
as your computer. Check each provider's pricing page.

## With Claude

```text
/caligrafy-quill:new-capability recommend_books ai:use read-only
Recommend three books from the books a reader liked, with an open model through Caligrafy\Agent (Llama on OpenRouter).
```

Claude writes the capability in `application/services/`, sets the provider settings it needs in `.env` (names only:
you paste the key), and runs `docker compose exec dev-box php caligrafer.php doctor --only agent`. For a chat app in Vue,
`/caligrafy-quill:new-app app chat` follows the plugin's AI chat recipe; it asks which provider when you say "Llama".

**Check**
- The key of the chosen provider is in `.env`, nowhere else; `doctor --only agent` shows the provider, the key accepted
  and the models available.
- `new Agent()` sits in a `try`: a missing key or an unknown provider becomes a readable refusal.
- `api_success` is checked: provider errors come back as its `response` text.
- A capability that receives an image reads a saved upload, never a URL sent by the caller.

## By hand

The project has sign-in, `Route::capabilities('/capabilities')` and `Route::mcp('/mcp')` (see the
[Quickstart](https://github.com/caligrafy/caligrafy-quill/wiki/Quickstart)). Without Docker (Composer with MAMP, XAMPP or LAMP), run the same commands without `docker compose exec dev-box` and open your own address.

### Step 1: Choose the provider in `.env`

OpenRouter (Llama in the cloud), with a key from [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys):

```text
AGENT_PROVIDER=openrouter
OPENROUTER_API_KEY=sk-or-...
AGENT_MODEL=
AGENT_VISION_MODEL=
```

Or Ollama on your computer (see [Running Llama locally with Ollama](#ollama)):

```text
AGENT_PROVIDER=ollama
AGENT_API_BASE=
```

Or Groq (the default when `AGENT_PROVIDER` is empty), with a key from [console.groq.com/keys](https://console.groq.com/keys):

```text
AGENT_PROVIDER=
GROQ_API_KEY=gsk_...
```

Run:

```bash
docker compose exec dev-box php caligrafer.php doctor --only agent
```

Expected, for example:

```text
 Agent provider
  OK    AGENT_PROVIDER: openrouter (OpenRouter), https://openrouter.ai/api/v1
  OK    OpenRouter: key accepted, ... models available
  OK    AGENT_MODEL: meta-llama/llama-3.3-70b-instruct is available
  OK    AGENT_VISION_MODEL: meta-llama/llama-4-maverick is available
```

With Groq, the Groq check runs instead and warns about retired models.

### Step 2: The capability

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/RecommendBooks --scope ai:use --read-only
```

Replace **`application/services/Bookshelf/RecommendBooks.php`** with:

```php
<?php
/**
 * RecommendBooks: book ideas from an open model (Llama, gpt-oss, Qwen...) through the Agent class
 */

use Caligrafy\Agent;
use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'recommend_books',
    description: 'Recommends three books for a reader from the books they liked. Returns {model, recommendations}.',
    scope: 'ai:use',
    readOnly: true
)]
class RecommendBooks extends Service
{
    public $rules = array(
        'liked' => 'required|max_len,1000',
    );

    public $filters = array(
        'liked' => 'trim',
    );

    public $descriptions = array(
        'liked' => 'Books the reader liked, for example "Kindred, The Dispossessed"',
    );

    public function handle(array $input, Context $context)
    {
        try {
            $agent = new Agent();   // provider, key and models come from .env (AGENT_PROVIDER...)
        } catch (Exception $e) {
            throw ServiceError::conflict('The AI provider is not set up: ' . $e->getMessage());
        }

        $result = $agent->delegate(messages: array(
            array('role' => 'system', 'content' => 'You are a librarian. Answer with a list of three books, one per line: title, author, and why in one sentence.'),
            array('role' => 'user', 'content' => 'I liked: ' . $input['liked']),
        ));
        if (empty($result['api_success'])) {
            throw ServiceError::conflict((string) $result['response']);   // the provider's message
        }

        return array('model' => $agent->model(), 'recommendations' => $result['response']);
    }
}
```

What it does:
+ `new Agent()` reads the provider, its key and its models from `.env`. It throws when the provider is unknown, its key
  is missing, or `custom` has no `AGENT_API_BASE`: the capability turns that into a `conflict` refusal (409) with the
  reason. (The agent is created in `handle()`, not through the constructor, so that this refusal is readable.)
+ `delegate(messages: ...)` uses the provider's default model and returns `['api_success' => true, 'response' => text]`,
  or `api_success` false with the provider's error (`OpenRouter error 401: ...`, *is Ollama running?*).

```bash
docker compose exec dev-box php caligrafer.php call recommend_books liked="Kindred, The Dispossessed"
```

Expected (the text varies):

```json
{
    "data": {
        "model": "meta-llama/llama-3.3-70b-instruct",
        "recommendations": "1. Parable of the Sower, Octavia E. Butler: ..."
    }
}
```

Without a key for the provider: `{"error": {"code": "conflict", "message": "The AI provider is not set up: The OpenRouter
API key is not set: add OPENROUTER_API_KEY=<your key> (or AGENT_API_KEY) to .env - create one on https://openrouter.ai/settings/keys"}}`.

The same capability is now `POST /capabilities/recommend_books` for REST and the JS client (`recommendBooks({ liked })`),
and the tool `recommend_books` for agents on `/mcp`. A page shows it with a form, as `write_blurb` does on the
[OpenAI page](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.4-OpenAI:-ChatGPT,-GPTs,-DALL.E):

```php
Route::form('/recommend', 'recommend_books', ['success' => '/recommend', 'back' => '/recommend', 'flash' => '{recommendations}']);
```

### Step 3: Describe an image (vision)

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/DescribeCover --scope ai:use --read-only
```

Replace **`application/services/Bookshelf/DescribeCover.php`** with:

```php
<?php
/**
 * DescribeCover: describes an uploaded cover image with the vision model of the provider
 */

use Caligrafy\Agent;
use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'describe_cover',
    description: 'Describes a book cover image in two sentences. Returns {description}.',
    scope: 'ai:use',
    readOnly: true,
    mcp: false
)]
class DescribeCover extends Service
{
    public $rules = array(
        'cover' => 'required|file|extension,png;jpg;jpeg;webp|max_size,4mb',
    );

    public $descriptions = array(
        'cover' => 'The cover image (PNG, JPEG or WebP, 4 MB at most)',
    );

    public function handle(array $input, Context $context)
    {
        // the page or REST saved the upload in public/uploads and sent its URL: read that file, never a URL
        $file = UPLOAD_PATH . basename((string) parse_url($input['cover'], PHP_URL_PATH));
        if (!is_file($file)) {
            throw ServiceError::invalid(array('cover' => 'Send the cover as an uploaded file'));
        }

        try {
            $agent = new Agent();
            $result = $agent->visualize($file, 'Describe this book cover in two sentences.');
        } catch (Exception $e) {
            throw ServiceError::conflict('The AI provider is not set up: ' . $e->getMessage());
        } finally {
            deleteFile($input['cover']);   // the cover was only needed for this answer
        }
        if (empty($result['api_success'])) {
            throw ServiceError::conflict((string) $result['response']);
        }

        return array('description' => $result['response']);
    }
}
```

+ The `file` rule makes web forms and REST save the upload in `public/uploads` under a random name and give `handle()`
  its URL. The capability reads that saved file by name, so a URL sent by a caller never makes your server fetch
  anything; `mcp: false` keeps it away from agents, which cannot send files.
+ `visualize($file, $prompt)` sends the image with the provider's vision model. The file is deleted afterwards.

Send a cover with REST (a token with `ai:use`, see
[Caligrafer: token](https://github.com/caligrafy/caligrafy-quill/wiki/Caligrafer#token)):

```bash
curl -H "Accept: application/json" -H "Authorization: Bearer cq_..." -F cover=@cover.png \
  http://localhost:8080/capabilities/describe_cover
```

Expected: `200` and `{"data":{"description":"..."}}`. Sent as JSON text instead of a file, or with no cover, it is refused:
`422`, *The Cover field needs a file* (2.19.1: `required` on a file input now holds on every channel). A form posts it the same way (`enctype='multipart/form-data'`, see
[file inputs](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#files)).

**Check**
- `docker compose exec dev-box php caligrafer.php doctor --only agent` is all OK.
- `docker compose exec dev-box php caligrafer.php call recommend_books liked=Kindred` answers `data`; with the key removed it answers a `conflict`
  that names the missing setting.
- `public/uploads` holds no cover after a `describe_cover` call.

### Running Llama locally with Ollama

1. Install Ollama from [ollama.com/download](https://ollama.com/download) (macOS, Windows) or with
   `curl -fsSL https://ollama.com/install.sh | sh` (macOS, Linux).
2. Pull the models: `ollama pull llama3.2` (3B, about 2 GB) and, for images, `ollama pull llama3.2-vision` (11B, about
   8 GB). Bigger ones (`llama3.3` 70B, `llama4`) need a strong machine: see the [Ollama library](https://ollama.com/library).
3. Check that it runs: `ollama list` shows the models and `curl http://localhost:11434/v1/models` answers. The Ollama
   app starts the server; otherwise run `ollama serve`.
4. Set `AGENT_PROVIDER=ollama` in `.env`. When PHP runs in Docker, `localhost` is the container: set
   `AGENT_API_BASE=http://host.docker.internal:11434/v1`. Docker Desktop resolves `host.docker.internal`; on Linux add
   `extra_hosts: ["host.docker.internal:host-gateway"]` to the `dev-box` service of `docker-compose.yaml` and start
   Ollama with `OLLAMA_HOST=0.0.0.0`.
5. `docker compose exec dev-box php caligrafer.php doctor --only agent` (without Docker: `php caligrafer.php doctor --only agent`)
   confirms that the server answers and the models are pulled. A model without a tag is `:latest`.

## Reference

### `new Agent($apiKey = "", $provider = "", $baseUrl = "")`

Empty arguments come from `.env`. Each setting is found in this order:

| Setting | Order |
|---|---|
| provider | the argument, `AGENT_PROVIDER`, else `groq` |
| key | the argument, the provider's key (`GROQ_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`, `OPENROUTER_API_KEY`), then `AGENT_API_KEY`; never another provider's key. Ollama needs none |
| endpoint | the argument, `AGENT_API_BASE`, `GROQ_API_BASE` (Groq only), then the provider's default |
| text model | `AGENT_MODEL`, `GROQ_MODEL` (Groq only), then the default of the table above |
| vision model | `AGENT_VISION_MODEL`, `GROQ_VISION_MODEL` (Groq only), then the default |

Examples: `new Agent(provider: 'ollama')`, `new Agent('key', 'custom', 'https://llm.example.com/v1')`. Groq goes through
the groq-php library; the others through a built-in HTTP client (120 s timeout; OpenRouter also gets `HTTP-Referer:
APP_URL` and `X-Title: APP_NAME`).

### Methods

| Method | Returns |
|---|---|
| `delegate($model = "", $messages = array(), $response_format = array(), $stream = false, $tool_choice = "", $tools = array())` | `['api_success' => bool, 'response' => text or error]`; `$model` empty = `model()`; `$response_format` e.g. `['type' => 'json_object']`; `$stream` true reads the streamed answer and returns it as one text (other providers than Groq); `$tools`, `$tool_choice` in OpenAI's format |
| `visualize($file = "", $prompt = "Describe this image", $model = "")` | same shape; `$model` empty = `visionModel()`. Groq: a file of 4 MB at most, or a URL. Others: a local image file (sent as base64, 20 MB at most) or a public http(s) URL passed to the provider |
| `transcribe($file = "", $prompt = "", $model = GROQ_TRANSCRIPTION_MODEL, $language = "en", $response_format = "json")` | Groq's answer as a JSON string; Groq only (others throw *needs Groq*) |
| `translate($file = "", $prompt = "", $model = GROQ_TRANSCRIPTION_MODEL, $response_format = "json")` | audio to English text, JSON string; Groq only |
| `models()` | `['api_success' => true, 'response' => sorted model ids]` (Ollama: the pulled models), or `false` and the error |
| `configure($parameters = array())` | adds parameters (`temperature`, `max_tokens`...) to every `delegate()` and `visualize()`; returns the agent |
| `provider()`, `model()`, `visionModel()` | the provider in use and its default models |
| `Agent::settings()`, `Agent::modelIds($json)`, `Agent::PROVIDERS` | the resolved settings (doctor uses them), model ids of a `/models` answer, the providers table |

For audio next to another provider, keep `GROQ_API_KEY` and use `new Agent(provider: 'groq')`.

### Constants (Groq)

`GROQ_DEFAULT_MODEL` (`openai/gpt-oss-120b`, or `GROQ_MODEL`), `GROQ_SMALL_MODEL` (`openai/gpt-oss-20b`),
`GROQ_DEFAULT_VISION_MODEL` (`qwen/qwen3.8-27b`, or `GROQ_VISION_MODEL`), `GROQ_TRANSCRIPTION_MODEL` (`whisper-large-v3`).
In code that may run on another provider, use `$agent->model()` and `$agent->visionModel()` instead.

### `.env` for every provider

```text
AGENT_PROVIDER=together
TOGETHER_API_KEY=...          # https://api.together.ai/settings/api-keys

AGENT_PROVIDER=fireworks
FIREWORKS_API_KEY=...         # https://fireworks.ai/account/api-keys

AGENT_PROVIDER=custom         # vLLM, LM Studio, a gateway...
AGENT_API_BASE=https://llm.example.com/v1
AGENT_API_KEY=...             # only when the endpoint needs one
AGENT_MODEL=<model id>
```

A Llama deployment on Together or Fireworks: put the model id of your deployment in `AGENT_MODEL`.

### Migrating from the Groq Llama models

Groq retired these models; requests with them fail with *model decommissioned* or *does not exist*.

| Groq model (retired) | The same Llama elsewhere | Replacement on Groq |
|---|---|---|
| `llama-3.3-70b-versatile` | OpenRouter `meta-llama/llama-3.3-70b-instruct`, Ollama `llama3.3` | `openai/gpt-oss-120b` |
| `llama-3.1-8b-instant` | OpenRouter `meta-llama/llama-3.1-8b-instruct`, Ollama `llama3.1` | `openai/gpt-oss-20b` |
| `meta-llama/llama-4-scout-17b-16e-instruct` | OpenRouter `meta-llama/llama-4-scout` | `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` (vision) |
| `meta-llama/llama-4-maverick-17b-128e-instruct` | OpenRouter `meta-llama/llama-4-maverick`, Ollama `llama4` | `openai/gpt-oss-120b` |
| `llama-3.2-11b-vision-preview`, `llama-3.2-90b-vision-preview` | Ollama `llama3.2-vision` | `qwen/qwen3.8-27b` |
| `llama3-70b-8192`, `llama3-8b-8192` | OpenRouter `meta-llama/llama-3.3-70b-instruct` / `meta-llama/llama-3.1-8b-instruct` | `openai/gpt-oss-120b` / `openai/gpt-oss-20b` |

To keep Llama: set `AGENT_PROVIDER=openrouter` (or `ollama`), replace the Groq ids in your code or `GROQ_MODEL` with the
middle column (or remove them to use the defaults), then run `docker compose exec dev-box php caligrafer.php doctor --only agent`.

## Other ways

**Streaming the answer.** A capability serves every channel and is the way to write the agent. To stream the answer word by
word to the browser, serve a web-only capability with [`Route::action`](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#action): it sets its header, prints and
flushes each word, then returns `Web::text('')`. Controllers in older code return `api($agent->delegate(...))`.

## Common mistakes

+ **Expecting Llama on Groq.** It is gone: use OpenRouter or Ollama.
+ **Switching `AGENT_PROVIDER` without that provider's key.** The key of another provider is never used: `new Agent()`
  throws. Run `doctor --only agent`.
+ **`localhost` from Docker.** PHP in the container does not reach Ollama on your computer at `localhost`: use
  `AGENT_API_BASE=http://host.docker.internal:11434/v1`.
+ **Passing a URL from the client to `visualize()`.** Your server or the provider would fetch whatever it points to.
  Save the upload (the `file` rule) and pass the saved file.
+ **`transcribe()` on another provider.** Audio is Groq only.
+ **`GROQ_DEFAULT_MODEL` in code that runs on OpenRouter.** Use `$agent->model()`.
