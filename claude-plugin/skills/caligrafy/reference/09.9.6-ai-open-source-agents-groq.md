# 9.9.6 Open Source Agents (llama, Mistral, etc.)

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.6-Open-Source-Agents-(llama,-Mistral-etc.)
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - `AGENT_PROVIDER` (empty = groq) picks the provider; keys `GROQ_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`, `OPENROUTER_API_KEY`, then `AGENT_API_KEY` (`Agent::settings()`). `delegate()` is positional/named: `delegate(model:, messages:, response_format:, stream:, tool_choice:, tools:)`; an empty model uses `$agent->model()` (Groq `openai/gpt-oss-120b`, vision `qwen/qwen3.8-27b`; per-provider defaults in api-reference.md). Audio is Groq only (G17, G33).

Artificial Intelligence has made significant strides in the last couple of years especially - unexpectedly - in the creative world. Many open source providers like Meta have been a major player in bringing generative artificial intelligence to the mass.

Caligrafy integrates with open models (Llama, gpt-oss, Qwen, Mistral and others) through the `Agent` class. `Agent` talks to any **OpenAI-compatible provider**: Groq (the default), Together AI, Fireworks AI, OpenRouter, a local Ollama server or your own endpoint. Your code stays the same whichever provider you choose: only `.env` changes.

## Choosing a provider

| Provider | `AGENT_PROVIDER` | Key | Default text model | Default vision model | Audio (`transcribe`, `translate`) |
| - | - | - | - | - | - |
| [Groq](https://console.groq.com) | `groq` (default) | `GROQ_API_KEY` (`gsk_...`) | `openai/gpt-oss-120b` | `qwen/qwen3.8-27b` (preview) | Yes, `whisper-large-v3` |
| [Together AI](https://www.together.ai) | `together` | `TOGETHER_API_KEY` | `openai/gpt-oss-120b` | `Qwen/Qwen3.5-9B` | No |
| [Fireworks AI](https://fireworks.ai) | `fireworks` | `FIREWORKS_API_KEY` | `accounts/fireworks/models/gpt-oss-120b` | `accounts/fireworks/models/glm-5p3-flash` | No |
| [OpenRouter](https://openrouter.ai) | `openrouter` | `OPENROUTER_API_KEY` | `meta-llama/llama-3.3-70b-instruct` | `meta-llama/llama-4-maverick` | No |
| [Ollama](https://ollama.com) (local) | `ollama` | none | `llama3.2` | `llama3.2-vision` | No |
| Any OpenAI-compatible API | `custom` | `AGENT_API_KEY` | `AGENT_MODEL` (required) | `AGENT_VISION_MODEL` | No |

> **Where is Llama?** (October 2026) Groq retired its Llama chat models in August 2026 (`llama-3.3-70b-versatile`, `llama-3.1-8b-instant`, Llama 4 Scout and Maverick). Together AI and Fireworks AI no longer serve Llama serverless: they only run it on dedicated (Together) or on-demand (Fireworks) deployments, so their defaults are `gpt-oss-120b`. To use **Llama pay-per-token, choose OpenRouter**. To run it **for free on your own machine, choose Ollama**. The models of every provider keep changing: check them with `php caligrafer.php doctor` (it lists the models of your key) or `$agent->models()`.

Costs and keys, in short:
+ **Groq**: free developer tier with rate limits, then pay per token. Llama is no longer offered.
+ **Together AI** and **Fireworks AI**: pay per token. `gpt-oss-120b` costs about $0.15 per million input tokens and $0.60 per million output tokens on both. Llama needs a dedicated or on-demand deployment, which is billed per hour of GPU.
+ **OpenRouter**: one key for hundreds of models, billed from prepaid credits. `meta-llama/llama-3.3-70b-instruct` costs about $0.10 / $0.32 per million tokens and `meta-llama/llama-4-maverick` about $0.19 / $0.65. Models whose id ends with `:free` cost nothing but have daily request limits (no Llama model is free in October 2026).
+ **Ollama**: free. The models run on your computer, and how fast they answer depends on its CPU, GPU and memory.

Prices change: check the pricing page of the provider.

## Initializing open source models

### Step 1: Configure the provider in `.env`

**Groq (default, no change for existing projects)**

* [Open a Groq account for free](https://console.groq.com/playground) and [create an API key](https://console.groq.com/keys)
* Paste it in `.env`: `GROQ_API_KEY=<paste your key here>`
* Optional: `GROQ_MODEL` and `GROQ_VISION_MODEL` change the default models, `GROQ_API_BASE` the endpoint (all the `GROQ_*` settings and constants work as before)

**OpenRouter (Llama in the cloud)**

```
AGENT_PROVIDER=openrouter
OPENROUTER_API_KEY=...                     # https://openrouter.ai/settings/keys
AGENT_MODEL=meta-llama/llama-3.3-70b-instruct   # optional: this is the default
AGENT_VISION_MODEL=meta-llama/llama-4-maverick  # optional: this is the default
```

**Together AI**

```
AGENT_PROVIDER=together
TOGETHER_API_KEY=...                       # https://api.together.ai/settings/api-keys
# AGENT_MODEL=openai/gpt-oss-120b          # default; a Llama dedicated endpoint: use the model id shown for your endpoint
```

**Fireworks AI**

```
AGENT_PROVIDER=fireworks
FIREWORKS_API_KEY=...                      # https://fireworks.ai/account/api-keys
# AGENT_MODEL=accounts/fireworks/models/gpt-oss-120b   # default (serverless)
# Llama 3.3 70B needs an on-demand deployment of accounts/fireworks/models/llama-v3p3-70b-instruct: use the model id of the deployment
```

**Ollama (Llama on your machine)**

```
AGENT_PROVIDER=ollama
# AGENT_API_BASE=http://localhost:11434/v1             # default when PHP runs on your machine
# AGENT_API_BASE=http://host.docker.internal:11434/v1  # when PHP runs in Docker (.bin/caligrafer server start)
# AGENT_MODEL=llama3.2                                 # default
# AGENT_VISION_MODEL=llama3.2-vision                   # default
```

**Your own endpoint** (vLLM, LM Studio, a gateway...)

```
AGENT_PROVIDER=custom
AGENT_API_BASE=https://llm.example.com/v1  # the base of its /chat/completions and /models
AGENT_API_KEY=...                         # optional: only if the endpoint needs a key
AGENT_MODEL=<model id>
```

Settings, in order of precedence:
+ The **key** is the argument of `new Agent('key')`, then the key of the provider (`GROQ_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`, `OPENROUTER_API_KEY`), then `AGENT_API_KEY`. The key of another provider is never used.
+ The **endpoint** is the third argument of `new Agent()`, then `AGENT_API_BASE`, then (Groq only) `GROQ_API_BASE`, then the default of the provider.
+ The **default models** are `AGENT_MODEL` and `AGENT_VISION_MODEL`, then (Groq only) `GROQ_MODEL` and `GROQ_VISION_MODEL`, then the defaults of the table above.

Then run `php caligrafer.php doctor --only agent`. It checks the key and its format, that the provider answers and lists models, and that `AGENT_MODEL` and `AGENT_VISION_MODEL` are available. For Ollama, it checks that the server answers and that the models are pulled. With Groq it runs the Groq check, which warns about retired models ([Caligrafer doctor](1.-Getting-Started#doctor)).

### Running Llama locally with Ollama

1. Install Ollama: download the app from [ollama.com/download](https://ollama.com/download) (macOS, Windows) or run `curl -fsSL https://ollama.com/install.sh | sh` (macOS, Linux)
2. Pull the models: `ollama pull llama3.2` (3B, about 2 GB) and, for images, `ollama pull llama3.2-vision` (11B, about 8 GB). Larger models: `llama3.3` (70B, about 43 GB) and `llama4` (vision, about 67 GB) need a powerful machine. See the [Ollama library](https://ollama.com/library)
3. Make sure it runs: the Ollama app starts the server, otherwise run `ollama serve`. `ollama list` shows the pulled models, and `curl http://localhost:11434/v1/models` should answer
4. Set `AGENT_PROVIDER=ollama` in `.env`. If PHP runs in Docker, `localhost` is the container itself: set `AGENT_API_BASE=http://host.docker.internal:11434/v1`. Docker Desktop (macOS, Windows) resolves `host.docker.internal`. On Linux, add `extra_hosts: ["host.docker.internal:host-gateway"]` to the `dev-box` service in `docker-compose.yaml` and start Ollama with `OLLAMA_HOST=0.0.0.0` so that it listens on more than the loopback interface
5. `php caligrafer.php doctor --only agent` (in Docker: `docker-compose exec dev-box php caligrafer.php doctor --only agent`) confirms that the server is reachable and the model is pulled. A model name without a tag means `:latest` (`llama3.2` is `llama3.2:latest`)

### Step 2: Create a controller to interface with the models

Create a controller in Caligrafy that uses the Agent class to interface with the models

```php
<?php

use Caligrafy\Controller;
use Caligrafy\Agent; // <---- Make sure to include the Agent class

class AgentController extends Controller {

    public function index() {

         $agent = new Agent(); // provider, key and models come from .env
         // $agent = new Agent('your api key');                          // another key for the provider of .env
         // $agent = new Agent(provider: 'ollama');                       // another provider
         // $agent = new Agent('key', 'custom', 'https://llm.example.com/v1'); // key, provider, endpoint

         // methods that can be called on the agent object
         $delegate = $agent->delegate(...);
         $visualize = $agent->visualize(...);
         $transcription = $agent->transcribe(...); // Groq only
         $translation = $agent->translate(...);    // Groq only
         $models = $agent->models();

         // Render output
         dump($delegate); // use dump for flushing result on the browser
         return api($delegate); // use api function to show api result
         return view(...); // use view function to return response to view
    }
}

```

`new Agent()` throws an `Exception` when `AGENT_PROVIDER` is unknown, when the key of a cloud provider is missing, or when `custom` has no `AGENT_API_BASE`. `$agent->provider()`, `$agent->model()` and `$agent->visionModel()` return the provider in use and its default models.

## Using the AI methods

### Delegate (Prompting engine)

This method is a textual prompting engine that could help query, converse and delegate tasks to the AI

```php

$agent->delegate(

       model: "model id of the provider", // optional: $agent->model() when empty
       messages: array(
            [
               'role' => 'user', // or system
               'content' => 'your message goes here'
            ]
       ),
       // response_format: ['type' => 'json_object'],
       // stream: false,  // true: the streamed answer is read and returned as one text (not with Groq: keep false)
       // tool_choice: 'auto',
       // tools: array of tool definitions (OpenAI format)

);

// Example
$result = $agent->delegate(messages: [['role' => 'user', 'content' => 'Hi']]); // default model of the provider
// $result = array('api_success' => true, 'response' => 'Hello! How can I help you today?')

```

`delegate()` and `visualize()` return `array('api_success' => true|false, 'response' => <text or error>)`: errors of the provider (rejected key, unknown model, server not reachable) come back as `api_success => false` with the message. Default settings such as `temperature` or `max_tokens` can be set for all calls with `$agent->configure(array('temperature' => 0.2))`.

**Llama chat examples**

```php
// OpenRouter (.env: AGENT_PROVIDER=openrouter, OPENROUTER_API_KEY=...)
$agent = new Agent();
$answer = $agent->delegate(messages: [
    ['role' => 'system', 'content' => 'You are a concise assistant.'],
    ['role' => 'user', 'content' => 'Explain MVC in two sentences.'],
]); // meta-llama/llama-3.3-70b-instruct

$messages = [['role' => 'user', 'content' => 'Hi']];
$answer = $agent->delegate('meta-llama/llama-4-maverick', $messages); // another Llama model

// Ollama (.env: AGENT_PROVIDER=ollama, after ollama pull llama3.2)
$answer = (new Agent())->delegate(messages: $messages); // llama3.2 on your machine
$answer = (new Agent(provider: 'ollama'))->delegate('llama3.3', $messages); // whatever the .env provider is

// Together AI or Fireworks AI with a Llama deployment: pass the model id of your endpoint
$answer = (new Agent())->delegate('<your Llama endpoint model id>', $messages);
```

> **Default models** (October 2026): Groq `GROQ_DEFAULT_MODEL` = `openai/gpt-oss-120b` (text), `GROQ_SMALL_MODEL` = `openai/gpt-oss-20b`, `GROQ_DEFAULT_VISION_MODEL` = `qwen/qwen3.8-27b` (vision, preview) and `GROQ_TRANSCRIPTION_MODEL` = `whisper-large-v3` (audio). The other providers: see the table above. Set `AGENT_MODEL` and `AGENT_VISION_MODEL` (or `GROQ_MODEL` and `GROQ_VISION_MODEL` with Groq) in `.env` to change them without touching the code.

### Migrating from the Groq Llama models

Groq retired these models; requests that use them fail with a "model decommissioned" or "does not exist" error:

| Groq model (retired) | Same Llama elsewhere | Replacement on Groq |
| - | - | - |
| `llama-3.3-70b-versatile` | OpenRouter `meta-llama/llama-3.3-70b-instruct`, Ollama `llama3.3` | `openai/gpt-oss-120b` |
| `llama-3.1-8b-instant` | OpenRouter `meta-llama/llama-3.1-8b-instruct`, Ollama `llama3.1` | `openai/gpt-oss-20b` |
| `meta-llama/llama-4-scout-17b-16e-instruct` | OpenRouter `meta-llama/llama-4-scout` | `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` (vision) |
| `meta-llama/llama-4-maverick-17b-128e-instruct` | OpenRouter `meta-llama/llama-4-maverick`, Ollama `llama4` | `openai/gpt-oss-120b` |
| `llama-3.2-11b-vision-preview`, `llama-3.2-90b-vision-preview` | Ollama `llama3.2-vision` | `qwen/qwen3.8-27b` |
| `llama3-70b-8192`, `llama3-8b-8192` | OpenRouter `meta-llama/llama-3.3-70b-instruct` / `meta-llama/llama-3.1-8b-instruct` | `openai/gpt-oss-120b` / `openai/gpt-oss-20b` |

To keep Llama: set `AGENT_PROVIDER=openrouter` (or `ollama`), replace the Groq ids in your code or in `GROQ_MODEL` by the ids of the middle column (or remove them to use the defaults), and run `php caligrafer.php doctor --only agent`. Keep `GROQ_API_KEY` if you transcribe audio: `new Agent(provider: 'groq')` still works next to another default provider. To stay on Groq, use the right column.

### Visualize

Interprets the content of an image file

```php
$agent->visualize(

       file: "file path goes here", // or a public https URL, which the provider downloads
       prompt: "optional prompt if something specific is needed from the image",
       model: "vision model of the provider" // default $agent->visionModel()

);

```

With Groq, groq-php reads the file (4 MB max). The other providers receive the file as a base64 data URL (20 MB max, image files only). Never pass a URL or a path that comes from the client: save the upload to a temporary file and pass that path. A provider without a vision model (`custom` without `AGENT_VISION_MODEL`) returns `api_success => false` with the reason.

### Audio Transcribe

Converts audio files to text (Groq only)

```php
$agent->transcribe(

       file: "file path goes here",
       prompt: "optional prompt if something specific is needed from the audio",
       model: "model name from groq goes here", // default GROQ_TRANSCRIPTION_MODEL: whisper-large-v3
       language: "en", // default 'en': set the language of the audio
       response_format: "json"

);

```

### Audio Translate

Translate audio files to english (Groq only)

```php
$agent->translate(

       file: "file path goes here",
       prompt: "optional prompt if something specific is needed from the audio",
       model: "model name from groq goes here", // default GROQ_TRANSCRIPTION_MODEL: whisper-large-v3
       response_format: "json"

);

```

`transcribe()` and `translate()` return the Groq response as a JSON string. With another provider they throw an `Exception` ("needs Groq"): keep a `GROQ_API_KEY` and use `new Agent(provider: 'groq')` for audio.

### Models

Lists the models of the provider (for Ollama: the models pulled on the server). Use it to fill a model picker instead of hard-coding ids.

```php
$models = $agent->models();
// array('api_success' => true, 'response' => array('meta-llama/llama-3.3-70b-instruct', 'meta-llama/llama-4-maverick', ...))
// array('api_success' => false, 'response' => 'OpenRouter error 401: ...') on errors
```
