# 9.9.4 OpenAI: ChatGPT, GPTs, DALL.E

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.4-OpenAI:-ChatGPT,-GPTs,-DALL.E
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - Default TEXT model is `OPENAI_DEFAULT_MODEL` (`gpt-6-luna`, or `OPEN_AI_MODEL`); images use `gpt-image-2` and come back as `b64_json` only (G31). Resolve user input with `OpenAI::command()`/`OpenAI::type()`, never `constant()`.

Your application can ask OpenAI's models to write text (GPT) and to draw images (GPT image models; DALL.E was shut down
on May 12, 2026). The class `Caligrafy\OpenAI` sends the request; your key stays on the server. You put the call in a
**capability**, so the same feature reaches a web page, a Vue app, the REST API and AI agents (MCP) without a second
line of AI code. In the Bookshelf example, the capability `write_blurb` writes the back-cover blurb of a book, and
`draw_cover` draws a cover.

This page is about your application calling a model. The other direction, AI agents such as Claude using your
application, is [MCP](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#mcp).

API calls cost money: create a key on [platform.openai.com/api-keys](https://platform.openai.com/api-keys) and add
credits to its project first.

## With Claude

Ask for the feature and name the capability:

```text
/caligrafy-quill:new-capability write_blurb ai:use read-only
Write a two-sentence back-cover blurb for a book from its title and author, with OpenAI. Show it on a /blurb page with a form.
```

Claude scaffolds `application/services/Bookshelf/WriteBlurb.php` with `docker compose exec dev-box php caligrafer.php service`, fills its `$rules` and
`handle()`, adds the routes to `application/config/routing/web.php` (`Route::page`, `Route::form`, and
`Route::capabilities`, `Route::mcp` when the project does not have them), writes the Pug view and a test in `tests/`.
For a chat app in Vue, `/caligrafy-quill:new-app app chat` follows the plugin's AI chat recipe.

**Check**
- `OPEN_AI_KEY` is in `.env`, never in a file of `public/` or in git; `docker compose exec dev-box php caligrafer.php doctor --only openai` says OK.
- The capability is not `public: true` (anyone could spend your credits) and has a scope (`ai:use`).
- `handle()` checks `$result['response']['error']` (OpenAI's own errors) and `api_success` (no answer at all).
- `docker compose exec dev-box php caligrafer.php test` passes without a real key: the test replaces the OpenAI client.

## By hand

The steps below add `write_blurb` (text) and `draw_cover` (image) to a project of the
[Quickstart](https://github.com/caligrafy/caligrafy-quill/wiki/Quickstart) that has sign-in
([`Route::auth`](https://github.com/caligrafy/caligrafy-quill/wiki/9.1-Authentication#routeauth)), `Route::capabilities('/capabilities')`
and `Route::mcp('/mcp')` in `web.php`. Run the commands in the project folder. Without Docker (Composer with MAMP, XAMPP or LAMP), run the same commands without `docker compose exec dev-box` and open your own address.

### Step 1: Add the key

Open `.env` and set the key (keep the other lines as they are):

```text
OPEN_AI_KEY=sk-proj-...
OPEN_AI_MODEL=
OPEN_AI_IMAGE_MODEL=
```

Empty models mean the defaults: `gpt-6-luna` for text, `gpt-image-2` for images. Run:

```bash
docker compose exec dev-box php caligrafer.php doctor --only openai
```

It checks, without spending anything, that the key is accepted and that the default models are allowed for its
project. Without a key it prints `SKIP  OpenAI: OPEN_AI_KEY is not set`.

### Step 2: Create the capability

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/WriteBlurb --scope ai:use --read-only
```

Expected: `Created application/services/Bookshelf/WriteBlurb.php: capability 'write_blurb' (scope ai:use)`. Replace the
content of **`application/services/Bookshelf/WriteBlurb.php`** with:

```php
<?php
/**
 * WriteBlurb: writes the back-cover blurb of a book with OpenAI
 */

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\OpenAI;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'write_blurb',
    description: 'Writes a two-sentence back-cover blurb for a book from its title and author. Returns {blurb}.',
    scope: 'ai:use',
    readOnly: true
)]
class WriteBlurb extends Service
{
    public $rules = array(
        'title' => 'required|max_len,255',
        'author' => 'max_len,255',
    );

    public $filters = array(
        'title' => 'trim',
        'author' => 'trim',
    );

    public $descriptions = array(
        'title' => 'The title of the book',
        'author' => 'The author of the book',
    );

    // the OpenAI client comes through the constructor: a test can replace it ($this->fake(OpenAI::class, ...))
    public function __construct(private OpenAI $openai)
    {
    }

    public function handle(array $input, Context $context)
    {
        $book = $input['title'] . (!empty($input['author']) ? ' by ' . $input['author'] : '');
        $result = $this->openai->delegate(
            $book,
            'Write a back-cover blurb of two sentences. No spoilers.',
            CONVERSE
        );

        $response = $result['response'] ?? null;
        if (empty($result['api_success']) || !is_array($response)) {
            throw ServiceError::conflict('OpenAI did not answer: try again in a moment');
        }
        if (isset($response['error'])) {
            throw ServiceError::conflict('OpenAI refused: ' . ($response['error']['message'] ?? 'unknown error'));
        }

        return array('blurb' => trim($response[0]['message']['content'] ?? ''));
    }
}
```

What it does:
+ `readOnly: true`: it changes none of your data (agents may call it without asking).
+ The constructor gets a new `OpenAI` object (type `TEXT`) from the [container](https://github.com/caligrafy/caligrafy-quill/wiki/Dependency-Injection).
+ `delegate($input, $outcome, $command)` sends `CONVERSE` as the system prompt and the title with the instructions as
  the user message, with the default model.
+ The answer is in `$response[0]['message']['content']`. When OpenAI refuses (wrong key, no credits, unknown model),
  `$response['error']['message']` says why; when nothing comes back (timeout, network), `api_success` is `false`.
  Both become a `conflict` refusal with that message: a page shows it in `flash('error')`, REST answers 409.

Run `docker compose exec dev-box php caligrafer.php capabilities`: the list now has
`write_blurb  ai:use  read  Writes a two-sentence back-cover blurb...`.

### Step 3: Call it from the command line

```bash
docker compose exec dev-box php caligrafer.php call write_blurb title=Kindred author="Octavia E. Butler"
```

Expected (the text varies):

```json
{
    "data": {
        "blurb": "..."
    }
}
```

Without a title it answers `{"error": {"code": "invalid", ..., "fields": {"title": "The Title field is required"}}}`.

### Step 4: A page with a form

Add the routes to **`application/config/routing/web.php`**, before `Route::run();`:

```php
Route::page('/blurb', 'Bookshelf/blurb', ['signedIn' => true]);
Route::form('/blurb', 'write_blurb', ['success' => '/blurb', 'back' => '/blurb', 'flash' => '{blurb}']);
```

`Route::form` calls `write_blurb` with the form's fields, as the signed-in person, then goes back to `/blurb` with the
blurb as the `success` message (`{blurb}` is filled from the result). Create **`application/views/Bookshelf/blurb.pug`**:

```pug
extends ../default/master/site

block content
  section.cq-hero.cq-hero--page
    h1.cq-display Write a blurb

  section.cq-band.cq-band--tight
    .cq-inner.cq-inner--narrow
      if flash('error')
        .cq-alert.cq-alert--error(role='alert')= flash('error')
      if flash('success')
        .cq-card
          p.cq-lead= flash('success')
      form(method='POST', action="{$home}blurb")
        =csrf()
        .cq-field
          label(for='title') Title
          input#title.form-control(type='text', name='title', value=old('title'))
          if errors('title')
            p.cq-field-error= errors('title')
        .cq-field
          label(for='author') Author
          input#author.form-control(type='text', name='author', value=old('author'))
          if errors('author')
            p.cq-field-error= errors('author')
        button.btn.btn-primary(type='submit') Write
```

Open `http://localhost:8080/blurb`. Signed out, you go to `/login`. Signed in, type a title and click **Write**: the
page comes back with the blurb above the form. With an empty title it comes back with *The Title field is required*
under the field and the author you typed still there.

### Step 5: REST and AI agents

Nothing to add: `Route::capabilities` and `Route::mcp` serve every capability. Create a token for a program or an agent:

```bash
docker compose exec dev-box php caligrafer.php token create "blurb agent" --scopes ai:use --user 1
```

It prints `cq_...` once: store it as a secret. Then:

```bash
curl -X POST -H "Accept: application/json" -H "Content-Type: application/json" \
  -H "Authorization: Bearer cq_..." \
  -d '{"title": "Kindred", "author": "Octavia E. Butler"}' \
  http://localhost:8080/capabilities/write_blurb
```

Expected: `200` and `{"data":{"blurb":"..."}}`. Without the token: `401`. An agent connected to `/mcp` with this token
sees the tool `write_blurb` and calls it with the same inputs.

### Step 6: Test it without a key

```bash
docker compose exec dev-box php caligrafer.php test make WriteBlurb
```

Replace **`tests/WriteBlurbTest.php`** with:

```php
<?php

use Caligrafy\OpenAI;
use Caligrafy\Testing\TestCase;

/**
 * php caligrafer.php test WriteBlurb
 */
final class WriteBlurbTest extends TestCase
{
    public function testItWritesABlurb(): void
    {
        // a stand-in for OpenAI: no request leaves the computer
        $this->fake(OpenAI::class, new class extends OpenAI {
            public function delegate($input = '', $outcome = '', $command = CONVERSE, $context = array(), $parameters = array())
            {
                return array('api_success' => true, 'type' => 'text',
                    'response' => array(array('message' => array('role' => 'assistant', 'content' => "A blurb for $input."))));
            }
        });

        $answer = $this->call('write_blurb', array('title' => 'Kindred', 'author' => 'Octavia E. Butler'), $this->user(1));

        $this->assertSame('A blurb for Kindred by Octavia E. Butler.', $answer['blurb']);
    }

    public function testItNeedsATitle(): void
    {
        $this->assertCapabilityFails('invalid', 'write_blurb', array(), $this->user(1));
    }

    public function testGuestsCannotUseIt(): void
    {
        $this->assertCapabilityFails('unauthenticated', 'write_blurb', array('title' => 'Kindred'), 'guest');
    }
}
```

```bash
docker compose exec dev-box php caligrafer.php test WriteBlurb
```

Expected: `OK (3 tests, 3 assertions)`.

### Step 7: Images

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/DrawCover --scope ai:use --read-only
```

Replace **`application/services/Bookshelf/DrawCover.php`** with:

```php
<?php
/**
 * DrawCover: draws a book cover with an OpenAI image model
 */

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\OpenAI;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'draw_cover',
    description: 'Draws a book cover from a title and a short description. Returns {image}: a PNG as a data URL.',
    scope: 'ai:use',
    readOnly: true
)]
class DrawCover extends Service
{
    public $rules = array(
        'title' => 'required|max_len,255',
        'idea' => 'max_len,1000',
        'quality' => 'contains_list,low;medium;high',
    );

    public $filters = array(
        'title' => 'trim',
        'idea' => 'trim',
    );

    public $descriptions = array(
        'title' => 'The title of the book',
        'idea' => 'What the cover should show',
        'quality' => 'low (fastest), medium (default) or high',
    );

    public function handle(array $input, Context $context)
    {
        $prompt = 'A book cover for "' . $input['title'] . '". ' . ($input['idea'] ?? '') . ' No text on the cover.';
        $openai = new OpenAI(IMAGE);
        $result = $openai->delegate($prompt, '', ANALYZE, array(), array(
            'size' => '1024x1536',
            'quality' => $input['quality'] ?? 'medium',
        ));

        $response = $result['response'] ?? null;
        if (empty($result['api_success']) || !is_array($response)) {
            throw ServiceError::conflict('No image: OpenAI did not answer in time, try the low quality');
        }
        if (isset($response['error'])) {
            throw ServiceError::conflict('OpenAI refused: ' . ($response['error']['message'] ?? 'unknown error'));
        }

        return array('image' => 'data:image/png;base64,' . ($response[0]['b64_json'] ?? ''));
    }
}
```

GPT image models answer with a **base64 image**, never a URL: the capability returns it as a `data:` URL that an `img`
shows as it is. For an image, `delegate()` sends the input as the `prompt` and ignores the command. (The container
always builds a `TEXT` client, so this capability creates its `IMAGE` client itself.)

An image is too large for a flash message, so the page calls the capability from the browser with the generated
JavaScript client. Write the client (run it again after every capability change):

```bash
docker compose exec dev-box php caligrafer.php client
```

Expected: `public/js/capabilities.js written: ... capabilities`. Add the page to **`web.php`**:

```php
Route::page('/cover', 'Bookshelf/cover', ['signedIn' => true]);
```

**`application/views/Bookshelf/cover.pug`**:

```pug
extends ../default/master/site

block content
  section.cq-hero.cq-hero--page
    h1.cq-display Draw a cover

  section.cq-band.cq-band--tight
    .cq-inner.cq-inner--narrow
      p#error.cq-alert.cq-alert--error(role='alert', hidden)
      form#cover(method='POST')
        .cq-field
          label(for='title') Title
          input#title.form-control(type='text', name='title', required)
        .cq-field
          label(for='idea') What the cover shows
          input#idea.form-control(type='text', name='idea')
        button.btn.btn-primary(type='submit') Draw
      img#image(alt='The cover', width='512', hidden)

  script(type='module', src="{$home}public/js/cover.js")
```

**`public/js/cover.js`**:

```js
import { drawCover, CapabilityError } from './capabilities.js'

const form = document.getElementById('cover')
const image = document.getElementById('image')
const error = document.getElementById('error')
const button = form.querySelector('button')

form.addEventListener('submit', async (event) => {
  event.preventDefault()
  error.hidden = true
  button.disabled = true
  button.textContent = 'Drawing...'
  try {
    const answer = await drawCover({ title: form.elements.title.value, idea: form.elements.idea.value, quality: 'low' })
    image.src = answer.image
    image.hidden = false
  } catch (e) {
    error.textContent = e instanceof CapabilityError ? (Object.values(e.fields || {}).join(' ') || e.message) : 'Something went wrong.'
    error.hidden = false
  } finally {
    button.disabled = false
    button.textContent = 'Draw'
  }
})
```

Open `http://localhost:8080/cover`, type a title and click **Draw**: the button says *Drawing...* and the cover
appears under the form. The client sends the session cookie and its CSRF token: no key in the page.

**Check**
- `docker compose exec dev-box php caligrafer.php capabilities` lists `write_blurb` and `draw_cover` with the scope `ai:use`.
- `/blurb` and `/cover` send signed-out visitors to `/login`.
- `docker compose exec dev-box php caligrafer.php test WriteBlurb` passes with no key in `.env`.
- `curl` without a token on `/capabilities/write_blurb` answers `401`.
- `grep -r OPEN_AI_KEY public/` finds nothing.

## Reference

### `new OpenAI($mode = TEXT)`

| Mode | Endpoint | Default parameters |
|---|---|---|
| `TEXT` | `https://api.openai.com/v1/chat/completions` | `model` = `OPENAI_DEFAULT_MODEL` only |
| `IMAGE` | `https://api.openai.com/v1/images/generations` | `model` = `OPENAI_DEFAULT_IMAGE_MODEL`, `n` 1, `size` `1024x1024`, `quality` `medium`, `output_format` `png` |

Only the model is sent by default for text: current reasoning models reject `temperature`, `top_p` and `max_tokens`.
Add the parameters your model supports (`max_completion_tokens`, `reasoning_effort`, `response_format`...).

### `delegate($input = '', $outcome = '', $command = ANALYZE, $context = array(), $parameters = array())`

+ **TEXT**: sends `messages` = the `$context` messages, then `{role: system, content: $command}`, then
  `{role: user, content: "$input\n\n$outcome\n"}`. `$outcome` may be an array (sent as `| a | b |`).
  `$context` is the earlier conversation (`['role' => 'user'|'assistant'|'system', 'content' => '...']`).
+ **IMAGE**: sends `prompt` = `$input` with `$parameters`; `$outcome`, `$command` and `$context` are not used.
+ `$parameters` are merged over the defaults.

| Command | System prompt sent |
|---|---|
| `CONVERSE` | `You are a helpful assistant:` |
| `SUMMARIZE` | `Summarize the following:` |
| `ANALYZE` (default) | `Analyze the following:` |
| `CORRECT` | `Fix the following:` |
| `CLASSIFY` | `Classify the following:` (the categories in `$outcome`) |
| `COMPLETE` | `Complete the following:`; with `[insert]` in the input, the model writes only the text that replaces it |
| `PREDICT` | `Predict based on the following:` |
| `RECOMMEND` | `Recommend about the following:` |
| `CUSTOM` | empty: put your own system message first in `$context` |

### The answer

```php
array(
    'api_success' => true,     // false only when nothing came back (timeout, network): response is then a message
    'response' => array(...),  // TEXT: the choices, the text in [0]['message']['content']
                               // IMAGE: the data, the base64 PNG in [0]['b64_json']
                               // or OpenAI's error body: ['error' => ['message' => ..., 'code' => ...]]
    'type' => 'text'           // 'text' or 'image', when something came back
)
```

`api_success` is `true` for an error body too: always check `isset($result['response']['error'])`.

### Other methods

| Method | What it does |
|---|---|
| `converse($parameters = array(), $attachments = array(), $method = 'POST', $additionalHeaders = array())` | sends the parameters as they are to the endpoint of the mode (`delegate()` uses it); same answer shape |
| `OpenAI::command($name)` | `'summarize'` -> `SUMMARIZE`... (`OpenAI::COMMANDS`), anything else -> `null` |
| `OpenAI::type($name)` | `'text'` -> `TEXT`, `'image'` -> `IMAGE`, anything else -> `null` |

When a command or a type comes from a form, resolve it with `OpenAI::command()` / `OpenAI::type()`, never with
`constant()`: `constant()` would accept the name of any constant, `.env` secrets included.

An `OpenAI` object keeps the parameters of its earlier calls (`converse()` merges each call's parameters into it): use
a new object per request, as the container does for each capability call.

### Models

| Constant | Model |
|---|---|
| `GPT6_LUNA` | `gpt-6-luna`: fastest, cheapest; the default (`OPENAI_DEFAULT_MODEL`, or `OPEN_AI_MODEL`) |
| `GPT6_SOL` | `gpt-6.1-sol` |
| `GPT6_ASTRA` | `gpt-6-astra`: the flagship (`GPT4_LATEST` and `GPT4_LATEST_VISION` point to it) |
| `GPT_IMAGE` | `gpt-image-2`: the image default (`OPENAI_DEFAULT_IMAGE_MODEL`, or `OPEN_AI_IMAGE_MODEL`) |
| `GPT_IMAGE_BEST` | `gpt-image-2.5-sunburst` |
| `GPT_IMAGE_FAST` | `gpt-image-2.5-flare` |
| `GPT3`, `GPT4`, `GPT4_32` | shut down by OpenAI |
| `GPT4O`, `GPT4OMINI` | retire on January 14, 2027 |

Pass another model with `$parameters`: `array('model' => GPT6_ASTRA)`. Image options: `size` (`1024x1024`, `1536x1024`,
`1024x1536`, `auto`), `quality` (`low`, `medium`, `high`, `auto`), `output_format` (`png`, `jpeg`, `webp`), `background`, `n`.

### `.env`

| Setting | Default |
|---|---|
| `OPEN_AI_KEY` | none: required |
| `OPEN_AI_MODEL` | `gpt-6-luna` |
| `OPEN_AI_IMAGE_MODEL` | `gpt-image-2` |

The constants of `OpenAI.php` (`TEXT`, `CONVERSE`, `GPT6_LUNA`...) exist once the class is loaded: a file that uses one
before any `OpenAI` (for example in a property default) stops with *Undefined constant*.

## Other ways

**The example controller.** `web.php` ships two commented routes to a demo page that sends a form to `delegate()`:

```php
Route::get('/ai', 'Caligrafy\\Controllers\\AIController');
Route::post('/ai', 'Caligrafy\\Controllers\\AIController@query');
```

The controller is `application/controllers/core/AI/AIController.php`, its view `application/views/AI/openai.pug`. The
routes are open to anyone who reaches the site and every request is billed to you: use them to explore, then write a
capability as above, which has a scope, a sign-in check, validation and every channel.

**A controller that calls OpenAI.** A controller action can create `new OpenAI()` and return `api(...)`; it reaches
only that one route. Use a controller only for HTTP that a declarative route does not cover (streaming, custom
headers), and then keep the AI call in the capability and call it with `$this->call('write_blurb')`.

## Common mistakes

+ **Reading only `api_success`.** It is `true` when OpenAI answers with an error (rejected key, no credits, unknown
  model). Check `$result['response']['error']`. A `429 insufficient_quota` means the project has no credits.
+ **Sending `temperature` or `max_tokens`** to a reasoning model: OpenAI refuses the request. Use `max_completion_tokens`.
+ **Looking for an image URL.** GPT image models return base64 in `[0]['b64_json']`.
+ **Slow images.** The HTTP client gives up after 30 seconds (`httpRequest()`): a `high` quality image can take longer
  and comes back with `api_success` false. Use `low` or `medium`.
+ **A public capability.** `public: true` lets anyone spend your credits. Keep a scope and sign-in.
+ **The key in the browser.** Never put `OPEN_AI_KEY` in a page, `public/` or a Vue build: the browser calls the
  capability, the server calls OpenAI.
+ **`form.title` in a script.** It is the form's own `title` attribute: read inputs with `form.elements.title`.
+ **`constant($_POST['command'])`.** Use `OpenAI::command()`.
