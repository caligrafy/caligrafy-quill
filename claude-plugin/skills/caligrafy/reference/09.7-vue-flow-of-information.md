# 9.7 Understanding the flow of information

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7-Understanding-the-flow-of-information
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A **Vue app** is one more experience of your application, next to its Pug pages, its REST API and its AI agents. Caligrafy keeps the data and the rules on the server, in capabilities; the Vue app draws the screens in the browser and calls those capabilities through a JavaScript client that Caligrafy generates. This page follows one click from a Vue app to the database and back, and compares the two kinds of Vue app Caligrafy makes.

## With Claude

```text
/caligrafy-quill:new-app app bookshelf
```
Claude scaffolds `public/bookshelf/`, generates the JS client into `public/js/capabilities.js`, wires the page route in `application/config/routing/web.php` and writes the screens with the page components. `/caligrafy-quill:new-app create bookshelf` makes a Vite single page app instead. Write the capabilities first, or in the same request (`/caligrafy-quill:new-capability`).

**Check** before you say OK:
+ The app's page opens and its browser console has no error.
+ Data comes from the generated client (`listBooks()`, `createBook()`), never from a hand-built request with an API key.
+ A refused input shows the field's message from the server.

## By hand

You follow one call of the Bookshelf app, with `curl` standing in for the browser. You need the Bookshelf tables, sample data and capabilities of [Views, steps 1 to 3](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#viewsstartup), and `Route::capabilities('/capabilities');` in `application/config/routing/web.php` (the Quickstart adds it).

**1. What the client sees.** Run:
```bash
curl -H "Accept: application/json" http://localhost:8080/capabilities
```
Expected: `{"data":[{"name":"create_book","description":"Adds a book to the Bookshelf catalog and returns it with its id and its author. ...","scope":"books:write",...,"input":{"type":"object","properties":{"title":{"type":"string","maxLength":200,...},...},"required":["title","published_year","author_id"]}},...],"csrf":"<64 characters>"}`: the capabilities this caller may use, with their inputs, and the session's CSRF token. The generated client reads this token once, then sends it with every write.

**2. A call.** Run:
```bash
curl -X POST -H "Accept: application/json" -H "Content-Type: application/json" -d '{"id": 3}' http://localhost:8080/capabilities/get_book
```
Expected: `{"data":{"id":3,"title":"Kindred","published_year":1979,"summary":"A young woman is pulled back in time to a plantation in Maryland.","isbn":null,"author_id":2,...,"author":{"id":2,"name":"Octavia E. Butler",...}}}`: the book, with its author nested. In the Vue app this is one line, `await getBook({ id: 3 })`, which returns what is inside `data`.

**3. A refusal.** Run:
```bash
curl -X POST -H "Accept: application/json" -H "Content-Type: application/json" -d '{"title": "Lilith"}' http://localhost:8080/capabilities/create_book
```
Expected: status `422` and `{"error":{"code":"invalid","message":"Some of the inputs are invalid","fields":{"published_year":"The Published Year field is required","author_id":"The Author Id field is required"}}}`. In the Vue app, `createBook()` throws a `CapabilityError` whose `fields` is that object: one message per field, ready for the form.

**Check**
+ The same answers come from the Pug page, from REST and from an AI agent: one set of rules.
+ No API key appears anywhere: a page uses the visitor's session cookie and the CSRF token; programs and agents use a personal access token.

## Reference

### The flow

```text
Vue app (browser)                     Caligrafy (server)
-----------------                     ------------------
createBook({ title, ... })
  -> POST /capabilities/create_book   Route::capabilities('/capabilities')
     session cookie + X-CSRF-Token      -> who is calling: the signed-in user, or a visitor
                                        -> may they use it: public, scope, level
                                        -> $rules check the inputs
                                        -> handle(): the query builder reads and writes the database
  <- {"data": {...}}            201     <- the answer, the same for every channel
  <- {"error": {code, fields}}  422     <- or a refusal: invalid, unauthenticated, forbidden, not_found, conflict
```

### The two kinds of Vue app

| | Vue as a library | Vite single page app |
| --- | --- | --- |
| Created by | `php caligrafer.php app <name>` | `php caligrafer.php create <name>` |
| Lives in | `public/<name>/index.php` and `public/<name>/scripts/main.js` | `public/<name>/src/` (`.vue` files), built to `public/<name>/dist/` |
| Needs Node.js | no | yes (20.19+ or 22.12+), on your computer |
| Served by | Caligrafy: a page route renders it (view `Client/app`) and gives it `env` | `npm run dev` while you work; `dist/` once built |
| Its JS client | `public/js/capabilities.js` | `public/<name>/src/capabilities.js` |
| Good for | one screen or a few, next to Pug pages | a larger app with its own routes, components and store |
| Pages | [setting up](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.0-Setting-up-Vue.js-as-a-library), [structure](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.1-Understanding-the-structure), [routes](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.2-Routes), [requests](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests), [forms](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms), [validations](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.5-Validations), [components](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.6-Components) | [setting up](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.1---Setting-up-the-Vue-application), [routing](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.2-Routing-for-Single-Page-Applications), [single file components](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.3-Single-File-Components), [state](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.4-State-Management) |

### Who does what

| Caligrafy (PHP, `application/`) | Vue (JavaScript, `public/<app>/`) |
| --- | --- |
| tables, models, capabilities and their rules | screens, components, what the person types |
| who may do what: sessions, tokens, scopes, levels | showing what the server answered, and its errors |
| the page route that serves the app | the routes between the screens of a single page app |

Both kinds of app build their screens with Caligrafy's [page components](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#pagecomponents) (`layout.css`, `look.css`), so they look like the Pug pages.

## Other ways

A Vue app can still call controller routes that answer with `api()`, with `fetch` or axios and the headers of `apiHeaders()`: see [Requests, other ways](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests). Capabilities replace them: the same rules then serve the pages, REST and AI agents.
