# 9.1 Authentication

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.1-Authentication
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - Current templates hash passwords (`User::hashPassword`/`verifyPassword`), look users up with the bound `findByUsername()`, and require `permissions >= 1` for the admin pages. Projects initialized before the security release keep the old copies in `application/` until upgraded (9.5 page, gotchas G13/G14).

Authentication lets people create an account, sign in and sign out, and keeps pages and capabilities for the people
allowed to use them. Caligrafy ships the parts: a `users` table, a `User` model, the sign-in and sign-up views, and one
line of `web.php`, `Route::auth()` (2.19.0), that declares the sign-in pages without a controller. Programs and AI
agents do not sign in: they use **personal access tokens**.

## With Claude

Ask for sign-in in plain words. `/caligrafy-quill:idea` adds it to a new app unless everything is public, and
`/caligrafy-quill:new-capability` uses it for a capability that needs someone.

```text
/caligrafy-quill:new-capability Only signed-in people see /shelf, the list of books, and only administrators see /admin/shelf
```

Claude writes:

+ in `application/config/routing/web.php`: `Auth::authentication('User', 'users');`, then
  `Route::auth(['home' => '/shelf']);` and the pages with `'signedIn' => true` or `'level' => 1`;
+ runs `application/models/Auth/create_db.sql` (the `users` table);
+ a *Sign in* / *Create account* line for visitors and a *Sign out* link or button for signed-in people on the main page.

People sign in with a username by default. To sign in with an email, say so: *"people sign in with their email, kept in the
username column"* ([below](#emailsignin)).

Password reset and face sign-in are not in `Route::auth`: Claude leaves them out unless you ask. A password reset is
then two capabilities with `Route::page` and `Route::form` ([below](#passwordreset)), a face sign-in or a sign-in through
another site is a set of web-only capabilities with `Route::action` ([below](#betweensites)). Neither is a controller.

**Check**

+ A page that needs someone sends visitors to `/login`, and with `comeBack` brings them back after signing in.
+ *Create account*, then *Sign in*, lands on the `home` page; *Sign out* ends the session.
+ Five wrong passwords in a row for one username answer *Too many tries in a row. For your security, wait 15 minutes, then try again.*
+ `web.php` has no `AuthController` route uncommented next to `Route::auth` (one or the other, never both).

## By hand

These steps use the **Bookshelf** catalog of the course: its tables and sample books
(`application/models/Bookshelf/create_db.sql`, with the models `Book` and `Author`:
[lesson 03](https://github.com/caligrafy/caligrafy-quill-course/wiki/03-Your-Data)) and its capabilities `list_books`
and `create_book` (`application/services/Bookshelf/`:
[lessons 04](https://github.com/caligrafy/caligrafy-quill-course/wiki/04-Your-First-Capabilities) and
[05](https://github.com/caligrafy/caligrafy-quill-course/wiki/05-Rules-and-Changes)), in a project made with
the [Quickstart](https://github.com/caligrafy/caligrafy-quill/wiki/Quickstart) and its Docker server
(`http://localhost:8080`). Without Docker, drop `docker compose exec dev-box` from the commands.

**1. Create the tables.** Run:

```bash
docker compose exec dev-box php caligrafer.php sql application/models/Auth/create_db.sql
docker compose exec dev-box php caligrafer.php sql application/models/Bookshelf/create_db.sql
```

Each prints ` application/models/<folder>/create_db.sql run on caligrafy`. The `users` script creates the table only when it
does not exist: running it again never deletes your users.

**2. Turn authentication on and declare the pages.** In `application/config/routing/web.php`, uncomment
`Auth::authentication('User', 'users');` and add the lines below it, so that the start of the `try` block reads:

```php
    // API ACCESS - add comments if you don't want to allow API access on routes
    Auth::activateAPI();

    // AUTHENTICATION
    Auth::authentication('User', 'users');
    Route::auth(['home' => '/shelf']);       // /login, /logout, /register, /notAuthorized

    // PAGES
    Route::page('/shelf', 'Bookshelf/shelf', ['signedIn' => true, 'comeBack' => true, 'data' => ['books' => 'list_books']]);
    Route::page('/admin/shelf', 'Bookshelf/shelf', ['level' => 1, 'data' => ['books' => 'list_books']]);

    // the REST API of the capabilities (step 7)
    Route::capabilities();
```

Leave the `AuthController` routes of the template commented: `Route::auth` replaces them.

**3. The page.** Write `application/views/Bookshelf/shelf.pug`:

```pug
extends ../default/master/site

block title
  | My shelf

block content
  main
    h1 My shelf
    p Signed in as #{$user['username']}.
    form(method='POST', action=$home . 'logout')
      =csrf()
      button(type='submit') Sign out
    ul
      each $book in $books['data']
        li= $book['title'] . ', ' . $book['author']['name']
```

`list_books` answers a page of books (`data`, `total`, `page`...), each with its `author`. Every `Route::page` view
also gets `$authorized` and `$user` (`id`, `username`, `permissions`). The *Sign out* button posts to `/logout` with
the form's CSRF token (2.19.1); a link, `a(href=$home . 'logout') Sign out`, signs out too (`GET /logout`).

**4. Try it.**

| You do | You get |
|---|---|
| Open `http://localhost:8080/shelf` | `302` to `/login?return=%2Fshelf` |
| *Create account*: `ada`, a password of 8 characters or more, twice | `302` to `/login`, *Your account is ready. Sign in to start.* |
| Sign in as `ada` from that page | `302` to `/shelf`: *Signed in as ada*, then *A Wizard of Earthsea, Ursula K. Le Guin* and the other books |
| Open `/admin/shelf` | `302` to `/notAuthorized`: *Restricted Page* (403) |
| *Sign out* | `302` to `/`; `/shelf` sends you to `/login` again |
| A wrong password, five times in a row | four times *We couldn't sign you in with those details. Check them and try again.* with the username kept in its field, then *Too many tries in a row. For your security, wait 15 minutes, then try again.* (429) |

The fifth failure locks that username from your address for 15 minutes, the right password included.
`docker compose exec dev-box php caligrafer.php cache clear` lifts the lock at once (the counts are in the cache).

**5. Make an administrator.** New accounts have `permissions` 0. In phpMyAdmin (`http://localhost:8077`), on the
database `caligrafy`, run:

```sql
UPDATE users SET permissions = 1 WHERE username = 'ada';
```

Open `/shelf`: you are sent to `/login`, because a session whose user changed in the database is no longer valid.
Sign in again: `/admin/shelf` opens.

**6. A token for a program.** A program that adds books has no account: give it a token. Run:

```bash
docker compose exec dev-box php caligrafer.php token create "Bookshelf importer" --scopes books:write --expires 30
```

It prints ` Token #1 "Bookshelf importer" created with books:write, expires <date>`, then the token, `cq_<id>_<secret>`,
shown only this once.

**7. Call a capability with it.**

```bash
curl -X POST -H "Authorization: Bearer cq_<id>_<secret>" -H "Content-Type: application/json" \
  -d '{"title": "The Dispossessed", "published_year": 1974, "author_id": 1}' \
  http://localhost:8080/capabilities/create_book
```

| You send | You get |
|---|---|
| the token | `201 {"data":{"id":6,"title":"The Dispossessed","published_year":1974,...}}` |
| a token made with `--scopes books:read` | `403 {"error":{"code":"forbidden","message":"This needs the scope books:write"}}` |
| no token (add `-H "Accept: application/json"`) | `401 {"error":{"code":"unauthenticated","message":"Sign in or send a personal access token"}}` |
| the token, with `"title": ""` | `422 {"error":{"code":"invalid",...,"fields":{"title":"The Title field is required"}}}` |
| the token after `php caligrafer.php token revoke 1` | `401` |

`docker compose exec dev-box php caligrafer.php audit` lists the calls and the refusals.

**Check**

+ `/shelf` sends visitors to `/login?return=%2Fshelf` and shows the books once signed in.
+ `/admin/shelf` answers *Restricted Page* to `permissions` 0 and opens for 1.
+ The fifth wrong password in a row is refused with 429.
+ The token adds a book, and a token without `books:write` cannot.

## Reference: `Route::auth`

`Route::auth(array $options = [])`, after `Auth::authentication('User', 'users')`, declares:

| Route | What it does |
|---|---|
| `GET /login` | the sign-in page (`Auth/login`); a signed-in person goes to `home`, or to `?return=` |
| `POST /login` | checks the identifier field and `passcode`; on success a new session id and a new CSRF token, then `home`, or the page of `/login?return=` |
| `GET /logout`, `POST /logout` | signs out (a new session id and CSRF token), then `logout` |
| `GET /notAuthorized` | the page of people below the level a page needs (403) |
| `GET /register`, `POST /register` | the sign-up page (`Auth/register`) and the `register_user` capability, then `/login` |
| `POST /passkey/register/options`, `/passkey/register`, `/passkey/login/options`, `/passkey/login` | with `'passkeys' => true` only |

| Option | Default | What it does |
|---|---|---|
| `home` | `'/'` | where people land once signed in, and where a signed-in person opening `/login` or `/register` goes |
| `logout` | `'/'` | where people land once signed out |
| `register` | `true` | `true` uses `register_user`; `false` declares no sign-up; a string names your own capability |
| `identifier` | `'username'` | the `users` column people sign in with, and the name of its form field (`'email'`...) |
| `signInAfterRegister` | `false` | `true` signs a new account in at once and sends it to `home` |
| `attemptsPerUser` | `0` (off) | failed sign-ins of one username, from any address, before it is locked for `lock` seconds (2.19.6): against guessing spread over many machines. It lets someone lock a known username out on purpose, so keep it high (20) |
| `level` | `0` | the lowest permission level (`permissions` column) that may sign in (2.19.5): `1` lets only administrators in; anyone below is refused exactly like a wrong password, and counted toward the lock |
| `messages` | the words above | what sign-in and sign-up say, in your own words: `invalid` and `locked` (a failed sign-in, 2.19.3; `{minutes}` is the wait), `mismatch`, `register_invalid`, `register_taken` and `registered` (the sign-up page, 2.19.4). Example: `['register_taken' => 'This email already has an account: sign in instead.']` |
| `attempts` | `5` | failed sign-ins allowed per username and address |
| `lock` | `900` | the window of those failures, in seconds |
| `views` | `['login' => 'Auth/login', 'register' => 'Auth/register']` | your own views |
| `prefix` | `''` | `'/account'` gives `/account/login`...; the shipped views post to `/login`, so write your own |
| `passkeys` | `false` | `true` adds the passkey endpoints ([passkeys](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.2-Face-Detection-and-Face-Recognition#passkeys); they need the `passkeys` table of the face login recipe) |

+ **Sign-in.** The user is found with the model's `findByUsername()` (for `username`), else its `findBy($column,
  $value)`, else a bound query on its table. The password is checked with `verifyPassword()`. A username that does not
  exist takes as long to refuse as one that does. A passcode stored by an old version (encrypted with the `APP_KEY`) is
  replaced by a hash at its next sign-in.
+ **Throttle.** Failures are counted per address (`REMOTE_ADDR`) and username, in the cache (`CACHE_STORE`; the session
  when the cache is off). Behind a proxy every visitor has the proxy's address: the limit is then per username. A wrong
  password answers the sign-in page again (`200`) with *We couldn't sign you in with those details. Check them and try again.* and what was typed in the username field (never the password); a locked one, `429`.
+ **Sign-up** sends the capability every field its `$rules` declare, nothing else. When the form has `confirmpasscode`,
  it must equal `passcode`. A refusal shows the page again with the field errors (`$errors`) and what was typed
  (`$user`), never the passwords. An existing username shows *An account already exists with these details. Sign in instead, or use other details.*, and inputs to fix *A few details need a fix: see the notes under the fields.*
+ **JSON.** A request with `Accept: application/json` gets JSON answers and must send the `X-CSRF-Token` header (else
  `403`): sign-in answers `200 {"data":{"user":{"id":1,"username":"ada","permissions":0}}}`, `401` (invalid) or `429`
  (locked); sign-out `200 {"data":{"signedOut":true}}`; sign-up `201 {"data": <the profile>}` or the capability's error.
+ **Coming back.** `/login?return=/books/3` (2.20.0) keeps that page in the session, and signing in goes there instead of
  `home`, with its query string. Only a path of this site is followed: `https://...`, `//...` or a backslash is ignored and
  the person goes to `home`. `Route::page` and `Route::action` with `'comeBack' => true` build the address.
+ **Not in `Route::auth`:** password reset (the `users` table has no email address: [below](#passwordreset)) and face
  sign-in (the [face login recipe](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.2-Face-Detection-and-Face-Recognition#face-login), web-only capabilities
  and tables of its own). `'reset' => true` or `'face' => true` stops with a `LogicException`.
+ **How the session signed in.** `Route::auth` records `password` or `passkey`: [`AuthRoutes::signedInBy()`](#signedinby) reads it (2.21.3).
+ More examples: [Declarative routes](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#auth).

### Pages and capabilities that need someone

| Where | Setting | Who gets in | Others |
|---|---|---|---|
| `Route::page` | `'signedIn' => true` | anyone signed in | visitors: `302` to `/login` (`'comeBack' => true`: with `?return=`) |
| `Route::page`, `Route::form`, `Route::action` | `'visitorsOnly' => '/books'` | visitors | people signed in: `302` to that path |
| `Route::page` | `'level' => N` | signed in with `permissions >= N` | visitors: `/login`; below `N`: `/notAuthorized` |
| `#[Capability]` | `public: true` | everyone, visitors included | |
| `#[Capability]` | `level: N` (default `0`) | users with `permissions >= N`; tokens whose owner has it | `401` for visitors, `403` below the level |
| `#[Capability]` | `scope: 'books:read'` | tokens that grant the scope (`*` and `books:*` too) | `403` |

+ A signed-in user has every scope: for people only `level` counts.
+ A token created with `--user <id>` acts for that user: it needs the scope **and** the user's level. A token without
  an owner needs only the scope, whatever the level. A token whose owner was deleted is refused.
+ The command line (`php caligrafer.php call`), scheduled jobs, background jobs and webhooks have full access.
+ The level is compared with the `permissions` column (`Caligrafy\Context::$levelAttribute`).

### Helpers

| Function | What it does |
|---|---|
| `authorized()` | `true` when someone is signed in and their row in the database is unchanged |
| `user()` | the signed-in `User`, or `null` |
| `guard($attribute, $level, $loginUrl = '/login', $notAuthorizedUrl = '/notAuthorized')` | redirects and stops unless signed in with `$attribute >= $level` |
| `authorize($user)`, `unauthorize()` | signs a user in or out (no new session id: `Route::auth` does that) |
| `logout($url = '/')` | signs out, ends the session, redirects |

Each is also a static method of `Caligrafy\Auth` (`Auth::guard(...)`, `Auth::user()`). In a capability, read
`$context->user`, `$context->userId()` and `$context->level()` instead: a capability does not read the session. Only a
web-only capability (`webOnly: true`, served by `Route::action`) may.

### The `users` table and the `User` model

`application/models/Auth/create_db.sql` creates `users`: `id`, `username` (unique), `passcode` (`varchar(255)`),
`permissions` (0 by default), `created_at`, `modified_at`. `application/models/Auth/User.php` has:

```php
public function findByUsername($username);      // the User with exactly this username (bound query), or null
public function findBy($column, $value);        // the User whose column equals the value, or null
public static function hashPassword($password); // password_hash() of the password
public function verifyPassword($password);      // checks a password against the stored passcode
public function needsRehash();                  // true when the stored passcode must become a new hash
```

Passwords are stored with `password_hash()`: they cannot be read back, even with the `APP_KEY`. Accounts of older
versions, whose passcodes were encrypted with the `APP_KEY`, still sign in and get a hash then: keep the same
`APP_KEY` until they all signed in once.

### User capabilities

The people who can sign in are managed by capabilities in `application/services/Users/`, like any other feature, so
the REST API and AI agents can manage them too:

| Capability | Who | What it does |
| --- | --- | --- |
| `list_users` | administrators | the users, newest change first: `id`, `username`, `permissions`, `created_at`, `modified_at` |
| `get_user` | administrators | one user (input `id`) |
| `update_user` | administrators | changes `username`, `passcode` (8 to 72 characters) or `permissions`; only the inputs given change |
| `delete_user` | administrators | deletes a user (`destructive`) and revokes their tokens |
| `register_user` | anyone, from the sign-up page or the command line | creates an account with `permissions` 0; refused over REST and MCP, so nobody can create accounts in bulk |

+ **Administrators** have `permissions >= CaligrafyUsers::ADMIN_LEVEL` (`1`, in
  `application/services/Users/CaligrafyUsers.php`): signed in, or calling with a token created for them (`--user`). The
  command line may always manage users; the legacy API key and a token without an owner never can.
+ **No one goes above their own level**: an administrator cannot change or delete someone whose `permissions` are
  higher than theirs (`403`), nor give more than their own (`422`), and cannot delete their own account.
+ **Never a password**: every answer leaves `passcode` out.
+ `register_user` accepts usernames of letters and digits (up to 100) and passwords of 8 to 72 characters.
+ The classes are `CaligrafyListUsers`, `CaligrafyGetUser`, `CaligrafyUpdateUser`, `CaligrafyDeleteUser`,
  `CaligrafyRegisterUser` and `CaligrafyUsers`: framework names that do not collide with yours.

### Users, tokens and agents

People sign in; programs and AI agents use personal access tokens.

```bash
php caligrafer.php token create <name> --scopes <a:read,b:write | *> [--user <id>] [--expires <days>]
php caligrafer.php token list
php caligrafer.php token revoke <id>
php caligrafer.php audit [--limit 50] [--capability <name>]
```

+ A token is `cq_<id>_<secret>`, shown once and stored as a hash in `caligrafy_tokens`, sent as
  `Authorization: Bearer cq_...`.
+ An agent that manages users needs a token of an administrator:
  `php caligrafer.php token create "Claude admin" --scopes users:read,users:write --user <their id>`, connected to
  `/mcp`. A token of someone who is not an administrator does not see these tools.
+ More in [Build once: tokens](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#tokens).

## A sign-up page of your own

`/register` asks for a username and a password, and sends the person to `/login`. For a page that also asks to accept the
terms, signs in at once and is for visitors only, use `Route::form`, with the `register_user` capability
([the complete example](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#form)):

```php
Route::page('/join', 'Bookshelf/join', ['visitorsOnly' => '/books']);
Route::form('/join', 'register_user', [
    'visitorsOnly' => '/books',
    'same' => ['confirmpasscode' => ['passcode', 'The two passwords are not the same']],
    'accepted' => ['terms' => 'Accept the terms of use to create an account'],
    'signsIn' => 'id',
    'success' => '/books',
    'back' => '/join',
]);
```

## Password reset

The `users` table has no email address, so `Route::auth` has no password reset. It takes two capabilities and four routes,
and no controller. **With Claude:** "Add a password reset by email: a /forgot page, a link valid one hour that works once".

**1. The tables.** They hold data: add them with a [migration](https://github.com/caligrafy/caligrafy-quill/wiki/Migrations). Run
`docker compose exec dev-box php caligrafer.php migrate make add_password_resets`, and write in the file it names:

```sql
-- add_password_resets
ALTER TABLE users ADD COLUMN email VARCHAR(191) NULL, ADD UNIQUE KEY users_email_unique (email);

CREATE TABLE IF NOT EXISTS password_resets (
    id INT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id INT(15) NOT NULL,
    token_hash CHAR(64) NOT NULL,
    expires_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uq_password_resets_token_hash (token_hash),
    CONSTRAINT fk_password_resets_user_id FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

Run `docker compose exec dev-box php caligrafer.php migrate`. People need an address in `users.email`: ask for it at
sign-up (`Route::auth`'s `register` option names your own capability) or on an account page. When the `username` column holds
the address ([Signing in with an email](#emailsignin)), leave out the `ALTER TABLE` statement and read
`->where('username', strtolower($input['email']))` in `request_password_reset` below.

**2. The capabilities.** `application/services/Account/RequestPasswordReset.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Database;
use Caligrafy\Mail;
use Caligrafy\Service;
use Caligrafy\ServiceError;
use Caligrafy\Throttle;

// request_password_reset: emails a link to choose a new password. The answer is the same whether the address exists or not
#[Capability(
    name: 'request_password_reset',
    description: 'Emails a link to choose a new password, valid one hour. Used by the page /forgot.',
    public: true,
    mcp: false
)]
class RequestPasswordReset extends Service
{
    // link and ip come from the route ('inputs'): the form cannot set them
    public $rules = array('email' => 'required|valid_email', 'link' => 'required', 'ip' => '');

    public function handle(array $input, Context $context)
    {
        if (!in_array($context->channel, array('web', 'cli'), true)) {
            throw ServiceError::forbidden('Ask for a new password on the page /forgot');
        }
        $throttle = new Throttle(5, 3600);
        $key = Throttle::key('password-reset', $input['ip'] ?? '', $input['email']);
        if (!$throttle->locked($key)) {
            $throttle->fail($key);
            $user = Database::table('users')->where('email', $input['email'])->first();
            if ($user) {
                $token = bin2hex(random_bytes(32));
                Database::table('password_resets')->where('user_id', $user['id'])->delete();
                Database::table('password_resets')->insert(array(
                    'user_id' => $user['id'],
                    'token_hash' => hash('sha256', $token),       // the database never holds the link
                    'expires_at' => gmdate('Y-m-d H:i:s', time() + 3600),
                ));
                (new Mail())->sendMail(
                    array('email' => $input['email']),
                    array(
                        'subject' => 'Choose a new password',
                        'body' => '<p><a href="' . htmlspecialchars($input['link'] . $token) . '">Choose a new password</a>. This link works once, for one hour.</p>',
                    ),
                    array('email' => getenv('MAIL_FROM') ?: getenv('MAIL_USERNAME'), 'name' => 'Bookshelf')
                );
            }
        }
        return array('sent' => true);
    }
}
```

`application/services/Account/ResetPassword.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Database;
use Caligrafy\Service;
use Caligrafy\ServiceError;

// reset_password: a valid link sets a new password, once
#[Capability(
    name: 'reset_password',
    description: 'Sets a new password from the link of a password reset email. The link works once, for one hour.',
    public: true,
    mcp: false
)]
class ResetPassword extends Service
{
    public $rules = array('token' => 'required|alpha_numeric|exact_len,64', 'passcode' => 'required|min_len,8|max_len,72');
    public $descriptions = array('token' => 'The token of the link', 'passcode' => 'The new password: 8 to 72 characters');

    public function handle(array $input, Context $context)
    {
        $reset = Database::table('password_resets')->where('token_hash', hash('sha256', $input['token']))->first();
        if (!$reset || $reset['expires_at'] < gmdate('Y-m-d H:i:s')) {
            throw ServiceError::invalid(array('token' => 'This link no longer works: ask for a new one'), 'This link no longer works: ask for a new one');
        }
        Database::table('users')->where('id', $reset['user_id'])->update(array('passcode' => User::hashPassword($input['passcode'])));
        Database::table('password_resets')->where('id', $reset['id'])->delete();
        return array('reset' => true);
    }
}
```

## A sign-in through another site

Signing in through another site (a partner, a company directory, OAuth) needs the session, sends the browser away and signs
someone in: two web-only capabilities and two [`Route::action`](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#action) lines.
**With Claude:** "Add 'Sign in with Partner': the code comes back to /auth/partner".

`application/services/Account/PartnerSignIn.php` (`PARTNER_URL`, `PARTNER_CLIENT_ID` and `PARTNER_CLIENT_SECRET` in `.env`):

```php
<?php

use Caligrafy\AuthRoutes;
use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Database;
use Caligrafy\Service;
use Caligrafy\Web;

// GET /signin/partner: off to the other site, with a value only this browser knows
#[Capability(name: 'partner_sign_in', description: 'Sends the visitor to sign in on the partner site.', public: true, webOnly: true)]
class PartnerSignIn extends Service
{
    public function handle(array $input, Context $context)
    {
        $state = bin2hex(random_bytes(16));
        session('partner_state', $state);
        return Web::redirect(getenv('PARTNER_URL') . '/authorize?' . http_build_query(array(
            'client_id' => getenv('PARTNER_CLIENT_ID'),
            'redirect_uri' => session('home') . 'auth/partner',
            'state' => $state,
        )));
    }
}

// GET /auth/partner?code=&state=: back from the other site
#[Capability(name: 'partner_callback', description: 'Finishes a sign-in on the partner site.', public: true, webOnly: true)]
class PartnerCallback extends Service
{
    public $rules = array('code' => '', 'state' => '');

    public function handle(array $input, Context $context)
    {
        $expected = (string) session('partner_state');
        clearFromSession('partner_state');
        if ($expected === '' || !hash_equals($expected, (string) ($input['state'] ?? ''))) {
            return Web::redirect('/login');      // a sign-in that did not start in this browser
        }
        // the code is traded for the account, server to server, with the secret
        $answer = httpRequest(getenv('PARTNER_URL') . '/token', 'POST',
            array('code' => $input['code'] ?? '', 'client_secret' => getenv('PARTNER_CLIENT_SECRET')),
            array('Content-Type: application/json', 'Accept: application/json'));
        $username = 'partner' . preg_replace('/[^0-9]/', '', (string) ($answer['id'] ?? ''));
        if ($username === 'partner') {
            return Web::redirect('/login');
        }
        $users = new User('users');
        if (!$users->findByUsername($username)) {
            Database::table('users')->insert(array('username' => $username, 'passcode' => User::hashPassword(bin2hex(random_bytes(32)))));
        }
        AuthRoutes::signIn($users->findByUsername($username));
        return Web::redirect('/books');
    }
}
```

```php
    Route::action('/signin/partner', 'partner_sign_in');
    Route::action('/auth/partner', 'partner_callback');
```

`/signin/partner` answers `302` to the other site with a `state`. Back at `/auth/partner`, a wrong or missing `state` goes
to `/login`; the right one signs the person in and goes to `/books`. To remember how, for what only some sign-ins may do,
pass it as the third argument: `AuthRoutes::signIn($user, null, 'partner')`, then read it with `AuthRoutes::signedInBy()`
([above](#signedinby)). `AuthRoutes::signIn()` gives a new session id and a new
CSRF token. A page that stays open and keeps calling JSON uses `session_regenerate_id(true); Auth::authorize($user);`, as the
[face login recipe](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.2-Face-Detection-and-Face-Recognition#face-login) does, so its token stays valid.

## How a session signed in

Since 2.21.3, `AuthRoutes::signedInBy()` says how the current session signed in. `Route::auth` records `password` or
`passkey`. When you sign someone in yourself, say how:

```php
AuthRoutes::signIn($user, null, 'face');        // a new session id, a new CSRF token, and how it signed in
AuthRoutes::rememberSignIn('face');             // a page that stays open and signs in with Auth::authorize()
```

Use it for anything that changes how the account signs in. A face without a liveness check does not prove a person (a good
photo can pass), so a session opened that way must not be able to replace the face or add a passkey:

```php
if (AuthRoutes::signedInBy() !== 'password') {
    return Web::json(['error' => 'Sign in with your password to change your face'], 403);
}
```

It answers `null` when nobody is signed in or the sign-in was not recorded: treat that as not allowed. Signing out forgets it.

| Function of `Caligrafy\AuthRoutes` | What it does |
|---|---|
| `signIn($user, null, $how = null)` | a new session id, a new CSRF token, `Auth::authorize($user)`, and records `$how` |
| `rememberSignIn($how)` | records `$how`, for a page that signs in with `Auth::authorize()` (`null` forgets it) |
| `signedInBy()` | `password` or `passkey` through `Route::auth`, what you recorded otherwise, `null` when nobody recorded it or nobody is signed in |
| `signOut()` | `Auth::unauthorize()`, forgets `$how`, a new session id and CSRF token |

`Route::form` with `signsIn` records `password` (2.21.7); give another with `'signsInWith' => 'face'`.

## Signing in with an email

`register_user` takes usernames of letters and digits. For people who sign in with their email address, the simplest way
keeps the `users` table: the `username` column holds the address, in lower case. `Route::auth`, passkeys, the throttle and
`$user['username']` keep working, with no new column. (A table with a separate `email` column: [other ways](#emailcolumn).)

**With Claude.** Say it in your idea or your request: *"people sign in with their email, kept in the username column"*.
`/caligrafy-quill:idea` puts it in the plan and writes the steps below.

**Check:** a sign-up with `Ada@Example.COM` lands in `users.username` as `ada@example.com`, and signing in as
`ADA@example.com` works.

**By hand**

**1. The column.** An address can be 254 characters. Before the table exists, write `username varchar(254) NOT NULL` in
`application/models/Auth/create_db.sql`. For a table that exists, run
`docker compose exec dev-box php caligrafer.php migrate make username_holds_email`, write in the file it names:

```sql
-- username_holds_email
ALTER TABLE users MODIFY username varchar(254) NOT NULL;
```

and run `docker compose exec dev-box php caligrafer.php migrate`.

**2. The rules.** In `application/services/Users/CaligrafyRegisterUser.php`, replace the `$rules` line with:

```php
public $rules = array('username' => 'required|valid_email|max_len,254', 'passcode' => 'required|min_len,8|max_len,72');
public $filters = array('username' => 'trim|lower_case');
```

and in `application/services/Users/CaligrafyUpdateUser.php` make the rule of `username` `'valid_email|max_len,254'` and add
`public $filters = array('username' => 'trim|lower_case');`. A later `update` keeps these two files and writes the
release's copies next to them as `.caligrafy-new`.

**3. The forms.** In `application/views/Auth/login.pug`, replace the `- $field`, `- $isEmail` lines and the `.cq-field` of the
identifier with:

```pug
        .cq-field
          label(for='username') Email
          input#username.form-control(type='email', name='username', value=isset($user) && is_object($user) ? ($user->username ?? '') : '', required, autocomplete='email', autocapitalize='none', maxlength='254')
```

In `application/views/Auth/register.pug`, change the `p.cq-lead` line to `p.cq-lead Your email address, and at least 8
characters for the password.` and the first `.cq-field` to:

```pug
      .cq-field
        label(for='username') Email
        input#username.form-control(type='email', name='username', value=$user->username?? '', required, autocomplete='email', autocapitalize='none', maxlength='254')
        if isset($errors['username'])
          p.cq-field-error= $errors['username']
```

The field stays named `username`. A sign-up page of your own ([above](#signupform)) changes the same way.

**4. The words.** Say it in the messages of `Route::auth`:

```php
Route::auth(['home' => '/books', 'messages' => [
    'invalid' => 'Invalid email or password',
    'register_taken' => 'An account already uses this email',
]]);
```

| You do | You get |
|---|---|
| *Create account* with `not an email` | *A few details need a fix: see the notes under the fields.*, with the field's message under it |
| *Create account* with `Ada@Example.COM` | `302` to `/login`; `SELECT username FROM users` shows `ada@example.com` |

## Other ways

### The authentication controller

Projects made before 2.19.0 declare the sign-in pages with `Caligrafy\Controllers\AuthController`
(`application/controllers/core/Auth/AuthController.php`). They keep working; use them or `Route::auth`, never both.

```php
Route::get('/home', 'Caligrafy\\Controllers\\AuthController@home');
Route::get('/login', 'Caligrafy\\Controllers\\AuthController');
Route::get('/logout', 'Caligrafy\\Controllers\\AuthController@logout');
Route::get('/notAuthorized', 'Caligrafy\\Controllers\\AuthController@notAuthorized');
Route::get('/register', 'Caligrafy\\Controllers\\AuthController@registerForm');
Route::post('/login', 'Caligrafy\\Controllers\\AuthController@login');
Route::post('/register', 'Caligrafy\\Controllers\\AuthController@register');
```

It signs in to `/home` and has neither the throttle, nor the new session id, nor the `?return=` of `Route::auth`. A
controller you keep signs a user in with `authorize($user)`: call `session_regenerate_id(true)` just before it.

### The user administration pages

`AdminController` serves pages that list, edit and delete users, through the user capabilities above, for
`permissions >= 1`. The template's lines still name it, and it works:

```php
Route::get('/admin', 'Caligrafy\\Controllers\\AdminController');
Route::get('/users', 'Caligrafy\\Controllers\\AdminController');
Route::get('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@editUserForm');
Route::put('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@updateUser');
Route::delete('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@deleteUser');
```

To declare them instead, give the capabilities' answers to views of your own (the shipped ones expect the objects
`AdminController` passes):

```php
Route::page('/users', 'Admin/users', ['level' => CaligrafyUsers::ADMIN_LEVEL, 'data' => ['people' => 'list_users']]);
Route::page('/users/{id}/edit', 'Admin/person', ['level' => CaligrafyUsers::ADMIN_LEVEL, 'data' => ['person' => 'get_user'], 'notFound' => 'Admin/missing']);
Route::form('/users/{id}/edit', 'update_user', ['method' => 'PUT', 'success' => '/users', 'back' => '/users/{id}/edit']);
Route::form('/users/{id}/edit', 'delete_user', ['method' => 'DELETE', 'success' => '/users']);
```

Short names (`'AuthController@login'`) keep working: a short name that is not a class of yours falls back to
`Caligrafy\Controllers`.

### A separate `email` column

[Signing in with an email](#emailsignin) keeps the address in `username`, and is the simplest. When you need both a username
and an address, `Route::auth(['identifier' => 'email'])` signs in with the `email` column, and the shipped `login.pug` names its
field after `$identifier`. The shipped `users` table has no `email` column and `register_user` asks for a username: add the
column in a migration and write your own sign-up capability (`'register' => 'register_reader'`) whose `$rules` declare
`email`.

## Common mistakes

+ **A sign-out form answers `[ERROR 3000]` (403) before 2.19.1.** In 2.19.0 a `POST /logout` sent by a form signed out,
  then failed its CSRF check against the new token. Since 2.19.1 the form works (`form(method='POST', action=$home .
  'logout')` with `=csrf()`); on 2.19.0, sign out with a link, `a(href=$home . 'logout') Sign out`.
+ **Promoted, then sent to `/login`.** Changing a user's row (their `permissions`) ends their session: they sign in again.
+ **`Route::auth needs Auth::authentication('User', 'users') in web.php`.** Uncomment that line above `Route::auth`.
+ **Usernames with `@` or spaces are refused** at sign-up (`alpha_numeric`): say so next to the form, or
  [sign in with an email](#emailsignin).
+ **A `prefix` with the shipped views.** They post to `/login` and link to `/register`: with a prefix, write your own.
+ **A JSON sign-in answers 403.** Send the `X-CSRF-Token` header with the session's token.
+ **Locked out while testing.** `php caligrafer.php cache clear` empties the failure counts.
+ **A view without `$user`.** A closure that returns `view()` does not get `$authorized` and `$user`: use `Route::page`,
  or `Web::view()` in a web-only capability.
+ **A `return=` that goes nowhere.** Only a path of this site is followed: `/books/3`, never `https://...` or `//...`.
