## Activating the Database
In order to use authentication, the Database needs to be activated. 
> [Learn more about Database Activation](https://github.com/caligrafy/caligrafy-quill/wiki/4.-Models)

## Routing
In order to activate authentication, the following line should be **uncommented** from `/application/config/routing/web.php`:
```php
// AUTHENTICATION - Remove comment if you have an authentication implemented
  Auth::authentication('User', 'users');

```

This framework comes with a prepackaged set of routes that help illustrate how logging in, registration and logging out work. In order to activate these routes, the following lines should be **uncommented** from `/application/config/routing/web.php`:
```php
// Auth Routes - Uncomment only if AUTHENTICATION activated above
  Route::get('/home', 'Caligrafy\\Controllers\\AuthController@home');
  Route::get('/login', 'Caligrafy\\Controllers\\AuthController');
  Route::get('/logout', 'Caligrafy\\Controllers\\AuthController@logout');
  Route::get('/notAuthorized', 'Caligrafy\\Controllers\\AuthController@notAuthorized');
  Route::get('/register', 'Caligrafy\\Controllers\\AuthController@registerForm');
  Route::post('/login', 'Caligrafy\\Controllers\\AuthController@login');
  Route::post('/register', 'Caligrafy\\Controllers\\AuthController@register');
```

Also this framework comes with prepackaged user interfaces to manage users. In order to activate user management routes, the following lines should be **uncommented** from `/application/config/routing/web.php`:

```php

// User Administration Routes - Uncomment only if AUTHENTICATION activated above
Route::get('/admin', 'Caligrafy\\Controllers\\AdminController');
Route::get('/users', 'Caligrafy\\Controllers\\AdminController');
Route::get('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@editUserForm');
Route::put('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@updateUser');
Route::delete('/users/{id}/edit', 'Caligrafy\\Controllers\\AdminController@deleteUser');

```

The example controllers are declared in the `Caligrafy\Controllers` namespace. Routes written with the short names (`'AuthController@login'`, `'AdminController'`) keep working: a short name that is not a class of yours falls back to `Caligrafy\Controllers`.

## `users` table
As part of this framework, a MySql script is provided to create the basic `users` table to put in place an authentication mechanism. This script can be found in `application/models/Auth/create_db.sql`.

This script can be run from either the Terminal or from a DB manager application such as `phpMyAdmin`. It creates the table only if it does not exist, so running it again never deletes your users.

> **Upgrading an existing project:** older versions of the script created `passcode` as `varchar(100)`. Password hashes fit in it, but `varchar(255)` is recommended (step 4 of [Upgrading an existing project](https://github.com/caligrafy/caligrafy-quill/wiki/9.5-Security-and-Upgrading#upgrading)) because it leaves room for future algorithms: `ALTER TABLE users MODIFY passcode varchar(255) NOT NULL;`

**Run from the Terminal** 
```
~: cd application/models/Auth
~: mysql -u <username> -p <databasename> < create_db.sql

```
**Run from phpMyAdmin**
- Click on the database name that you created
- Click `Import` from the action menu
- Browse to `application/models/Auth`
- Select the file `create_db.sql`
- Click on `Go`

## `User` Model
The framework has a `User` Model already created for use that can be found in `/application/models/Auth/User.php`.
This model is a representation of the database table that was previously created.
Both the table and the model have basic attributes `id`, `username`, `passcode`, `permissions`, `created_at`, `modified_at`. `username` is unique.

The model also provides the methods used by the authentication controller:
```php
public function findByUsername($username); // returns the User with exactly this username (bound query), or null
public static function hashPassword($password); // returns a password_hash() of the password, to store in passcode
public function verifyPassword($password); // checks a password against the stored passcode
public function needsRehash(); // true when the stored passcode must be upgraded to a new hash
```

### Password storage
Passwords are stored with PHP's `password_hash()` and checked with `password_verify()`: they cannot be decrypted, even with the `APP_KEY`.

Older versions of Caligrafy stored passcodes encrypted with the `APP_KEY`. Those users can still log in: on their next successful login, their passcode is automatically replaced by a hash. Do not change the `APP_KEY` before all your users have logged in once, otherwise the old passcodes can no longer be checked.

> Before making any changes to both the table and the model, we recommend that you understand how the authentication mechanism works and how the out-of-the-box controllers and views are implemented

## Authentication Controller
The authentication controller is the controller that will allow interfacing with the `User` model, the `users` table and the different authentication views (explained in the next section).
This controller can be found in `/application/controllers/core/Auth/AuthController.php` (class `Caligrafy\Controllers\AuthController`).

This controller is shipped with 7 methods that can be accessed from the route
+ **index()**: This method is called from a `GET` route and it returns the `Auth/login` view, or redirects to `/home` when the user is already logged in.
+ **home()**: This method is called from a `GET` route and it returns the `default/index` view that has 2 states, authorized and not authorized.
+ **registerForm()**: This method is called from a `GET` route and it returns the `Auth/register` view.
+ **notAuthorized()**: This method is called from a `GET` route and it shows the page of a visitor who is not allowed to see a page.
+ **register()**: This method is called from a `POST` route to create a new record in the `users` tables. The username must be alphanumeric and unique, and the password must have between 8 and 72 characters.
+ **login()**: This method is called from a `POST` route to validate the credentials entered against a record in the `users` table. The user is found by exact username and the password is checked with `password_verify()`.
+ **logout()**: This method is called from a `GET` route and calls a `logout` core helper method that unauthorizes a user and redirects to a specified URL after logging out.

It is also shipped with an `AdminController` (`/application/controllers/core/Auth/AdminController.php`) whose administration methods are controlled by the `guard` method. They require `permissions` to be at least `AdminController::ADMIN_PERMISSION` (`1` out-of-the-box). New users are registered with `permissions` set to `0`, so they cannot manage users. Promote your first administrator directly in the database:
```sql
UPDATE users SET permissions = 1 WHERE username = 'your-username';
```
The user needs to log in again after a change of permissions.
+ **index()**: This method is called from a `GET` route and it returns the `users` view that lists all the users that are registered in the system
+ **editUserForm()**: This method is called from a `GET` route and it returns the `manageusers` in an editing form that allows modifying the user information
+ **updateUser()**: This method is called from a `PUT` route to update the user record
+ **deleteUser()**: This method is called from a `DELETE` route to delete a user record

## Authentication Views
This framework comes with several views out-of-the-box to perform the basic authentication interactions.
+ **`/application/views/default/index.pug`:** This view acts as a welcome page that has 2 states, authorized and unauthorized - to help illustrate how authentication works.
+ **`/application/views/Auth/login.pug`:** This view has a basic login form with basic field validations.
+ **`/application/views/Auth/register.pug`:** This view has a basic registration form with basic field validations. 

The following view are user management views:
+ **`/application/views/Auth/users.pug`:** This view displays all the users registered in a tabular format.
+ **`/application/views/Auth/manageusers.pug`:** This view has an editing form to modify the user record.

## Authentication Methods
Once a user is authenticated, this framework comes with a set of core helper methods that can be used in the context of a `Controller` to restrict or grant access to the different controller actions.

+ **Check if logged in:** In order to check if a user is authorized (logged in)
```php
function authorized(); // returns a boolean of whether or not a user is logged in
function user(); // returns the information of a logged in user, otherwise it returns null
```

+ **Log in or log out:** In order to authorize (log in) or unauthorize (logout) a user
```php
function authorize($user); // use this method upon your login mechanism to authorize user
function unauthorize(); // use this method upon your logout mechanism to unauthorize all users
function logout($redirectUrl = '/'); // logs out an authenticated user and redirects to the specified url
```
+ **Permissions:** In order to check for permissions, this framework provides a way to put a `guard` on a controller action. The `guard` not only checks if the user is authenticated (logged in) but it also checks their permission level and restricts their access to the action if their permission is `<` than the accepted permission level to run the action. 
```php
function guard($permissionAttribute, $acceptedPermission, $loginUrl = '/login', $notAuthorizedUrl = '/notAuthorized'); // redirects to $loginUrl when nobody is logged in, to $notAuthorizedUrl when the permission is too low, and stops the script
```
The `$permissionAttribute` is the name of the attribute in the `users` database table that holds the permissions. In the out-of-the-box table, this attribute name is `permissions`. If that attribute is changed in the table, the `guard` function provides a way to change it.
