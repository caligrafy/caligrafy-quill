# 9.9.1 Creating Bots with Watson

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.1-Creating-Bots-with-Watson
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

With the advancement of Artificial Intelligence, conversational user interfaces have become quite popular. Conversational UIs, whether through messaging or voice, rely heavily on natural language processing. Natural language processing is in itself achieved through machine learning. 

The Caligrafy `Bot` makes use of IBM Watson Assistant as the core natural language processor and it provides a server-side framework that communicates with the IBM Watson Assistant API. Also, Caligrafy uses VueJS on the client-side in order to provide an appealing user interface for the conversation.

APIs that the Caligrafy `Bot` uses:
+ **Server-side**: Caligrafy core framework class that interfaces with the [IBM Watson Assistant API](https://cloud.ibm.com/apidocs/assistant/assistant-v2)
+ **Client-side**: a small Vue 3 chat application (`framework/plugins/bot`), no other library needed

> ### Requirements 
> + [IBM Cloud free account](https://cloud.ibm.com/registration) with an IBM Watson Assistant
> + All the Dialog logic is created using IBM Watson Assistant interface
> + Caligrafy VueJS integration. You can learn more about the integration in the Caligrafy and Vue section
> + The bot client is a Vue 3 chat (pinned Vue 3.5.44). It replaced the BotUI library, which only supports Vue 2 and React

## `Bot` out-of-the-box

>
> In this video, we show how Caligrafy connects to IBM Watson to help you implement your own custom bot.

> [Live Example: Ask Cali to show you a picture of a dog or a cat](https://caligrafy.com/bot/cali?botSkillId=62196ce3-0b22-4aea-b2f2-d39730c03797)

Caligrafy comes prepackaged with a `Bot` that can connect to your Watson IBM Assistant and that you can start using in 4 steps:

### Step 1: Get the Bot app from Caligrafer

+ From the Caligrafy project root, use Caligrafer to create a bot app by running 

    ```php

       .bin/caligrafer bot `<your_bot_app_name>`

       // or 

       php caligrafer.php bot `<your_bot_app_name>`

    ```

+ A new app <your_bot_app_name> was created in the `public` folder. 

### Step 2: Create an IBM Watson Assistant 

After you open an account with IBM Cloud, you can create an IBM Watson Assistant. From the IBM Watson Assistant manager, you can create several assistants. When you create an assistant and you launch it, you are provided with an **`API key`** and with an **`Assistant ID`**. 

You need both these credentials to link them to Caligrafy.

### Step 3: Linking the IBM Watson Assistant to Caligrafy

+ In the `.env` file of Caligrafy, add:
    + `WATSON_API_KEY`: the **`API key`** of the service
    + `WATSON_URL`: the URL of your service instance, `https://api.<region>.assistant.watson.cloud.ibm.com/instances/<instance_id>` (Service credentials in IBM Cloud). It is required
    + `WATSON_ENVIRONMENT_ID` (optional): the environment of the assistant (Environment settings > API details in watsonx Assistant). Recent assistants need it: sessions are created in `/v2/assistants/<assistant_id>/environments/<environment_id>/sessions`
    + `WATSON_API_VERSION` (optional): the API version date, `2024-08-25` by default
+ The v2 API needs a watsonx Assistant Plus plan or higher
+ Check the URL and the key with `php caligrafer.php doctor --only watson` (add `WATSON_ASSISTANT_ID=<assistant id>` to `.env` to check the assistant too). See [Caligrafer doctor](1.-Getting-Started#doctor)

+ In the Caligrafy `config/routing/web.php` file, out-of-the-box routes are already built-in to help you get started quickly. Later on, we will explain how you can modify those routes to best match your application.

+ Now you can test the Bot. You need to make sure to specify the Watson Assistant ID as a URL parameter when accessing the route `localhost/caligrafy-quill/bot/<your_bot_app_name>?botSkillId=<Watson Assistant ID>`

### Step 4: Build your IBM Assistant dialog flow on IBM Watson Assistant

Now that the assistant is linked to Caligrafy, you can start building the dialog flow. This documentation will not go through explaining how to build a dialog flow. IBM provides great tutorials and videos on how to do that.

It is important for Caligrafy to understand what types of responses the IBM Watson responds with. There are 4 types of responses possible: 

+ **`text`:** The text response is the simplest form of responses and that is a sentence in any form or tense.

+ **`option`:** The assistant can always provide a collection of choices for users to select from. This is a typical way to restrict the user to making choices as opposed to open-ended answers.

+ **`image`:** The assistant could send images in a response.

+ **`pause`:** The assistant could pause for a certain period of time either to allow the user to answer or to execute an action that requires some time before responding back to the user.

It is also important to understand what types of inputs can be given to the IBM Watson Assistant

+ **`text`:** The assistant understands text and through natural language processing, it will direct the dialog by providing follow up responses.

+ **`context variables`:** The assistant can also receive context variables as inputs. Think of these context variables as a storage that is sent to the assistant that constitutes its knowledge. So for example, if you give your name to the assistant, it could refer to you by your name throughout the session and not ask you for your name anymore. 

> Learn more about creating dialogs with the IBM Watson Assistant [here](https://cloud.ibm.com/docs/services/assistant-data?topic=assistant-data-getting-started)

### Step 5: Converse using Caligrafy `Bot`

Once your Assistant is ready to have a conversation, you can first test it in the IBM Watson Assistant to make sure that it is conversing the way you intend it to.

Now you can test the Bot. You need to make sure to specify the Watson Assistant ID as a URL parameter when accessing the route `localhost/caligrafy-quill/bot/<your_bot_app_name>?botSkillId=<Watson Assistant ID>`

## Creating your own Bot client-side UI

If you want to create your own client-side UI, you will need to use the Caligrafy and Vue integration. 

### Step 1: Create your client-side structure
Just like any other Caligrafy-Vue `app`, your `Bot` app needs to be created in the `public` folder using Caligrafer. Refer to Step 1 in the previous section to see how it is done.

Once the bot app created, a folder with the name you specified is created under the `public` folder. You can find in there `index.php` and a `scripts` folder containing a javascript file `main.js` that contains the VueJS code.

We will explore both of those files in the next steps.

### Step 2: `index.php`

The `index.php` is the markup of your Bot application: the messages, the answer buttons and the text input are a Vue 3 template.
```html
<!DOCTYPE html>
<html lang="en">
    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1">
        <title>Caligrafy Bot</title>
        <link rel="shortcut icon" href="<?php echo scripts('favicon'); ?>" type="image/x-icon" />
        <link rel="stylesheet" href="<?php echo scripts('bootstrap_css'); ?>" />
        <link rel="stylesheet" href="<?php echo session('public').'css/bot.css';?>">
    </head>

    <body>
        <div id="app" class="bot-container" v-cloak>
            <div class="bot-messages" ref="messages">
                <div v-for="(message, index) in messages" :key="index" class="bot-message" :class="message.human ? 'human' : 'bot'">
                    <template v-if="message.type === 'image'">
                        <a :href="message.source" target="_blank" rel="noopener">{{ message.title || message.source }}</a>
                        <img :src="message.source" :alt="message.title" class="bot-image">
                    </template>
                    <template v-else>{{ message.content }}</template>
                </div>
            </div>

            <!-- Buttons answer (Watson "option" responses) -->
            <div v-if="action.type === 'button'" class="bot-actions">
                <button v-for="option in action.options" :key="option.value" type="button" class="btn btn-outline-primary btn-sm" @click="answer(option.value, option.text)">{{ option.text }}</button>
            </div>

            <!-- Free text answer -->
            <form v-else-if="action.type === 'text'" class="bot-input" @submit.prevent="answer(text, text)">
                <input v-model="text" class="form-control" type="text" placeholder="Type a message" aria-label="Message">
                <button class="btn btn-primary" type="submit" :disabled="!text.trim()">Go</button>
            </form>
        </div>

        <script src="<?php echo scripts('vue'); ?>"></script>
        <script src="<?php echo scripts('axios'); ?>"></script>
        <script src="<?php echo APP_SERVICE_ROOT.'app.js'; ?>"></script>
        <script>loadEnvironment(`<?php echo $env; ?>`);</script>
        <script>loadVue({ scripts: ['main'] });</script>
    </body>
</html>
```

Messages are always rendered as text (never as HTML), so nothing that the assistant sends can inject code in the page.

### Step 3: VueJS main script

Your VueJS code lives in the `scripts` folder. It can have any name that you desire. Once named, the name needs to be invoked (without the .js extension) in the `index.php` (check the code in the previous step).

The main script keeps the conversation (`messages`) and the expected answer (`action`): a free `text` input or a list of `button` options.

```js
const app = Vue.createApp({
    data() {
        return {
            env: env,
            botId: env.botSkillId,
            route: env.home + "__bots__/" + env.appName + "/",
            messages: [],
            action: { type: null, options: [], context: null },
            text: '',
            config: { headers: { "Authorization": "Bearer " + apiKey, "Accept": "application/json", "Content-Type": "application/json" } }
        };
    },
    methods: {
        addMessage(content, human = false) { this.messages.push({ type: 'text', content: content, human: human }); },
        addImage(source, title) { this.messages.push({ type: 'image', source: source, title: title, human: false }); },
        addAction(type, options = [], context = null) { this.action = { type: type, options: options, context: context }; },
        answer(value, label) {
            const input = { text: value };
            if (this.action.context) input.variables = this.action.context;
            this.addMessage(label, true);
            this.text = '';
            this.action = { type: null, options: [], context: null };
            this.communicate(input);
        }
        // connect() and communicate(): see Step 5
    },
    mounted() {
        this.connect();
        this.addMessage("Hi there!");
        this.addAction('text', [], { "bot_name": 'Cali' });
    }
});

app.mount('#app');
```

### Step 4: Routing to your client-side app

Just like any Caligrafy and VueJs app, the server-side needs to route the url to the client-side pages. For that, you can do small modifications to the routes that come out-of-the-box with Caligrafy since we will be using the same Caligrafy Bot Controller. 

```php
...
// BOT PAGE ROUTES
Route::get('/bot/{appName}', 'ClientController');  // A botSkillId needs to be provided in the URL. 

// BOT DATA ROUTES
// routes need to start with reserved path __bots__ 
Route::post('/__bots__/{appName}/communicate', 'WatsonController@communicate');
Route::post('/__bots__/{appName}/{appId}', 'WatsonController@connect');
Route::delete('/__bots__/{appName}', 'WatsonController@end');   
...  

```
Notice that there is one `Page Route` and 3 `Data Routes` (Refer to the Routes section of the Caligrafy and Vue section to learn about the difference).

The `Data Routes` are request endpoints to the Caligrafy Bot Controller:
+ **`connect`:** Post request that connects to the IBM API
+ **`communicate`:** Post request that sends a message and retrieves a response from the IBM API
+ **`end`**: Delete request that manually ends the Bot instance. 

There are many changes that you can do to the Page Routes to tailor them to the needs of your application.

+ For Page routes, you can specify any path to route to as long as it always ends with {appName} variable. Don't forget that a `botSkillId` needs to be provided in the browser URL of the route as such: `localhost/caligrafy-quill/<any path you specify in the route>/<your_bot_app_name>?botSkillId=<Watson Bot Skill Id>

+ If the destination page of your Page Route is not `index.php`, you can override that in the URL by appending an `app=<name of php file>` to the URL provided in the browser

### Step 5: VueJS interfacing with the Caligrafy Bot server-side

Your VueJS main script talks to the endpoints with `axios`. The data routes are controller routes, so the requests send the JSON headers and the API key (in `config`).

```js
        // Connect to the bot
        connect() {
            return axios.post(this.route + this.botId, {}, this.config)
                .then(response => response.data === true)
                .catch(error => { console.log(error); return false; });
        },

        // Communicate with the bot
        communicate(input) {
            return axios.post(this.route + 'communicate', input, this.config)
                .then(response => {
                    const data = response.data;
                    if (!(data && data.action_success === true && data.response)) {
                        this.addMessage("Bye for now. You can close the chat");
                        return;
                    }
                    data.response.forEach(element => {
                        switch (element.response_type) {
                            case 'text':
                                this.addMessage(element.text);
                                this.addAction('text');
                                break;
                            case 'option':
                                this.addMessage(element.title);
                                this.addAction('button', element.options.map(option => ({ text: option.label, value: option.value.input.text })));
                                break;
                            case 'image':
                                this.addImage(element.source, element.title);
                                this.addAction('text');
                                break;
                            case 'pause':
                                // run your own action: define window.executeBotAction(context) => { text, variables }
                                if (data.context && data.context.action && typeof window.executeBotAction === 'function') {
                                    const result = window.executeBotAction(data.context);
                                    if (result) {
                                        this.addMessage(result.text);
                                        this.addAction('text', [], result.variables);
                                    }
                                }
                                break;
                        }
                    });
                })
                .catch(error => console.log(error));
        }
```

> The complete client (with a typing indicator and automatic scrolling) is in `framework/plugins/bot`, copied to `public/<your_bot_app_name>` by `caligrafer bot`. Its style is in `public/css/bot.css`.
