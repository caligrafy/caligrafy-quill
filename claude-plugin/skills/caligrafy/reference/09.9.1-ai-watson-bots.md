# 9.9.1 Creating Bots with Watson

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.1-Creating-Bots-with-Watson
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A **bot** is a chat window where people talk to an assistant in plain language. Caligrafy connects to
[IBM watsonx Assistant](https://cloud.ibm.com/apidocs/assistant/assistant-v2): you design the conversation (intents,
answers, choices) in IBM's interface, and Caligrafy gives you the chat app (a small Vue 3 app in `public/<name>`) and
the server side (`Caligrafy\Watson`), which keeps your key on the server. In the Bookshelf example, the help desk
answers questions such as opening hours and loans: people use it in the chat window, and the capability `ask_helpdesk`
gives the same answers to pages, the REST API and AI agents.

You need an [IBM Cloud account](https://cloud.ibm.com/registration) with a watsonx Assistant on the **Plus plan or
higher** (the v2 API that Caligrafy uses needs it).

> #### (video) [Creating Bots with Caligrafy](https://youtu.be/TVajzJIDwfA)
>
> The video shows how Caligrafy connects to IBM Watson to build your own bot.

## With Claude

```text
/caligrafy-quill:new-app bot helpdesk
```

Claude checks the name, runs `docker compose exec dev-box php caligrafer.php bot helpdesk`, and tells you the address to open
(`/bot/helpdesk?botSkillId=<assistant id>`) and the `.env` settings to fill. To reach the same assistant from pages,
REST and agents, ask for a capability too:

```text
/caligrafy-quill:new-capability ask_helpdesk ai:use read-only
Ask the watsonx help desk one question and return its text answer.
```

**Check**
- `WATSON_API_KEY`, `WATSON_URL` and `WATSON_ASSISTANT_ID` are in `.env`; `docker compose exec dev-box php caligrafer.php doctor --only watson` says OK.
- The chat page answers your first message; without `?botSkillId=` it says *No assistant here: add ?botSkillId=<assistant id> to the address of this page.*
- The bot's script calls the data routes with `apiHeaders()` (the session and its CSRF token), never an API key.

## By hand

Run the commands in the project folder of the [Quickstart](https://github.com/caligrafy/caligrafy-quill/wiki/Quickstart).
Without Docker (Composer with MAMP, XAMPP or LAMP), run the same commands without `docker compose exec dev-box` and
open your own address.

### Step 1: Create the assistant on IBM Cloud

In watsonx Assistant, create an assistant and build its conversation (try it in IBM's preview first). Then collect:

+ the **API key** and the **instance URL** (IBM Cloud > your Assistant service > Service credentials):
  `https://api.<region>.assistant.watson.cloud.ibm.com/instances/<instance_id>`;
+ the **assistant id** and, for recent assistants, the **environment id** (Assistant settings, or Environments >
  API details).

### Step 2: Add the settings

Open `.env` and fill the Watson lines (add `WATSON_ASSISTANT_ID`, which is not in `.env.example`):

```text
WATSON_API_KEY=...
WATSON_URL=https://api.us-south.assistant.watson.cloud.ibm.com/instances/<instance_id>
WATSON_ENVIRONMENT_ID=
WATSON_API_VERSION=2024-08-25
WATSON_ASSISTANT_ID=<assistant id>
```

`WATSON_URL` has no `/v2` at the end: Caligrafy adds the path. Run:

```bash
docker compose exec dev-box php caligrafer.php doctor --only watson
```

Expected: `OK    Watson: key and assistant accepted ...` (with `WATSON_ASSISTANT_ID` it opens and closes a test session).

### Step 3: Create the chat app

```bash
docker compose exec dev-box php caligrafer.php bot helpdesk
```

Expected:

```text
 Project created in the public folder.
 Type cd public/helpdesk to access it anytime
```

It copies `framework/plugins/bot` to `public/helpdesk`: `index.php` (the chat markup) and `scripts/main.js` (the Vue
app); the style is `public/css/bot.css`. The routes are already in `application/config/routing/web.php`:

```php
// BOT PAGE ROUTES
Route::get('/bot/{appName}', 'Caligrafy\\Controllers\\ClientController');  // A botSkillId needs to be provided in the URL. For Example: ?botSkillId=62196ce3-0b22-4aea-b2f2-d39730c03797

// BOT DATA ROUTES
// routes need to start with reserved path __bots__
Route::post('/__bots__/{appName}/communicate', 'Caligrafy\\Controllers\\WatsonController@communicate');
Route::post('/__bots__/{appName}/{appId}', 'Caligrafy\\Controllers\\WatsonController@connect');
Route::delete('/__bots__/{appName}', 'Caligrafy\\Controllers\\WatsonController@end');
```

Open `http://localhost:8080/bot/helpdesk?botSkillId=<assistant id>`. The chat says *Hi there!*; type a message and
press **Go**: the assistant's answer appears below it. Without `?botSkillId=`, or when the assistant cannot be reached
(wrong URL, key or plan), the chat says so under *Hi there!*.

### Step 4: The same assistant for pages, REST and agents

The chat app keeps a Watson session in the PHP session, which only a browser has. For one question at a time, from any
channel, write a capability:

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/AskHelpdesk --scope ai:use --read-only
```

Replace **`application/services/Bookshelf/AskHelpdesk.php`** with:

```php
<?php
/**
 * AskHelpdesk: one question to the watsonx Assistant of the bookshelf
 */

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Service;
use Caligrafy\ServiceError;
use Caligrafy\Watson;

#[Capability(
    name: 'ask_helpdesk',
    description: 'Asks the bookshelf help desk (a watsonx Assistant) one question. Returns {answer, replies}: the text, and every reply as Watson sent it.',
    scope: 'ai:use',
    readOnly: true
)]
class AskHelpdesk extends Service
{
    public $rules = array(
        'question' => 'required|max_len,2000',
    );

    public $filters = array(
        'question' => 'trim',
    );

    public $descriptions = array(
        'question' => 'The question for the help desk',
    );

    public function handle(array $input, Context $context)
    {
        if (!defined('WATSON_ASSISTANT_ID') || WATSON_ASSISTANT_ID === '') {
            throw ServiceError::conflict('The help desk is not set up: add WATSON_ASSISTANT_ID to .env');
        }

        try {
            $watson = new Watson(WATSON_ASSISTANT_ID);   // opens a session (WATSON_URL, WATSON_API_KEY)
        } catch (Exception $e) {
            throw ServiceError::conflict('Watson could not be reached: ' . $e->getMessage());
        }

        $replies = $watson->communicate($input['question'])->getResponse() ?? array();
        $watson->closeSession();

        $texts = array();
        foreach ($replies as $reply) {
            if (($reply['response_type'] ?? '') === 'text') {
                $texts[] = $reply['text'];
            }
        }

        return array('answer' => implode("\n", $texts), 'replies' => $replies);
    }
}
```

Each call opens a session, sends the question and closes the session, so the assistant does not remember earlier
questions here. Run:

```bash
docker compose exec dev-box php caligrafer.php call ask_helpdesk question="When are you open?"
```

Expected (the text is your assistant's):

```json
{
    "data": {
        "answer": "We are open from 9 to 6, Monday to Saturday.",
        "replies": [
            {
                "response_type": "text",
                "text": "We are open from 9 to 6, Monday to Saturday."
            }
        ]
    }
}
```

With `Route::capabilities('/capabilities')` and `Route::mcp('/mcp')` in `web.php`, it is also
`POST /capabilities/ask_helpdesk` and the agent tool `ask_helpdesk`. A page shows it with a form, as on the
[OpenAI page](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.4-OpenAI:-ChatGPT,-GPTs,-DALL.E):
`Route::form('/helpdesk', 'ask_helpdesk', ['success' => '/helpdesk', 'back' => '/helpdesk', 'flash' => '{answer}'])`.

**Check**
- `docker compose exec dev-box php caligrafer.php doctor --only watson` is OK.
- The chat at `/bot/helpdesk?botSkillId=<assistant id>` answers.
- `docker compose exec dev-box php caligrafer.php call ask_helpdesk question=Hi` answers `data`; with `WATSON_ASSISTANT_ID` empty it answers
  `conflict`, *The help desk is not set up: add WATSON_ASSISTANT_ID to .env*.

## Reference

### `Caligrafy\Watson`

| Method | What it does |
|---|---|
| `new Watson($watson_assistant_id, $environment_id = null)` | opens a session; `$environment_id` defaults to `WATSON_ENVIRONMENT_ID`. Throws without `WATSON_URL` (*Set WATSON_URL to your watsonx Assistant instance URL...*) or when no session opens (*The session could not be initialized*) |
| `communicate($messageText, $skillVariables = null)` | sends a message; `$skillVariables` (an array) are the context variables of the main skill. Returns the object |
| `getResponse()` | the replies of the last message (the `output.generic` list) |
| `getLastExchange()` | the last turn: `['turn_count', 'user', 'response']` |
| `getConversation()` | every turn, by turn number |
| `getExchangeAt($turnCount)` | one turn, or `[]` |
| `getContext()`, `getSkillVariables()`, `getContextVariable($variable)` | the context Watson returned, its user-defined variables, one of them |
| `getSessionId()` | the session id |
| `closeSession()` | deletes the session on Watson |

`getResponse()` and `getLastExchange()` take the last turn **out** of the log: call one of them once per message.

Requests go to `{WATSON_URL}/v2/assistants/{assistant_id}[/environments/{environment_id}]/sessions...?version={WATSON_API_VERSION}`
with the key as `apikey` basic authentication.

### `.env`

| Setting | Default |
|---|---|
| `WATSON_API_KEY` | none: required |
| `WATSON_URL` | none: required, the instance URL without `/v2` |
| `WATSON_ENVIRONMENT_ID` | none: sessions are created on the assistant itself |
| `WATSON_API_VERSION` | `2024-08-25` |
| `WATSON_ASSISTANT_ID` | none: read by `doctor` and by your own code (the capability above) |

### Replies

| `response_type` | What the chat app does |
|---|---|
| `text` | shows `text`, then waits for typed input |
| `option` | shows `title` and one button per option (`label`; the value sent is `value.input.text`) |
| `image` | shows the image (`source`, `title`) |
| `pause` | when the context has an `action` and the page defines `window.executeBotAction(context)`, shows the `text` it returns and sends its `variables` with the next answer |

### The chat app

`public/<name>/scripts/main.js` keeps the conversation (`messages`) and what the bot waits for (`action`: a `text`
input or `button` options) and calls the data routes with axios and `{ headers: apiHeaders() }`:

| Route | Body | Answer |
|---|---|---|
| `POST __bots__/<name>/<assistant id>` | `{}` | `true` once the session is open (kept in the PHP session) |
| `POST __bots__/<name>/communicate` | `{text, variables?}` | `{action_success: true, response: [replies], context: {variables}}` |
| `DELETE __bots__/<name>` | | closes the session |

Messages are always shown as text, never as HTML. To change the look, edit `public/<name>/index.php` and keep the ids
and Vue bindings; the page route can be any path that ends with the app name, and `?app=<file>` opens another
`public/<name>/<file>.php` (letters, digits, `-` and `_`).

## Under the hood

The chat app uses the example controller `Caligrafy\Controllers\WatsonController`
(`application/controllers/core/AI/WatsonController.php`): `connect()` creates `new Watson($appId)` and keeps it,
serialized, in the session; `communicate()` sends the text and the variables and answers the replies and the context;
`end()` closes the session. It is a controller because the conversation lives in the PHP session, which capabilities
never read. Everything else (one question from a page, REST or an agent) goes through a capability such as
`ask_helpdesk`.

## Common mistakes

+ **`WATSON_URL` with `/v2` at the end**, or the URL of the IBM Cloud dashboard instead of the instance URL.
+ **A Lite plan.** The v2 API needs Plus or higher: sessions are refused.
+ **No `?botSkillId=` in the page address.** The chat cannot connect.
+ **An old bot client that sends the API key.** Since 2.7.0 the client sends `apiHeaders()`; a bot that sends the key
  gets `[ERROR 1004] Access Denied` once `LEGACY_API_KEY=false` (Caligrafy Cloud). Copy `framework/plugins/bot/scripts/main.js` again.
+ **A bot folder name that is reserved**: `app`, `bot`, `__bots__`, `css`, `facedetect`, `fonts`, `images`, `js`,
  `ml`, `resources`, `uploads`.
