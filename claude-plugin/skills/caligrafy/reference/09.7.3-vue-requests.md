# 9.7.3 Requests

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A Vue app asks the server for data, and sends it what people type, through **requests**. In Caligrafy the app does not build these requests: `php caligrafer.php client` writes a JavaScript module with one function per capability (`listBooks()`, `createBook()`), and each function sends the request with the visitor's session and CSRF token, then returns the answer or throws a `CapabilityError`. This page is the reference of that client.

## With Claude

Ask for the screen and the data it needs: "the bookshelf app lists the books 20 at a time with Previous and Next". Claude uses the generated client (`/caligrafy-quill:new-app`, `/caligrafy-quill:new-capability`) and runs `php caligrafer.php client` again when a capability changes.

**Check** before you say OK:
+ Every call goes through a function of `capabilities.js`; no `axios`, `fetch` or `Authorization` header written by hand for capabilities.
+ A refused call is caught: `invalid` shows the field messages, any other error shows its message.
+ `public/js/capabilities.js` was generated again after the last capability change (its functions match `php caligrafer.php capabilities`).

## By hand: calling capabilities

You call the Bookshelf capabilities from the Bookshelf app of [Setting up Vue as a library](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.0-Setting-up-Vue.js-as-a-library), then from a Node script.

**1. Generate the client.** `web.php` needs `Route::capabilities('/capabilities');`. Run:
```bash
docker compose exec dev-box php caligrafer.php client public/js/capabilities.js
```
Expected: `public/js/capabilities.js written: <n> capabilities, calls /capabilities (Route::capabilities('/capabilities') in web.php)` and an example line `import { createBook, CapabilityError } from './capabilities.js'`.

**2. Load it in the app.** In `public/bookshelf/scripts/main.js`, `mounted()` loads it and points it at the application:
```js
this.api = await import(env.home + 'public/js/capabilities.js')
this.api.configure({ baseUrl: env.home.replace(/\/$/, '') })
```

**3. Call it.** Open `http://localhost:8080/bookshelf`, then type in the browser console:
```js
const api = await import(env.home + 'public/js/capabilities.js')
await api.listBooks({ page: 1 })
```
Expected: `{data: Array(n), total: n, page: 1, per_page: 20, pages: 1}`, the paged answer of `list_books`. Then:
```js
await api.getBook({ id: 3 })
```
Expected: `{id: 3, title: 'Kindred', published_year: 1979, ..., author: {id: 2, name: 'Octavia E. Butler', ...}}`.

**4. A refusal.** Type:
```js
try { await api.createBook({ title: 'Lilith' }) } catch (e) { console.log(e.name, e.status, e.code, e.fields) }
```
Expected: `CapabilityError 422 invalid {published_year: 'The Published Year field is required', author_id: 'The Author Id field is required'}`.

**5. From a Node script.** Programs use a personal access token instead of a session. Run:
```bash
docker compose exec dev-box php caligrafer.php token create "bookshelf script" --scopes books:read,books:write
```
It prints the token once (`cq_...`). Copy `public/js/capabilities.js` next to your script as `capabilities.mjs`, and write `books.mjs`:
```js
import { configure, listBooks, createBook, CapabilityError } from './capabilities.mjs'

configure({ baseUrl: 'http://localhost:8080', token: process.env.CALIGRAFY_TOKEN })
const page = await listBooks({ page: 1 })
console.log(page.total, page.pages)
try {
  await createBook({ title: 'Lilith' })
} catch (e) {
  console.log(e instanceof CapabilityError, e.status, e.code, JSON.stringify(e.fields))
}
```
Run `CALIGRAFY_TOKEN=cq_... node books.mjs` (Node.js 18 or later). Expected: the number of books and of pages (`5 1` with the sample data), then `true 422 invalid {"published_year":"The Published Year field is required","author_id":"The Author Id field is required"}`.

**Check**
+ In the browser's network panel, writes carry `X-CSRF-Token` and no `Authorization`; the first write is preceded by one `GET /capabilities`.
+ The Node script sends `Authorization: Bearer cq_...` and no cookie.

## Reference

### The generated module

`php caligrafer.php client [<file>] [--prefix /capabilities]` writes an ES module with no dependency (default file `public/js/capabilities.js`). Run it again after adding or changing a capability.

| Export | What it does |
| --- | --- |
| `listBooks(input = {})`, `createBook(input)`... | one function per capability: `create_book` becomes `createBook`. A JSDoc comment gives its description, whether it reads, writes or destroys, who may call it, and its inputs |
| `call(name, input = {})` | calls a capability by name: `call('create_book', {...})` |
| `capabilities()` | the capabilities this caller may use, with their input schema |
| `configure(options)` | `baseUrl` (default `''`: this origin), `token` (a personal access token), `prefix` (default the `--prefix`, `/capabilities`), `credentials` (default `'same-origin'`) |
| `CapabilityError` | thrown on a refusal: `status` (HTTP), `code`, `message`, `fields` (`{}` unless `invalid`) |

Each function sends `POST <baseUrl><prefix>/<name>` with the input as JSON and `Accept: application/json`, and returns what is inside `data`. With a `token` it sends `Authorization: Bearer <token>`; without one, writes send `X-CSRF-Token`, read once from `GET <baseUrl><prefix>` (the answer's `csrf`), and the browser sends the session cookie.

### Answers

| Capability returns | The function returns |
| --- | --- |
| a row (`Book::find()`, `->first()`) | an object: `{id, title, published_year, ...}` |
| a list (`->get()`) | an array of objects |
| a page (`->paginate(20)`) | `{data, total, page, per_page, pages}`; with `with('author')` each book has its `author` object |

### Refusals

| `code` | `status` | When |
| --- | --- | --- |
| `invalid` | 422 | an input breaks a rule of `$rules`: `fields` has one message per field |
| `unauthenticated` | 401 | the capability is not public and nobody is signed in (no token) |
| `forbidden` | 403 | the caller lacks the scope or level, or a write of a signed-in session came without `X-CSRF-Token` (a visitor's write to a `public` capability needs no token) |
| `not_found` | 404 | no capability with that name, or the capability answered `not_found` |
| `conflict` | 409 | the capability refused a duplicate or a state change |
| `error` | other | no JSON error in the answer (a server error) |

### Where the app runs

| App | Client | `baseUrl` |
| --- | --- | --- |
| Vue as a library | `public/js/capabilities.js`, loaded with `await import(env.home + 'public/js/capabilities.js')` | `env.home` without its last `/` |
| Vite single page app | `public/<app>/src/capabilities.js`, `import { listBooks } from '@/capabilities.js'` | `''` (same origin; in development the Vite proxy forwards `/capabilities`) |
| A Node script or another site | a copy of the module | the application's address, with a `token` |

## Other ways: `Route::action` and controller routes with `fetch` or axios

The generated client reaches capabilities. A JSON route of your own, a [`Route::action`](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#action) or a controller route in older code, is called with `fetch` or axios. What other experiences need belongs in a capability: the same rules then serve pages, REST and agents.

+ **The headers.** A JSON call from a page to its own `Route::action` (`GET` included, signed in or not, 2.21.1) or controller route sends `Accept: application/json` and the session's token in `X-CSRF-Token` (since 2.7.0): `apiHeaders()` of `public/js/services/app.js` returns both. The controller then sees the signed-in person or a visitor, as for a form post. Without them the route answers `401` and `{"error":{"code":1004,"message":"Access Denied: send the page's CSRF token in an X-CSRF-Token header (pages, with the session cookie) or Authorization: Bearer <personal access token> (programs and agents)"}}`.
  ```js
  const response = await fetch(env.home + 'api/shelf', { headers: apiHeaders() })
  const books = await response.json()
  ```
  For a JSON body with `fetch`, add the type: `apiHeaders({ 'Content-Type': 'application/json' })`. axios is not in the template: add `<script src="<?php echo scripts('axios'); ?>"></script>` (axios 1.21.1) before `app.js`, then `axios.get(env.home + 'api/shelf', { headers: apiHeaders() })`; axios sets `Content-Type` itself (JSON for an object, multipart for a `FormData`) and rejects an error status (`error.response.status`, `error.response.data`).
+ **Form requests.** A request without `Accept: application/json` is a form request: its `POST`, `PUT` and `DELETE` carry the CSRF token as the form field `_token` (`formData.append('_token', env.token)`), otherwise `403` (`[ERROR 3000]`). PHP does not read form data sent with a real `PUT`: send `POST` with `_method` set to `PUT` ([Forms](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms)).
+ **The legacy API key** (`'Bearer ' + apiKey`): readable by anyone who opens the page, and turned off on Caligrafy Cloud (`LEGACY_API_KEY=false`, then `env.apiKey` is `null`). Do not use it.

## Common mistakes

+ **`/capabilities` not found under a sub-folder** (`APP_ROOT` not empty): call `configure({ baseUrl: env.home.replace(/\/$/, '') })`.
+ **A new capability is missing from the client**: generate it again.
+ **`fetch` without `Accept: application/json`** to a `Route::action` or a controller route: it is a form request, and a write fails the CSRF check.
+ **An error shown as `[object Object]`**: show `e.message`, or `e.fields` for `invalid`.
