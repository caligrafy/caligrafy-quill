# 9.7.3 Requests

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

Integrating frameworks requires a clear definition on the responsibilities of each. One of these responsibilities that could be of concern is **Requests**. Requests is about handling the request that comes from the browser and dispatching it to the intended modules or pages.

> Learn more about Requests [here](https://github.com/caligrafy/caligrafy-quill/wiki/3.-Request)

## Requests are handled on the client-side
Requests are handled on the client-side, basically that is exactly what the purpose of a browser is. It is meant to render a user interface for the end-users and turn their commands into requests that the server would understand.

Since `Vue` is the one responsible for creating the user interface, then `Vue` needs to handle the requests.

### How does `Vue` handle HTTP Requests
`Vue` is written in Javascript so there are multiple ways and multiple services to handle HTTP requests in Javascript. `Vue` recommends using `Axios` for handling HTTP Requests.

In Caligrafy, there are 4 HTTP requests currently supported 'GET', 'POST', 'PUT' and 'DELETE'. 
A request that sends the `Accept: application/json` header is an API call: when its route points to a controller, it needs the API key as `Authorization: Bearer <apiKey>`, otherwise Caligrafy answers HTTP `401` with `{"error": {"code": 1004, "message": "Access Denied"}}`. API calls skip the CSRF check. A request without that header is a form request: its `POST`, `PUT` and `DELETE` must carry the CSRF token `_token` as form data (see [Forms](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms)), otherwise Caligrafy answers `403` (`[ERROR 3000]`). axios rejects these responses, so handle them in `.catch()` (`error.response.status`, `error.response.data.error`).

Here is the basic structure of `axios` requests in the `Vue` app:
```javascript
const app = Vue.createApp({
  data () {
    return {
        response: null,
        error: null,
        env: env,
        // headers for the Caligrafy API: apiKey is a global variable set by loadEnvironment()
        config: {
            headers: {
                'Accept': 'application/json',
                'Authorization': 'Bearer ' + apiKey
            }
        }
    }
  },
  /* Method Definition  */
  methods: {

      // example of axios get method
      get: function() {
          axios.get(this.env.home + 'the/route/', this.config)
              .then(response => (this.response = response))
              .catch(error => (this.error = error));
      },

      // example of axios post request
      post: function() {
          axios.post(this.env.home + 'the/route/', <data in JSON or form data>, this.config)
              .then(response => (this.response = response))
              .catch(error => (this.error = error));
      },

      // example of axios put request
      put: function() {
          axios.put(this.env.home + 'the/route/', <data in JSON>, this.config)
              .then(response => (this.response = response))
              .catch(error => (this.error = error));
      },

      // example of axios delete request (delete is a reserved word: the method cannot be called delete)
      remove: function() {
          axios.delete(this.env.home + 'the/route/', this.config)
              .then(response => (this.response = response))
              .catch(error => (this.error = error));
      }

      //...

```

### Javascript methods for data delivery
At this stage, it is good to know that Javascript comes packaged with methods that can help format the data appropriately for the requests.

#### Sending Data in data form
Sending data in data form is taking the completed HTML form as submitted by the user and handing it off to the server. Javascript provides a mechanism to get the input from the user and turn it into a ready-to-use data form.

```javascript
    var form = document.getElementById('<id of html form>');
    var formData = new FormData(form);

    // you can append more values to send to the server if needed
    formData.append(<key>, <value>);

    // files uploaded need to be appended separately
    let files = document.getElementById('image_url'); 
    formData.append(<image field name>, files.files[0]);

    // the formData can now be sent as is to axios
    axios.post(this.env.home + 'the/route/', formData, this.config)
    //...
```

#### Sending Data in JSON
In some cases, you might need to send data to the server in a JSON format. A very common example of this is a `PUT` request: PHP does not read form data sent with a real `PUT`. You have two options: send the form data with `axios.post` and a `_method` of `PUT` ([method spoofing](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms)), which keeps the uploaded files, or send a real `PUT` with a JSON body, which Caligrafy reads from the request body. Javascript can turn form data into an object that axios sends as JSON (files are lost this way):
```javascript

   // after building the formData similarly to before
   var data = Object.fromEntries(formData)

   axios.put(this.env.home + 'the/route', data, this.config)
   //...

```
