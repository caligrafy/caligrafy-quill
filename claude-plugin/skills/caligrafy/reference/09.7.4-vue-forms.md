# 9.7.4 Forms

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.4-Forms
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A **form** in a Vue app collects what a person types and hands it to a capability. Vue keeps the fields in `data` (`v-model`), stops the browser from sending the form itself (`@submit.prevent`), and the generated client sends the values: no hidden `_token` field, no method spoofing, no request to build. The capability's rules answer, and the form shows each refusal under its field.

## With Claude

Ask for the form with the capability it calls: "in the bookshelf app, a form to add a book that shows each error under its field and a message when the book is added". Claude writes it in `public/<app>/index.php` and `scripts/main.js` with the page components (`.cq-form-grid`, `.cq-field`, `.cq-field-error`, `.cq-alert`).

**Check** before you say OK:
+ The `form` has `method="POST"` and `@submit.prevent`; the button is `type="submit"`.
+ Sending it empty shows one message under each required field; what was typed stays.
+ Sending it filled shows the success message once, and the fields are emptied.
+ The submit button cannot be pressed twice while the call runs.

## By hand

You finish the add form of the Bookshelf app of [Setting up Vue as a library](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.0-Setting-up-Vue.js-as-a-library): trimmed values, a length limit, a busy button and a success message.

**1. The form.** In `public/bookshelf/index.php`, replace the `cq-alert` line and the `form` with:
```html
                    <p class="cq-alert cq-alert--error" role="alert" v-if="error">{{ error }}</p>
                    <p class="cq-alert" role="status" v-if="message">{{ message }}</p>
                    <form method="POST" novalidate @submit.prevent="addBook">
                        <div class="cq-form-grid cq-form-grid--2">
                            <div class="cq-field">
                                <label for="title">Title</label>
                                <input id="title" class="form-control" type="text" maxlength="200" v-model.trim="book.title">
                                <p class="cq-field-error" v-if="errors.title">{{ errors.title }}</p>
                            </div>
                            <div class="cq-field">
                                <label for="author_id">Author</label>
                                <select id="author_id" class="form-select" v-model.number="book.author_id">
                                    <option v-for="author in authors" :key="author.id" :value="author.id">{{ author.name }}</option>
                                </select>
                                <p class="cq-field-error" v-if="errors.author_id">{{ errors.author_id }}</p>
                            </div>
                            <div class="cq-field">
                                <label for="published_year">Year</label>
                                <input id="published_year" class="form-control" type="number" v-model.number="book.published_year">
                                <p class="cq-field-error" v-if="errors.published_year">{{ errors.published_year }}</p>
                            </div>
                            <div class="cq-field">
                                <label for="summary">Summary</label>
                                <input id="summary" class="form-control" type="text" maxlength="2000" v-model.trim="book.summary">
                            </div>
                        </div>
                        <button class="btn btn-primary" type="submit" :disabled="sending">{{ sending ? 'Adding...' : 'Add book' }}</button>
                    </form>
```
+ `method="POST"`: if the script does not run, the browser never puts the fields in the address.
+ `novalidate`: the server's rules give the messages, the same as on the Pug page and over REST.
+ `@submit.prevent`: Vue calls `addBook` instead of the browser sending the form.
+ `v-model.trim`: the field's value, without spaces around it, in `book.title`; `v-model.number`: the year and the author's id as numbers, as the `integer` rules expect.
+ The Author list comes from `list_authors` (`this.authors`), each option's value an author's id.

**2. The script.** Replace `public/bookshelf/scripts/main.js` with:
```js
// Bookshelf: the books of the catalog, through the generated JS client (public/js/capabilities.js)
const app = Vue.createApp({
    data () {
        return {
            env: env,
            books: [], total: 0, page: 1, pages: 1,
            authors: [],
            book: { title: '', author_id: null, published_year: null, summary: '' },
            errors: {},
            error: '',
            message: '',
            sending: false
        }
    },
    async mounted () {
        this.api = await import(env.home + 'public/js/capabilities.js')
        this.api.configure({ baseUrl: env.home.replace(/\/$/, '') })   // the application root, whatever APP_ROOT is
        this.authors = await this.api.listAuthors()
        await this.load(1)
    },
    methods: {
        async load (page) {
            const result = await this.api.listBooks({ page: page })   // { data, total, page, per_page, pages }
            this.books = result.data
            this.total = result.total
            this.page = result.page
            this.pages = result.pages
        },
        async addBook () {
            this.errors = {}
            this.error = ''
            this.message = ''
            this.sending = true
            try {
                const created = await this.api.createBook(this.book)
                this.message = 'Book added: ' + created.title
                this.book = { title: '', author_id: null, published_year: null, summary: '' }
                await this.load(1)
            } catch (e) {
                if (e.name === 'CapabilityError' && e.code === 'invalid') this.errors = e.fields
                else this.error = e.message
            } finally {
                this.sending = false
            }
        }
    }
})

app.mount('#app')
```

**3. Try it.** Reload `http://localhost:8080/bookshelf`:
+ Press **Add book** with every field empty: `The Title field is required`, `The Author Id field is required` and `The Published Year field is required`, each under its field.
+ Type `  Imago  ` as the title, choose Octavia E. Butler, type `1989`, press **Add book**: `Book added: Imago` (without the spaces) above the form, the book in the list, the fields empty.

**Check**
+ The address bar never gets a `?` after sending.
+ The network panel shows one `POST /capabilities/create_book` per press, with a JSON body.

## Reference

| Part | Use |
| --- | --- |
| `form(method="POST" novalidate @submit.prevent="method")` | Vue handles the submit; the browser never sends it as a `GET` |
| `v-model`, `v-model.trim`, `v-model.number` | the value in `data`, trimmed, or as a number (for an `integer` rule) |
| `:disabled="sending"` | one call at a time |
| `e.fields` of a `CapabilityError` with `code === 'invalid'` | one message per field, keyed by the input's name |
| `.cq-form-grid`, `.cq-form-grid--2`, `.cq-field`, `p.cq-field-error`, `.cq-alert`, `.cq-alert--error` | the page components of a form ([Views](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#pagecomponents)) |

**Files.** The generated client sends JSON, so it cannot send a file. A capability with a `file` rule (`'cover' => 'required|file|extension,png;jpg|max_size,2mb'`) receives its file from a web form or REST: post a `FormData` to its [`Route::form`](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#form) address with `fetch(env.home + 'books', { method: 'POST', headers: apiHeaders(), body: formData })`. With `Accept: application/json` (in `apiHeaders()`), `Route::form` answers JSON instead of redirecting: `{"data": ...}` with `201`, or `{"error": {"code": "invalid", "fields": {...}}}` with `422`. See [file inputs](https://github.com/caligrafy/caligrafy-quill/wiki/Declarative-Routes#files).

Vue's own guides: [form bindings](https://vuejs.org/guide/essentials/forms.html), [event handling](https://vuejs.org/guide/essentials/event-handling.html), [conditional rendering](https://vuejs.org/guide/essentials/conditional.html), [list rendering](https://vuejs.org/guide/essentials/list.html).

## Other ways: form posts with `_token` and `_method`

A form request (without `Accept: application/json`) to a `Route::form`, a `Route::action` or a controller route must carry the session's CSRF token as the form field `_token`, or Caligrafy answers `403` (`[ERROR 3000]`). HTML forms only send `GET` and `POST`: a `_method` field turns a `POST` into a `PUT` or a `DELETE`.
```js
const formData = new FormData()
formData.append('title', 'Survivor')
formData.append('author_id', '2')
formData.append('published_year', '1978')
formData.append('_token', env.token)
const response = await fetch(env.home + 'books', { method: 'POST', body: formData })
// the Route::form of Views: redirected to /books/<id> (response.url); without _token: 403
```
For a route declared with `PUT` or `DELETE` (`Route::form('/books/{id}', 'update_book', ['method' => 'PUT'])`), add `formData.append('_method', 'PUT')` and keep `method: 'POST'`.
A Pug page writes the same fields with `= csrf()` and `= methodField('PUT')` ([Views: forms](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#formhelpers)). The generated client replaces this for capabilities; the token is read from form data only, never from a JSON body.

## Common mistakes

+ **No `method` on the form**: when the script fails to load, the browser sends the fields in the address (`GET /bookshelf?title=...`).
+ **Clearing the fields before the call answers**: a refused book would be lost. Clear them after success.
+ **`e.fields` shown for every error**: only `invalid` has fields; show `e.message` otherwise.
+ **A file field sent through `createBook()`**: JSON carries no file. Post a `FormData` to the `Route::form` address.
