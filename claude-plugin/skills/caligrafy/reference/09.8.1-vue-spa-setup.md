# 9.8.1 Setting up the Vue application

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.8.1---Setting-up-the-Vue-application
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A **single page app** (SPA) is a Vue app with its own routes between screens, `.vue` component files and a shared store, built with [Vite](https://vite.dev) into plain files. Caligrafy's template (`php caligrafer.php create`) gives you Vite 8, Vue 3.5, Vue Router 5 and Pinia, with Caligrafy's look already imported. The app lives in `public/<app>/`, calls your capabilities through the generated JS client, runs on Vite's development server while you work, and is served from `public/<app>/dist/` once built.

## With Claude

```text
/caligrafy-quill:new-app create shelfapp
```
Then describe the screens: "the list of the books with an add form, and a page for one book". Claude scaffolds the app, generates the client into `public/shelfapp/src/capabilities.js`, adds the `/capabilities` development proxy to `vite.config.js` and the books screens to the router, and writes the components with the page components. The template already has `base: './'`, hash addresses and no API key (2.19.1). It runs `npm install` on your computer, never in the Docker server (which has no Node.js).

**Check** before you say OK:
+ `npm run dev` opens the app and the books load; `npm run build` ends with `✓ built`.
+ `public/shelfapp/dist/index.html` opens from the Caligrafy server, and a reload of `#/books/1` shows the same book.
+ `src/main.js` has no `VITE_API_KEY` and no `Authorization` header: the built files contain no key.

## By hand

You create the Bookshelf single page app, `shelfapp`, run it in development, and build it. You need the Bookshelf tables and capabilities of [Views, steps 1 to 3](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#viewsstartup) and `Route::capabilities('/capabilities');` in `web.php`.

**1. Node.js.** On your computer, run `node --version`. It must be 20.19 or later in the 20 line, or 22.12 or later ([download](https://nodejs.org/en/download)). The Docker `dev-box` has no Node.js: run every `npm` command on your computer, in the project folder.

**2. Create the app.** Run, on your computer, from the project folder (this one command needs PHP 8.3+ on the computer, because `create` runs `npm install` where it runs):
```bash
php caligrafer.php create shelfapp
```
Expected, after npm's own lines:
```text
 VueJS project created and its packages installed.

 - To run the development server: cd public/shelfapp && npm run dev
 - To build it for production: npm run build (in the same folder)
```
With the Docker server instead (`docker compose exec dev-box php caligrafer.php create shelfapp`), it prints `VueJS project created, but its packages are NOT installed: npm is not available here (the Docker dev-box has no Node.js)`: then run `cd public/shelfapp && npm install` on your computer.

**3. The JS client.** Run:
```bash
docker compose exec dev-box php caligrafer.php client public/shelfapp/src/capabilities.js
```
Expected: `public/shelfapp/src/capabilities.js written: <n> capabilities, calls /capabilities ...`. Run it again after every change to a capability.

**4. The development proxy.** The template (2.19.1) already builds for any folder (`base: './'`), uses hash addresses (`createWebHashHistory()` in `src/router/index.js`), keeps no API key and commits `dist/`: nothing to change for those. What it does not have is a proxy for `npm run dev`: Vite's server runs on its own port (5173), so a call to `/capabilities` there answers `404` unless Vite forwards it to Caligrafy. Calling `http://localhost:8080` directly from port 5173 instead (`VITE_API_ROUTE`) is a call to another origin: the browser does not send the session cookie with the generated client's default (`credentials: 'same-origin'`). Replace `public/shelfapp/vite.config.js` with:
```js
import { fileURLToPath, URL } from 'node:url'

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'

// https://vite.dev/config/
export default defineConfig({
  // the built app works from any folder: public/shelfapp/dist/
  base: './',
  plugins: [
    vue(),
    vueDevTools(),
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    },
  },
  // npm run dev: the capability calls go to the Caligrafy server, with its session cookie
  server: {
    proxy: { '/capabilities': 'http://localhost:8080' }
  }
})
```
Use the address of your Caligrafy server in `proxy` (`http://localhost:8080` with Docker). The page and the proxied calls are then on one origin (`localhost:5173`), and the browser keeps one cookie per host whatever the port, so the session of `localhost:8080` goes with them.

The router of the template, `public/shelfapp/src/router/index.js`, uses hash addresses (`#/books/3`) since 2.19.1: they work with `npm run dev` and in `dist/` from any folder, and survive a reload. Apps created before 2.19.1 use `createWebHistory()`: change it as [Routing for single page apps](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.2-Routing-for-Single-Page-Applications) shows, which also adds the books screens.

**5. Run it in development.** Start the Caligrafy server, then run:
```bash
cd public/shelfapp
npm run dev
```
Expected: `VITE v8.x.x  ready in ... ms` and `➜  Local:   http://localhost:5173/`. Open that address: the template's home, *Welcome to Caligrafy*, in Caligrafy's look. Every file you save shows at once. In the browser console, `(await import('/src/capabilities.js')).listBooks()` answers the books through the proxy.

**6. Build it.** Stop the development server (Ctrl+C) and run:
```bash
npm run build
```
Expected: three lines for `dist/index.html`, `dist/assets/index-<hash>.css` and `dist/assets/index-<hash>.js`, each with its size, then `✓ built in ...ms`. Open `http://localhost:8080/public/shelfapp/dist/index.html`: the same app, served by Caligrafy, calling `/capabilities` on the same server.

**Check**
+ `grep -rc VITE_API_KEY src` prints `0` for every file, and the files of `dist/assets/` contain no API key.
+ `http://localhost:8080/public/shelfapp/dist/index.html#/` reloads without an error.
+ `npm run lint` ends without errors (it fixes the formatting it can).

## Calling the capabilities of the application

A single page app is one more experience of your [capabilities](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#service): import the functions you need from the generated client.
```js
import { listBooks, createBook, CapabilityError } from '@/capabilities.js'

const page = await listBooks({ page: 1 })      // { data, total, page, per_page, pages }
try {
  await createBook({ title: 'Dawn', author_id: 2, published_year: 1987 })
} catch (e) {
  if (e instanceof CapabilityError && e.code === 'invalid') errors.value = e.fields
}
```
+ The client uses the visitor's session (cookie and CSRF token): nothing secret is built into the app.
+ In development the app runs on Vite's port and the proxy of step 4 forwards `/capabilities` to Caligrafy; the browser keeps one cookie for `localhost` whatever the port, so a person signed in on the Caligrafy server is signed in in the app.
+ Built, `dist/` is served by Caligrafy itself: the calls go to the same server. When the application is in a sub-folder (`APP_ROOT` not empty), call `configure({ baseUrl: '/<APP_ROOT>' })` once in `src/main.js`.
+ The [Requests reference](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.3-Requests#capabilities) lists every function, option and error.

## Reference

### The template (`framework/librairies/app`)

| File | What it is |
| --- | --- |
| `package.json` | scripts `dev` and `serve` (Vite's server), `host` (the same, open to your network), `build`, `preview` (serves `dist/`), `lint` (ESLint 10 with `--fix`); dependencies Vue 3.5, Vue Router 5, Pinia, axios 1.20; Node `^20.19.0 \|\| >=22.12.0`; `overrides` keeps `minimatch` 11 |
| `vite.config.js` | Vite 8, `base: './'` (2.19.1: `dist/` works from any folder), the Vue plugin, Vue devtools, the alias `@` = `src/`; no proxy (step 4 adds it) |
| `index.html` | the page: Bootstrap 5.3.8 from jsDelivr, `<div id="app">`, `src/main.js` |
| `src/main.js` | the app, Pinia, the router, Caligrafy's stylesheets from `public/css/`; `this.http` (axios), `this.config`, `this.apiConfig` and `this.apiHeaders` from `src/common/app.js` for every component |
| `src/App.vue` | the frame: the top bar, `<router-view>`, the footer |
| `src/router/index.js` | the routes, with `createWebHashHistory()` (2.19.1) |
| `src/common/store.js` | an example Pinia store ([State management](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.4-State-Management)) |
| `src/common/app.js` | axios settings for calls the generated client does not make (controller routes), 2.19.1: `config` (`apiRoute` = `VITE_API_ROUTE` or `''`, `capabilities` = `VITE_CAPABILITIES_ROUTE` or `/capabilities`), `csrfToken()` (reads `csrf` from `GET /capabilities` once), `apiHeaders(extra)` (`Accept: application/json` and `X-CSRF-Token`), `apiConfig` (JSON, `withCredentials: true`). No API key |
| `src/components/pages/`, `src/components/global/` | page components (`HomePage.vue`) and shared ones (`ShowNavigation.vue`, `ShowMessage.vue`, `ShowGeneralCard.vue`) |
| `.env` | `VITE_APP_KEY` and `VITE_API_KEY`, written by `php caligrafer.php initialize` into the template and copied by `create`; the template no longer reads `VITE_API_KEY` (2.19.1). Never committed (the project's `.gitignore` has `.env`) |
| `.gitignore` | `node_modules`, `dist-ssr`, logs and editor files; `dist/` is not ignored (2.19.1): it is committed |

`create <name>` copies the template to `public/<name>/`, then runs `npm install` when `npm` is found. The name must not be a folder Caligrafy uses in `public/` (`app`, `bot`, `__bots__`, `css`, `facedetect`, `fonts`, `images`, `js`, `ml`, `resources`, `uploads`), and `public/<name>/` must not exist yet.

### Online

The production image of Caligrafy does not run `npm`: commit the built app.
1. Run `npm run build` in `public/shelfapp/`.
2. Commit `public/shelfapp/dist/` with the rest of the project (`node_modules/` stays out). The template's `.gitignore` does not ignore `dist/` since 2.19.1; in an app created before, delete the line `dist` from `public/shelfapp/.gitignore` first.
3. The app is at `https://<your site>/public/shelfapp/dist/index.html`, with hash addresses.

Build again and commit `dist/` after every change. A design style is imported in `src/main.js` (`import '../../css/designs/<name>.css'`) and needs a new build too.

## Other ways

+ **An address of its own** (`https://books.example.com/`): point a virtual host at `public/shelfapp/dist/`, keep `base: './'`, and set `configure({ baseUrl: 'https://<the Caligrafy address>' })` with a token, since the session cookie does not go to another site. With `createWebHistory()` instead of hash addresses, the virtual host needs a fallback to `index.html` (`FallbackResource /index.html`), or a reload of `/books/3` answers `404`.
+ **axios for a controller route** (one that answers with `api()`, not a capability): `this.http.post(this.config.apiRoute.replace(/\/+$/, '') + '/books/import', body, { headers: await this.apiHeaders(), withCredentials: true })` (an absolute path: the built app lives in `public/shelfapp/dist/`, so a relative `'books/import'` would point inside it), and add `'/books'` to the `proxy` of step 4 for `npm run dev`. The template sends the session and `X-CSRF-Token`, never an API key (2.19.1). Apps created before 2.19.1 have `'Bearer ' + VITE_API_KEY` in `src/main.js` and `src/common/app.js`: the key is readable by anyone in the built files and Caligrafy Cloud turns it off (`LEGACY_API_KEY=false`); replace both files with the template's.

## Common mistakes

+ **`npm install` reports 10 moderate vulnerabilities** (apps created with 2.2.0 or older): they come from `minimatch` below 11.0.1, used by ESLint only. Never run `npm audit fix --force` (it installs ESLint 4). Add `"overrides": { "minimatch": "^11.0.1" }` to `package.json`, then `rm -rf node_modules package-lock.json && npm install`.
+ **A blank page from `dist/`** (apps created before 2.19.1): the router uses `createWebHistory()`, or `base` is not `'./'` in `vite.config.js`. Use `createWebHashHistory()` and `base: './'`, as the template does now, and build again.
+ **`/capabilities` answers 404 in development**: the proxy of step 4 is missing or points to the wrong port.
+ **Changes not online**: `dist/` was not built again, or not committed.
