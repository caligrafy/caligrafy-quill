# 9.8.4 State Management

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.8.4-State-Management
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

Vue provides powerful patterns that help modularize the user interface. Vue `Components` are key building blocks that help achieve that modularity. However, components are self-contained in a sense that each has properties and structures of its own. We saw ways to pass data and trigger events across components but what if data needs to be shared across different components and what if data can be changed by different components? How can we make sure that the data is up to date and synchronized all the time?

State Management is the technique that makes sure that the data that need to be shared by different components is the same by creating a centralized single source of truth. Caligrafy uses **Pinia**, the official state management library of Vue (it replaces Vuex, which is in maintenance mode).

>
> Learn more about Pinia in the official [Pinia Documentation](https://pinia.vuejs.org/)
>

## The `Store`

A store is the single source of truth where shared data and the actions that change it are defined. Components read and change the shared data through the store, and every component that uses it is updated automatically.

In the Caligrafy Vue App, Pinia is installed in `src/main.js` (`app.use(createPinia())`) and an example store comes out of the box in `src/common/store.js`.

## Store Structure

A store is defined with `defineStore()` and has 3 properties: `state`, `getters` and `actions`.

```js
import { defineStore } from 'pinia'

export const useAppStore = defineStore('app', {
    // shared data
    state: () => ({
        count: 0
    }),

    // computed values derived from the state
    getters: {
        isEven: (state) => state.count % 2 === 0
    },

    // methods that change the state, synchronous or asynchronous (API calls)
    actions: {
        increment(value = 1) {
            this.count += value;
        }
    }
});
```

You can create as many stores as you need (one per domain: user, cart, books...), each with its own id.

## Using a store in a component

Call the store function (`useAppStore()`) inside the component. With the Options API used by the Caligrafy components:

```js
<script>
import { useAppStore } from '@/common/store'

export default {
    name: 'home',
    data() {
        return {
            store: useAppStore()
        }
    },
    methods: {
        add() {
            this.store.increment(1);
        }
    }
};
</script>

<template>
    <p>Count: {{ store.count }} ({{ store.isEven ? 'even' : 'odd' }})</p>
    <button @click="add">+1</button>
</template>
```

With the Composition API (`<script setup>`), the store is used the same way: `const store = useAppStore()`.

## Core Properties

### `State`
The state is the latest version of the shared data. It is a function that returns the initial data.
```js
store.count
```
The state can be changed directly (`store.count++`), through an action, or several properties at once with `store.$patch({ count: 10 })`. `store.$reset()` restores the initial state.

> [Read more about State](https://pinia.vuejs.org/core-concepts/state.html)

### `Getters`
Getters are computed values derived from the state. They are read like properties and are cached until the state they use changes.
```js
store.isEven // true or false
```
A getter can return a function to accept arguments:
```js
getters: {
    isMultipleOf: (state) => (n) => state.count % n === 0
}

store.isMultipleOf(3) // true or false
```

> [Read more about Getters](https://pinia.vuejs.org/core-concepts/getters.html)

### `Actions`
Actions are methods that change the state. They can be asynchronous, which makes them the right place for API calls to the Caligrafy data routes:
```js
// src/common/store.js: add books: [] to the state
import { callApi, config, apiConfig } from '@/common/app'

actions: {
    async loadBooks() {
        const response = await callApi.get(config.apiRoute + 'books', apiConfig);
        this.books = response.data;
    }
}

await store.loadBooks();
```

> [Read more about Actions](https://pinia.vuejs.org/core-concepts/actions.html)

## Migrating from Vuex

| Vuex | Pinia |
| - | - |
| `createStore({ state, mutations, actions, getters })` | `defineStore('id', { state: () => ({...}), getters, actions })` |
| `app.use(store)` | `app.use(createPinia())` |
| `this.$store.state.count` | `store.count` (with `const store = useAppStore()`) |
| `this.$store.commit('increment', 1)` (mutation) | `store.increment(1)` (action) or `store.count++`: there are no mutations |
| `this.$store.dispatch('increment', 1)` | `store.increment(1)` |
| `this.$store.getters.isEven` | `store.isEven` |
