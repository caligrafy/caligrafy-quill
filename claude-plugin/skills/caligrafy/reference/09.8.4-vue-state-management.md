# 9.8.4 State Management

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.8.4-State-Management
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

**State management** keeps the data that several components share in one place, a **store**, so every component shows the same thing and changes it the same way. Caligrafy's single page app template uses [Pinia](https://pinia.vuejs.org/), the official store of Vue (it replaces Vuex): `src/main.js` installs it (`app.use(createPinia())`) and `src/common/store.js` holds an example. In a Caligrafy app, the store's actions call the capabilities, so the store also holds what the server answered: the books, their count, the field errors.

## With Claude

Ask for what is shared: "in shelfapp, keep the books, the authors and the form errors in a Pinia store; the top bar shows how many books there are". Claude writes the store in `public/shelfapp/src/common/store.js`, with actions that call the generated client, and changes the components to read it.

**Check** before you say OK:
+ Only the store's actions call the capabilities; the components call the actions.
+ After adding a book, the count in the top bar and in the list change together, without a reload.
+ `npm run build` ends with `✓ built`.

## By hand

You move the data of the Bookshelf app of [Single file components](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.3-Single-File-Components) into a store, and show the count of books in the top bar. Files are in `public/shelfapp/`.

**1. The store.** Replace `src/common/store.js` with:
```js
import { defineStore } from 'pinia'
import { listBooks, listAuthors, createBook, CapabilityError } from '@/capabilities.js'

export const useBooksStore = defineStore('books', {
    // shared data
    state: () => ({
        books: [],
        total: 0,
        page: 1,
        pages: 1,
        authors: [],
        errors: {},
        error: ''
    }),

    // values computed from the state
    getters: {
        isEmpty: (state) => state.total === 0
    },

    // what changes the state: here, through the capabilities
    actions: {
        async load(page = 1) {
            try {
                if (!this.authors.length) this.authors = await listAuthors()
                const result = await listBooks({ page })   // { data, total, page, per_page, pages }
                this.books = result.data
                this.total = result.total
                this.page = result.page
                this.pages = result.pages
            } catch (e) {
                this.error = e.message
            }
        },
        async add(book) {
            this.errors = {}
            this.error = ''
            try {
                const created = await createBook(book)
                await this.load(1)
                return created
            } catch (e) {
                if (e instanceof CapabilityError && e.code === 'invalid') this.errors = e.fields
                else this.error = e.message
                return null
            }
        }
    }
})
```

**2. The top bar loads it.** The top bar is on every screen, so it loads the books once for the whole app. Replace `src/components/global/ShowNavigation.vue` with:
```vue
<template>
	<nav class='cq-nav' aria-label='Main'>
		<router-link class='cq-nav-brand' :to='{ name: "books" }'>
			<img class='cq-nav-mark' :src='mark' alt='' width='28' height='28'>
			<span class='semibold'>Book</span><span>shelf</span>
		</router-link>
		<div class='cq-nav-links'>
			<router-link class='cq-nav-link' :to='{ name: "books" }'>{{ store.total }} books</router-link>
		</div>
	</nav>
</template>

<script>
import mark from '../../assets/caligrafy-mark.svg'
import { useBooksStore } from '@/common/store'

export default {
	name: 'show-navigation',
	data() {
		return { mark, store: useBooksStore() }
	},
	mounted() {
		// the top bar is on every screen: it loads the books once for the whole app
		this.store.load(1)
	}
}
</script>
```

**3. The form uses it.** Replace `src/components/global/BookForm.vue` with:
```vue
<template>
	<form method='POST' novalidate @submit.prevent='submit'>
		<div class='cq-form-grid cq-form-grid--2'>
			<div class='cq-field'>
				<label for='title'>Title</label>
				<input id='title' class='form-control' type='text' maxlength='200' v-model.trim='book.title'>
				<p class='cq-field-error' v-if='store.errors.title'>{{ store.errors.title }}</p>
			</div>
			<div class='cq-field'>
				<label for='author_id'>Author</label>
				<select id='author_id' class='form-select' v-model.number='book.author_id'>
					<option v-for='author in store.authors' :key='author.id' :value='author.id'>{{ author.name }}</option>
				</select>
				<p class='cq-field-error' v-if='store.errors.author_id'>{{ store.errors.author_id }}</p>
			</div>
			<div class='cq-field'>
				<label for='published_year'>Year</label>
				<input id='published_year' class='form-control' type='number' v-model.number='book.published_year'>
				<p class='cq-field-error' v-if='store.errors.published_year'>{{ store.errors.published_year }}</p>
			</div>
			<div class='cq-field'>
				<label for='summary'>Summary</label>
				<input id='summary' class='form-control' type='text' maxlength='2000' v-model.trim='book.summary'>
			</div>
		</div>
		<button class='btn btn-primary' type='submit'>Add book</button>
	</form>
</template>

<script>
import { useBooksStore } from '@/common/store'

export default {
	name: 'book-form',
	emits: ['added'],
	data() {
		return {
			store: useBooksStore(),
			book: { title: '', author_id: null, published_year: null, summary: '' }
		}
	},
	methods: {
		async submit() {
			const created = await this.store.add(this.book)
			if (created) {
				this.book = { title: '', author_id: null, published_year: null, summary: '' }
				this.$emit('added', created)
			}
		}
	}
}
</script>
```
The form calls the store's `add` action, reads the errors from the store, and tells the page when a book was added.

**4. The list uses it.** Replace `src/components/pages/BooksPage.vue` with:
```vue
<template>
	<main>
		<section class='cq-hero cq-hero--page'>
			<h1 class='cq-display'>Books</h1>
			<p class='cq-lead'>{{ store.total }} books on the shelf.</p>
		</section>
		<section class='cq-band cq-band--tight'>
			<div class='cq-inner cq-inner--narrow'>
				<p class='cq-alert cq-alert--error' role='alert' v-if='store.error'>{{ store.error }}</p>
				<book-form @added='open'></book-form>
				<ul class='cq-rows' v-if='!store.isEmpty'>
					<li class='cq-row' v-for='book in store.books' :key='book.id'>
						<div class='cq-row-main'>
							<p class='cq-row-title'>
								<router-link :to='{ name: "book", params: { id: book.id } }'>{{ book.title }}</router-link>
							</p>
							<p class='cq-row-meta'>{{ book.author.name }}, {{ book.published_year }}</p>
						</div>
					</li>
				</ul>
				<p class='cq-empty-state' v-else>No books yet: add the first one above.</p>
			</div>
		</section>
	</main>
</template>

<script>
import { useBooksStore } from '@/common/store'
import BookForm from '../global/BookForm.vue'

export default {
	name: 'books-page',
	components: {
		'book-form': BookForm
	},
	data() {
		return {
			store: useBooksStore()
		}
	},
	methods: {
		open(book) {
			this.$router.push({ name: 'book', params: { id: book.id } })
		}
	}
}
</script>
```
The page no longer loads anything: the top bar did, and the list reads the store.

**5. Try it.** Run `npm run build`, then open `http://localhost:8080/public/shelfapp/dist/index.html#/books/3`:
+ The top bar says `5 books` on the page of *Kindred*: the store was loaded by the top bar.
+ Click `5 books`: the list shows the same books and the Author list its three authors, with no new call to `list_books` (the network panel shows none).
+ Type `Bloodchild`, choose Octavia E. Butler, no year, press **Add book**: `The Published Year field is required` under the year.
+ Type `1995` and press **Add book**: the address becomes `#/books/6`, and the top bar says `6 books`.

**Check**
+ `BooksPage.vue` and `BookForm.vue` import nothing from `capabilities.js`.
+ The count in the top bar and in the title band of the list are always the same.

## Reference

### A store

`defineStore(id, { state, getters, actions })` returns a function; call it in a component to get the store (`useBooksStore()`). Every component that calls it gets the same store.

| Part | What it is | Use |
| --- | --- | --- |
| `state: () => ({...})` | the shared data and its first values | `store.books`, `store.total`; change it in place (`store.total++`), several at once with `store.$patch({ page: 2 })`; `store.$reset()` restores the first values |
| `getters` | values computed from the state, kept until the state they read changes | `store.isEmpty`; a getter that takes an argument returns a function: `byAuthor: (state) => (id) => state.books.filter(b => b.author_id === id)` |
| `actions` | methods that change the state, synchronous or `async`; `this` is the store | `await store.load(2)`, `await store.add(book)` |

In an Options API component, keep the store in `data()` (`store: useBooksStore()`) and read it in the template (`store.total`). In a `<script setup>` component: `const store = useBooksStore()`. You can have as many stores as you need, one per subject (books, the signed-in person, a cart), each with its own id.

### Stores and capabilities

| In the store | Comes from |
| --- | --- |
| `books`, `total`, `page`, `pages` | `listBooks({ page })`: `{ data, total, page, per_page, pages }` |
| `authors` | `listAuthors()` |
| `errors` | `e.fields` of a `CapabilityError` with `code === 'invalid'` |
| `error` | `e.message` of any other refusal |

The store holds a copy of what the server answered. Load it again (`store.load(1)`) when the data may have changed elsewhere: another person, the REST API or an AI agent.

### Migrating from Vuex

| Vuex | Pinia |
| --- | --- |
| `createStore({ state, mutations, actions, getters })` | `defineStore('id', { state: () => ({...}), getters, actions })` |
| `app.use(store)` | `app.use(createPinia())` |
| `this.$store.state.count` | `store.count` (with `const store = useBooksStore()`) |
| `this.$store.commit('increment', 1)` (a mutation) | `store.increment(1)` (an action) or `store.count++`: there are no mutations |
| `this.$store.dispatch('load', 1)` | `store.load(1)` |
| `this.$store.getters.isEmpty` | `store.isEmpty` |

## Other ways

+ **No store**: for one or two screens, the page component keeps the data and passes it down with props, as in [Single file components](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.3-Single-File-Components). Add a store when two components that are not parent and child need the same data.
+ **The template's example store** (`useAppStore`, a counter with `count`, `isEven` and `increment`) shows the three parts with no server: replace it with stores of your own.

## Common mistakes

+ **`useBooksStore()` outside a component, before `app.use(createPinia())`**: Pinia is not installed yet. Call it in `data()` or `setup`.
+ **Copying a store value into a component's own data** (`total: store.total`): the copy does not follow the store. Read `store.total` in the template.
+ **A component that calls a capability and also the store**: two copies of the same data. Let the store's actions call the capabilities.
+ **Expecting the store to survive a reload**: it lives in the page. A reload loads it again from the server.
