# 9.7.1 Understanding the structure

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.7.1-Understanding-the-structure
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

A Vue app made with `php caligrafer.php app` has two files of its own, and Caligrafy does the rest: it renders the markup through a page route, hands the page an `env` object with what the server knows (the application's address, the CSRF token, who is signed in, your `with` values), and loads your script. This page shows where each part lives and what the "handshake" between the server and the app does.

## With Claude

Claude follows this structure when it scaffolds or changes a Vue app (`/caligrafy-quill:new-app app <name>`). To understand an existing app, ask: "explain the structure of public/bookshelf and how it gets its data".

**Check** before you say OK:
+ The markup is a `.php` file in `public/<app>/`, the scripts are in `public/<app>/scripts/`.
+ The markup loads `scripts('vue')`, then `app.js`, then `loadEnvironment(...)`, then `loadVue(...)`, in this order.
+ Nothing from `application/` is linked from the page.

## By hand

You look inside the Bookshelf app of [Setting up Vue as a library](https://github.com/caligrafy/caligrafy-quill/wiki/9.7.0-Setting-up-Vue.js-as-a-library) and read its `env`.

**1. The files.** Run `ls -R public/bookshelf`. Expected:
```text
index.php
scripts

public/bookshelf/scripts:
main.js
```

**2. The handshake in the markup.** The end of `public/bookshelf/index.php` holds four lines, in this order:
```php
<script src="<?php echo scripts('vue'); ?>"></script>
<script src="<?php echo APP_SERVICE_ROOT.'app.js'; ?>"></script>
<script>loadEnvironment(`<?php echo $env; ?>`);</script>
<script>loadVue({ scripts: ['main'] });</script>
```
`scripts('vue')` is Vue 3; `app.js` (`public/js/services/app.js`) defines `loadEnvironment`, `loadVue` and `apiHeaders`; `$env` is the JSON the server prepared; `loadVue` adds `public/bookshelf/scripts/main.js` to the page.

**3. Read `env`.** Open `http://localhost:8080/bookshelf`, open the browser console and type `Object.keys(env)`. Expected:
```js
['appName', 'app', 'authorized', 'user', '__pug_adapter', 'app_root', 'service_root', 'app_resources', 'request', 'apiKey', 'token', 'csrf', 'home', 'keywords', 'metadata', 'copyright']
```
`env.home` is the application's address (`http://localhost:8080/`), `env.authorized` is `false` for a visitor, `env.user` is `null` (`__pug_adapter` is the view engine's own: ignore it). `Object.keys(env.request)` gives `['method', 'host', 'uri', 'fullUri', 'uriComponents', 'uriParameters', 'parameters', 'parsedURI', 'currentRoute', 'fetch', 'acceptLanguage']`: no header, no cookie (2.19.1).

**4. Pass your own value.** In `application/config/routing/web.php`, give the route a `with` value:
```php
    Route::page('/bookshelf', 'Client/app', ['with' => ['appName' => 'bookshelf', 'app' => 'index', 'shelf' => 'Science fiction']]);
```
Reload the page and type `env.shelf` in the console: `'Science fiction'`. In `main.js`, the script reads it as `env.shelf` (or `this.env.shelf`, since `data()` returns `env: env`).

**Check**
+ `env.home` ends with `/` and is the address of the application, also when `APP_ROOT` is not empty.
+ `env.csrf` is a 64-character token, the same as `env.token`.
+ `JSON.stringify(env.request)` contains no `Cookie`, no `Authorization` and no session id.

## Reference

### Folders

| Folder | What lives there |
| --- | --- |
| `application/` | the server: routes, capabilities, models, Pug views. Never served to browsers |
| `public/` | what browsers load: `css/`, `js/`, `images/`, and each client app in its own folder |
| `public/<app>/` | one Vue app: its markup (`index.php`, or other `.php` files), `scripts/` for its scripts; add `css/` or `images/` as needed |
| `public/js/capabilities.js` | the generated JS client, shared by every Vue app and the Pug pages |

### Why `.php` and not `.html`

The markup is included by the view `application/views/Client/app.pug`, so it runs as PHP: it can call `scripts()`, `session('public')`, `design_stylesheet()` and print `$env`. Write it as HTML with these few PHP lines; the rest is Vue.

### `env`

`application/views/Client/app.pug` builds `env` from every value the route gives the view, plus:

| Key | Value |
| --- | --- |
| `appName`, `app` | the app folder and the markup file (without `.php`) |
| your `with` values, `data` answers and route variables | as the route gives them |
| `authorized`, `user` | who is signed in (with `Route::page`) |
| `home` | the application's address, ending with `/` |
| `token`, `csrf` | the session's CSRF token (the same value) |
| `app_root`, `service_root`, `app_resources` | `public/app/`, `public/js/services/`, `public/resources/` as full addresses |
| `request` | what the page may see of the request that opened it, `request()->forClient()` (2.19.1): `method`, `host`, `uri`, `fullUri`, `uriComponents`, `uriParameters` (the query string, without `_token`), `parameters` (the query string, or the route variables when there is none), `parsedURI`, `currentRoute`, `fetch` (the route variables), `acceptLanguage`. Never the headers: no `Cookie` (the session id), no `Authorization`, and no POST body. Before 2.19.1 it was the whole request, headers included |
| `apiKey` | the legacy API key, or `null` when `LEGACY_API_KEY=false` (Caligrafy Cloud). Never use it in a page |
| `keywords`, `metadata`, `copyright` | the values of `application/config/config.php` |

`env` is printed inside `` loadEnvironment(`...`) ``: Caligrafy escapes it so any value, including one from the address, reaches your script unchanged and never runs as code.

### Globals of `public/js/services/app.js`

| Global | What it is |
| --- | --- |
| `env` | the object above |
| `csrfToken` | `env.csrf` |
| `apiHeaders(extra)` | `{ Accept: 'application/json', 'X-CSRF-Token': csrfToken }` merged with `extra`: the headers of a JSON call from the page to its own `Route::action` or controller routes |
| `apiKey` | `env.apiKey` (legacy) |
| `loadEnvironment(json)` | parses `env` |
| `loadVue({ scripts: [...] })` | adds `public/<appName>/scripts/<name>.js` for each name, in order |

### The script

`main.js` creates the app with `Vue.createApp({...})`, registers its components with `app.component(...)`, then `app.mount('#app')`. Keep `env: env` in `data()` so the markup can use `env.home`.

## Other ways

`views/Client/app.pug` is the same for the bot, face detection and machine learning apps (`php caligrafer.php bot|facedetect|ml <name>`); their scaffolds differ in what they load.

## Common mistakes

+ **A script placed in `application/`**: the browser cannot load it. Scripts go in `public/<app>/scripts/`.
+ **`main.js` loaded before `loadEnvironment`**: `env` is `null`. Keep the order of step 2.
+ **A value expected in `env` that the route does not give**: add it to the route's `with`, or read it through a capability.
+ **Looking for a header or the cookie in `env.request`**: since 2.19.1 it has neither. Who is signed in is `env.user`; the CSRF token is `env.csrf`.
+ **Printing `env.apiKey` on screen**: it is the legacy key; never show or use it.
