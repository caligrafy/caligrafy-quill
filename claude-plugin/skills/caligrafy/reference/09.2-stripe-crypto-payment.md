# 9.2 Stripe & Cryptocurrency Payment

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.2-Stripe-&-Cryptocurrency-Payment
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

Caligrafy takes card payments with **Stripe** (stripe-php 22: Stripe Checkout, payment intents and the Payment
Element, Stripe Connect for marketplaces) and crypto payments with the **Coinbase Business Checkouts API**. The
recommended way is a Stripe Checkout started by a capability, and a webhook (`Route::webhook`, 2.19.0) that records the
payment when Stripe says it went through.

> #### (video) [Accepting online payments](https://youtu.be/OqHfnKtM5VY)
>
> In this video you will learn how to accept online payments with Caligrafy using Stripe.

## With Claude

```text
/caligrafy-quill:new-capability Readers pay 5 USD for a membership with Stripe Checkout; record each paid session from Stripe's webhook
```

Claude writes a capability that starts the checkout, a `Route::form` that sends the reader to Stripe, a capability
that records the payment and `Route::webhook('/stripe/events', '<capability>', ['verify' => 'stripe'])` in
`application/config/routing/web.php`, with the table of the payments. It never writes your keys: you put them in `.env`.

**Check**

+ `.env` has your test keys (`PAY_PUBLIC_KEY_TEST`, `PAY_PRIVATE_KEY_TEST`) and `STRIPE_WEBHOOK_SECRET`, and they are
  not in git.
+ The capability that records payments refuses every caller but the webhook, and records a session once even when
  Stripe sends the event twice.
+ A payment with the test card `4242 4242 4242 4242` shows up in the table.

## By hand

**Bookshelf** sells a 5 USD membership. The commands run in the Docker server of the
[Quickstart](https://github.com/caligrafy/caligrafy-quill/wiki/Quickstart) (`http://localhost:8080`); without Docker, drop
`docker compose exec dev-box`. Before you start: the sign-in pages of
[Authentication](https://github.com/caligrafy/caligrafy-quill/wiki/9.1-Authentication) (`Route::auth`), and a
[Stripe](https://stripe.com/) account.

**1. The keys.** In the [Stripe dashboard](https://dashboard.stripe.com/apikeys), copy the test keys into `.env`:

```text
PAY_PUBLIC_KEY_TEST=pk_test_...
PAY_PRIVATE_KEY_TEST=sk_test_...
PAY_PUBLIC_KEY_PRODUCTION=pk_live_...
PAY_PRIVATE_KEY_PRODUCTION=sk_live_...
```

`APP_ENV=local` uses the test keys; `APP_ENV=production` the live ones.

**2. The payments table.** Write `application/models/Payments/create_db.sql`:

```sql
CREATE TABLE IF NOT EXISTS payments (
    id int NOT NULL AUTO_INCREMENT,
    stripe_session varchar(255) NOT NULL,
    amount int NOT NULL DEFAULT 0,
    status varchar(20) NOT NULL,
    created_at datetime NOT NULL DEFAULT now(),
    PRIMARY KEY (id),
    UNIQUE KEY payments_stripe_session_unique (stripe_session)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

Run `docker compose exec dev-box php caligrafer.php sql application/models/Payments/create_db.sql`.

**3. The capability that starts the checkout.** Write `application/services/Payments/StartCheckout.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Payment;
use Caligrafy\Service;

#[Capability(
    name: 'start_checkout',
    description: 'Starts a Stripe checkout for a 5 USD membership and returns the address of the Stripe payment page.',
    scope: 'payments:write'
)]
class StartCheckout extends Service
{
    public $rules = array('site' => '');
    public $descriptions = array('site' => 'The address of this site, for the way back from Stripe. APP_URL wins over it');

    public function handle(array $input, Context $context)
    {
        $site = rtrim((string) (getenv('APP_URL') ?: ($input['site'] ?? '')), '/');
        $result = (new Payment())->createCheckout(
            500,                                    // the amount in cents: 5.00
            'usd',
            1,                                      // the quantity
            array('name' => 'Bookshelf membership'),
            $site . '/membership/done?session_id={CHECKOUT_SESSION_ID}',
            $site . '/membership'
        );
        if (!$result['action_success']) {
            throw new \RuntimeException('Stripe refused the checkout: ' . $result['error']);
        }
        return array('url' => $result['url']);
    }
}
```

The two addresses are where Stripe sends the reader back: after paying, and with its back link. `APP_URL` (the app's
address, set by Caligrafy Cloud) wins over `site`. A capability does not read the session: the route gives it `site` in
step 5.

**4. The capability that records the payment.** Write `application/services/Payments/RecordPayment.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Database;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'record_payment',
    description: 'Records a paid Stripe checkout session. Called by the Stripe webhook.',
    mcp: false
)]
class RecordPayment extends Service
{
    public $rules = array('event' => 'required');

    public function handle(array $input, Context $context)
    {
        if ($context->actorType() !== 'webhook') {
            throw ServiceError::forbidden('Payments are recorded by the Stripe webhook only');
        }
        $event = $input['event'];
        if (($event['type'] ?? '') !== 'checkout.session.completed') {
            return array('ignored' => true);
        }
        $session = $event['data']['object'];
        if (($session['payment_status'] ?? '') !== 'paid') {
            return array('ignored' => true);
        }
        if (Database::table('payments')->where('stripe_session', $session['id'])->exists()) {
            return array('duplicate' => true);
        }
        Database::table('payments')->insert(array(
            'stripe_session' => $session['id'],
            'amount' => (int) $session['amount_total'],
            'status' => 'paid',
        ));
        return array('recorded' => true);
    }
}
```

+ The `actorType()` check matters: without it any signed-in person could call `record_payment` through the REST API
  with an event they made up.
+ Stripe sends an event again until it gets a `2xx`: the `exists()` check records a session once.

**5. The routes.** In `application/config/routing/web.php`, below `Route::auth(...)`:

```php
    Route::page('/membership', 'Bookshelf/membership', ['signedIn' => true, 'comeBack' => true]);
    Route::form('/membership/checkout', 'start_checkout', [
        'inputs' => fn () => ['site' => session('home')],             // only the server sets it, whatever the form sends
        'success' => fn ($result) => $result['url'],                  // a full address: the payment page of Stripe
        'back' => '/membership',
    ]);
    Route::page('/membership/done', 'Bookshelf/membership-done', ['signedIn' => true]);
    Route::webhook('/stripe/events', 'record_payment', ['verify' => 'stripe']);
```

`success` is a function here because the address comes from Stripe: the form sends the reader to it.

**6. The pages.** Write `application/views/Bookshelf/membership.pug`:

```pug
extends ../default/master/site

block title
  | Membership

block content
  main
    h1 Membership
    p A year of Bookshelf for 5 USD.
    form(method='POST', action=$home . 'membership/checkout')
      =csrf()
      button.btn.btn-primary(type='submit') Pay with Stripe
```

and `application/views/Bookshelf/membership-done.pug`:

```pug
extends ../default/master/site

block title
  | Thank you

block content
  main
    h1 Thank you
    p Your payment is being confirmed. It appears in your account within a minute.
```

**7. The webhook secret.** Stripe signs each event with the secret of its endpoint, `whsec_...`:

+ **On your computer**, the [Stripe CLI](https://docs.stripe.com/stripe-cli) forwards the test events:
  `stripe listen --forward-to localhost:8080/stripe/events` prints a `whsec_...` secret.
+ **Online**, in the dashboard (Developers, Webhooks), add the endpoint `https://<your app>/stripe/events` with the
  event `checkout.session.completed`, and copy its signing secret.

Put it in `.env`:

```text
STRIPE_WEBHOOK_SECRET=whsec_...
```

**8. Try it.** Sign in, open `/membership`, press *Pay with Stripe*: Stripe's page opens. Pay with the test card
`4242 4242 4242 4242`, any future date, any CVC. Stripe brings you back to `/membership/done`, and its event adds a row
to `payments` (`status` `paid`, `amount` `500`).

To try the webhook with no Stripe at all, sign an event yourself. Write `tests/sign.php` (`tests/` is never served):

```php
<?php
// php tests/sign.php <secret> <file>: the Stripe-Signature header of the file's body
$time = time();
$body = file_get_contents($argv[2]);
echo 't=' . $time . ',v1=' . hash_hmac('sha256', $time . '.' . $body, $argv[1]);
```

and `tests/event.json`:

```json
{"id":"evt_test_1","type":"checkout.session.completed","data":{"object":{"id":"cs_test_a1","payment_status":"paid","amount_total":500}}}
```

then, with `STRIPE_WEBHOOK_SECRET=whsec_test_docs` in `.env`:

```bash
curl -X POST -H "Content-Type: application/json" \
  -H "Stripe-Signature: $(docker compose exec -T dev-box php tests/sign.php whsec_test_docs tests/event.json)" \
  --data-binary @tests/event.json http://localhost:8080/stripe/events
```

| You send | You get |
|---|---|
| the event, signed | `200 {"received":true}` and a row in `payments` |
| the same event again | `200 {"received":true}`, still one row |
| `Stripe-Signature: t=1,v1=bad`, or no header | `400 {"error":{"code":"invalid_signature","message":"The Stripe signature is not valid"}}` |
| any event with `STRIPE_WEBHOOK_SECRET` empty | `500 {"error":{"code":"error","message":"The webhook is not set up"}}` |
| `docker compose exec dev-box php caligrafer.php call record_payment '{"event":{"type":"x"}}'` | `{"error":{"code":"forbidden","message":"Payments are recorded by the Stripe webhook only"}}` |

`docker compose exec dev-box php caligrafer.php audit` shows each event as `webhook /stripe/events record_payment ok`.

**Check**

+ `payments` has one row per paid session, whatever the number of times Stripe sent it.
+ A bad signature gets `400`; no one but the webhook can record a payment.
+ `.env` (keys and `STRIPE_WEBHOOK_SECRET`) is not committed.

## Going live

With `APP_ENV=production`, payments use the `PAY_*_PRODUCTION` (live) keys: real cards, real money. Try one real
payment of a small amount, then refund it from the Stripe dashboard.

Stripe keeps **one list of webhook endpoints per mode, each with its own secret**:

+ Create the endpoint again in **live mode** and give the server its live signing secret (`STRIPE_WEBHOOK_SECRET`; on
  Caligrafy Cloud, `php caligrafer.php cloud secret set <app> STRIPE_WEBHOOK_SECRET=whsec_...`, then deploy).
+ A **test-mode** endpoint left on the production address fails: the server checks the test events with the live secret
  and answers `400`. Stripe retries, emails you, and stops sending to the endpoint after about nine days. Disable it
  (Developers, Webhooks, in test mode), or point it at a test server.

`php caligrafer.php doctor --only stripe,coinbase` checks the keys without creating anything: it reads the Stripe
balance (and says test or live mode) and lists one Coinbase checkout.

## Reference: `Route::webhook`

```php
Route::webhook('/stripe/events', 'record_payment', ['verify' => 'stripe']);
Route::webhook('/hooks/github', 'record_push', ['verify' => function ($rawBody, $headers) {
    return hash_equals('sha256=' . hash_hmac('sha256', $rawBody, getenv('GITHUB_SECRET')), $headers['x-hub-signature-256'] ?? '');
}]);
```

| Option | Default | What it does |
|---|---|---|
| `verify` | required | `'stripe'`, or a function `($rawBody, $headers): bool` (header names in lower case); anything else stops `web.php` with an error |
| `secret_env` | `'STRIPE_WEBHOOK_SECRET'` | the `.env` setting that holds the Stripe secret |
| `secret` | | the secret itself, instead of `secret_env` |
| `tolerance` | `300` | seconds a Stripe signature stays valid |

| The event | The answer |
|---|---|
| signature checked, capability done | `200 {"received": true}` |
| bad or missing signature, a body that is not JSON | `400` |
| the capability refuses (`ServiceError`) | its status and error |
| no secret set, no such capability, an error in the capability | `500` (the reason goes to the PHP error log) |

+ `POST` only. No session and no CSRF token: the signature is the only proof.
+ The capability gets `['event' => the decoded JSON body]` and runs as the system, with full access
  (`$context->actorType()` is `webhook`). Declare `public $rules = array('event' => 'required');`.
+ Before trusting an amount for something valuable, ask Stripe again: `(new Caligrafy\Payment())->retrieveCheckout($id)`.

## Reference: `Caligrafy\Payment`

```php
// a checkout on a page hosted by Stripe
public function createCheckout($amount = 1000, $currency = 'usd', $quantity = 1, $productData = array(), $successUrl = '', $cancelUrl = '', $customerEmail = null, $locale = null, $paymentType = null, $payment_intent_data = array(), $vendor = array())
public function retrieveCheckout($sessionId)        // its status: data->payment_status is 'paid' once paid

// a payment intent, for your own payment page (the Payment Element)
public function createPaymentIntent($amount, $currency, $metadata = array(), $receipt_email = null, $description = '', $transfer = array())
public function retrieveIntent($intentId)

// a charge from card data (only for Stripe accounts allowed to send raw card numbers)
public function createTransaction($amount, $currency, $card, $receipt_email = null, $metadata = null, $description = '', $transfer = array(), $save = false)

public function getPublicKey()                       // the publishable key of the current APP_ENV
```

| Argument | |
|---|---|
| `$amount` | in cents (`500` is 5.00) |
| `$currency` | `'usd'`, `'eur'`... |
| `$productData` | `array('name' => ..., 'description' => ..., 'tax_code' => ...)` |
| `$successUrl` | where Stripe sends the customer after paying; `{CHECKOUT_SESSION_ID}` is replaced by the session id |
| `$cancelUrl` | where Stripe's back link goes |
| `$customerEmail`, `$locale` | fill in the email; the language of the page |
| `$paymentType` | leave `null`: the payment methods come from your Stripe dashboard |
| `$transfer`, `$payment_intent_data`, `$vendor` | Stripe Connect: `array('transfer_data' => ['destination' => 'acct_...'])`, `array('payment_intent_data' => ['application_fee_amount' => 200])`, `array('stripe_account' => 'acct_...')` |
| `$receipt_email`, `$metadata`, `$description` | a receipt address, your own key/value pairs, a description |

+ Every method returns `array('action_success' => true, 'data' => <Stripe object>)`, or
  `array('action_success' => false, 'error' => '<message>')`. `createCheckout()` adds `'url'`, the Stripe page;
  `createTransaction()` returns `'data' => array('confirmation' => <charge id>)`.
+ **Tax codes.** New Stripe accounts have Managed Payments on and refuse a product without a tax code. A
  `createCheckout()` without `tax_code` creates a classic Checkout (`managed_payments` off). To use Managed Payments,
  give the product its code (`txcd_10103001` SaaS for business use, `txcd_10000000` electronically supplied services);
  `'managed_payments' => array('enabled' => true|false)` in `$payment_intent_data` decides either way.
+ An empty `PAY_PRIVATE_KEY_*` makes `new Payment()` throw (`api_key cannot be the empty string`).

**Stripe Connect** (vendors paid out by Stripe):

```php
public function createAccount($email = null, $country = null, $type = 'express', $capabilities = array(), $accountInformation = array())
public function createAccountLink($accountId, $refreshUrl, $returnUrl, $type = 'account_onboarding')
public function createLoginLink($accountId)
public function updateAccount($accountId, $updates)
public function retrieve($accountId)
```

**ACH (bank) payments** go through Stripe Checkout: turn ACH on in your Stripe payment methods, and `createCheckout()`
offers it.

## Cryptocurrency (Coinbase Business)

Caligrafy accepts USDC on Base through the **Coinbase Business Checkouts API**: Caligrafy creates a checkout and the
customer pays on a page hosted by Coinbase. Coinbase Commerce shut down on March 31, 2026, with its `CRYPTO_PAY_KEY`
setting; Coinbase Business serves merchants in the countries it supports (the United States and Singapore at the time
of writing).

**1. The keys.** Open a [Coinbase Business](https://www.coinbase.com/business) account, then create a secret API key for
the Business API in the Coinbase Developer Platform (Ed25519). In `.env`:

```text
# organizations/<org_id>/apiKeys/<key_id>
COINBASE_API_KEY_NAME=organizations/...
# the Ed25519 secret in base64, or a legacy ECDSA PEM written on one line with \n
COINBASE_API_KEY_SECRET=...
```

Each request is signed with a JWT built from them (valid 2 minutes); the secret never leaves your server.

**2. The capability.** Write `application/services/Payments/StartCryptoCheckout.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\CryptoPayment;
use Caligrafy\Service;

#[Capability(
    name: 'start_crypto_checkout',
    description: 'Starts a Coinbase checkout for a 5 USD membership and returns the address of the payment page.',
    scope: 'payments:write'
)]
class StartCryptoCheckout extends Service
{
    public $rules = array('site' => '');
    public $descriptions = array('site' => 'The address of this site, for the way back from Coinbase. APP_URL wins over it');

    public function handle(array $input, Context $context)
    {
        $site = rtrim((string) (getenv('APP_URL') ?: ($input['site'] ?? '')), '/');
        $result = (new CryptoPayment())->createTransaction(5, 'USD',
            array('name' => 'Bookshelf membership', 'description' => 'A year of Bookshelf'),
            array('user' => (string) $context->userId()),
            $site . '/membership/done', $site . '/membership');
        if (!$result['action_success']) {
            throw new \RuntimeException('Coinbase refused the checkout: ' . $result['error']);
        }
        return array('url' => $result['url']);
    }
}
```

**3. The route and the button.**

```php
    Route::form('/membership/crypto', 'start_crypto_checkout', [
        'inputs' => fn () => ['site' => session('home')],
        'success' => fn ($result) => $result['url'],
        'back' => '/membership',
    ]);
```

```pug
    form(method='POST', action=$home . 'membership/crypto')
      =csrf()
      button.btn.btn-secondary(type='submit') Pay with USDC
```

Coinbase needs `https://` addresses for both return links: try it on a server with HTTPS. Each checkout can be paid
once and expires after 24 hours by default.

```php
public function createTransaction($amount, $currency, $charge = array(), $metadata = array(), $redirectUrl = '', $cancelUrl = '', $expiresAt = null)
// ['action_success' => true, 'url' => <hosted payment page>, 'data' => <checkout>]
public function getCharge($chargeId)            // a checkout by id
public function getChargeStatus($chargeId)      // ACTIVE, PROCESSING, COMPLETED, EXPIRED, FAILED, DEACTIVATED, REFUNDED, PARTIALLY_REFUNDED, or 'unknown'
public function getCharges($filters = array())  // filters: status, startTime, endTime, descriptionQuery, pageSize, pageToken
public function cancelTransaction($id)          // deactivates an active checkout
public function refundTransaction($id, $amount = null, $currency = 'USDC', $reason = '') // full refund when $amount is null
```

`new CryptoPayment($keyName, $keySecret)` uses another account. Every method but `getChargeStatus()` returns
`array('action_success' => ..., 'data' => ...)` or `array('action_success' => false, 'error' => ...)`.

## Other ways

**The Payment Element on your own page.** For a payment form on your own page (cards, wallets, 3D Secure), opening the
page creates a payment intent and hands its client secret to the page Caligrafy ships, `default/pages/payment.pug` (with
`public/js/services/stripe_client.js`, the Payment Element and `stripe.confirmPayment`). A `GET` that changes something is
not a `Route::page`: it is a web-only capability, `application/services/Payments/PayPage.php`:

```php
<?php

use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Payment;
use Caligrafy\Service;
use Caligrafy\Web;

#[Capability(name: 'pay_page', description: 'The payment page of a 5 USD membership.', webOnly: true)]
class PayPage extends Service
{
    public function handle(array $input, Context $context)
    {
        $payment = new Payment();
        $result = $payment->createPaymentIntent(500, 'usd');
        $secret = $result['action_success'] ? $result['data']->client_secret : null;
        return Web::view('default/pages/payment', array('clientSecret' => $secret, 'publicKey' => $payment->getPublicKey()));
    }
}
```

with `Route::action('/pay', 'pay_page', ['comeBack' => true]);` (no `public: true`: a visitor signs in first and comes
back). Record the payment from the webhook (`payment_intent.succeeded`), as above.

**A controller around Checkout.** Projects made before 2.19.0 create the checkout in a controller and show
`default/pages/checkout.pug` with its `checkoutUrl`. They keep working; `StartCheckout` and `Route::form` replace them.

**A charge from card numbers** (`createTransaction()` with `'tok_visa'` in test mode, or raw card data): only for Stripe
accounts allowed to handle raw card data. Prefer Checkout.

## Common mistakes

+ **Every event answers 500.** `STRIPE_WEBHOOK_SECRET` is empty, or holds the API key instead of the endpoint's
  `whsec_...`.
+ **Every event answers 400 online.** A test-mode endpoint checked with the live secret, or the reverse (see
  [Going live](#going-live)).
+ **A payment recorded twice.** Stripe retries: check that the session is not recorded yet, as `RecordPayment` does.
+ **Anyone can record a payment.** A webhook capability is also a REST capability: refuse callers whose
  `$context->actorType()` is not `webhook`.
+ **`the product tax code is missing`.** A product with Managed Payments on and no tax code: give a `tax_code`, or leave
  it out to get a classic Checkout.
+ **The way back breaks on a test server.** Build the return addresses from `APP_URL` or from `session('home')` given by
  the route's `inputs`, never a fixed `https://` address.
+ **A payment created in `Route::page`.** Pages take read-only capabilities: use `Route::form`, or `Route::action` when
  opening the address must create it.
