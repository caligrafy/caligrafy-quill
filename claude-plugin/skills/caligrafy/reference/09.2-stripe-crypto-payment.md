# 9.2 Stripe & Cryptocurrency Payment

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.2-Stripe-&-Cryptocurrency-Payment
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

Accepting payments is a key success factor for any e-commerce application. Choosing the right service that balances security, ease of integration, cost and widespread availability is a challenging decision.
This framework selected Stripe as its primary payment service and integrates it seamlessly at its core (stripe-php 22, Stripe.js with the Payment Element). For Cryptocurrency, this framework uses the Coinbase Business Checkouts API.

## Setting up a Stripe
In order to accept payments through this framework, a Stripe account needs to be created.

> Open a free account with Stripe [here](https://stripe.com/)

Once you open an account, Stripe provides you with a pair of local and production keys.
You can get these keys from the [Developers section](https://dashboard.stripe.com/apikeys)

## Configuring .env
Stripe provides a pair of a `Publishable Key` and a `Secret Key` for a production environment and another one for a test environment.
In the framework `.env` file, you need to provide these keys:
```php
PAY_PUBLIC_KEY_TEST= // <Publishable Key for Test Data>
PAY_PRIVATE_KEY_TEST= // <Secret Key for Test Data>
PAY_PUBLIC_KEY_PRODUCTION= // <Publishable Key for Production>
PAY_PRIVATE_KEY_PRODUCTION= // <Secret Key for Production>
```
You need to make sure that in the `.env` of the development machine you set `APP_ENV=local` and on the production machine you set `APP_ENV=production`.

## Test Data
Stripe provides test credit cards to test the payment gateway on a development machine. The test credit card can only be used with the Test Data pair of keys.
+ **credit card number:** `4242 4242 4242 4242`
+ **expiry year:** `any year in the future`
+ **expiry month:** `any month`
+ **CVC:** `any combination of 3 or 4 numbers`

## Method 1: Simple card payment without authorization flows
Creating a payment for cards not requiring secure authorization flows by the issuer is quick and easy. The payment can be handled from the context of a `Controller`. To illustrate this, let's assume that we created a `view` that has a form containing the `card number`, the `expiry year`, the `expiry month` and the `CVC`. 
> Visit the [Views section](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views) to learn more about creating forms with Pug

In order to process the payment, a payment controller needs to be created to receive the posted card values and  to create a Stripe transaction:

1. Activate the payment in the `Controller`
```php
use Caligrafy\Controller;

class PaymentController extends Controller {

    public function index()
    {
        // Activate Stripe Payment
        $this->activatePayment();
    }

}
```

2. Get the card inputs from the form
```php
use Caligrafy\Controller;

class PaymentController extends Controller {

    public function index()
    {
        // Activate Stripe Payment
        $this->activatePayment();

        // Create a card object from the posted information
        $parameters = $this->request->parameters(); // fetches the inputs from the form

        // use this for testing purposes in stripe test mode
        $card = "tok_visa"; 

        // use this in production environment
        $card = [
            'card' => array(
            'number' => $parameters['number'], 
            'exp_month' => $parameters['exp_month'], 
            'exp_year' => $parameters['exp_year'],
            'cvc' => $parameters['cvc']) 
        ];
    }

}
```
3. Create a payment transaction
```php
use Caligrafy\Controller;

class PaymentController extends Controller {

    public function index()
    {
        // Activate Stripe Payment
        $this->activatePayment();

        // Create a card object from the posted information
        $parameters = $this->request->parameters(); // fetches the inputs from the form

        // use this for testing purposes in stripe test mode
        $card = "tok_visa"; 

        // use this in production environment
        $card = [
            'card' => array(
            'number' => $parameters['number'], 
            'exp_month' => $parameters['exp_month'], 
            'exp_year' => $parameters['exp_year'],
            'cvc' => $parameters['cvc']) 
        ];

        // Create a payment transaction
        $this->payment->createTransaction(1000, 'USD', $card);
    }
}

```

And that's it, you can verify in the Test Data Dashboard on Stripe that the charge was submitted.

## Method 2: Global payment for all types of cards
Creating a payment that works for all types of cards globally needs a mechanism that is capable of handling any additional authorizations that the card issuer requires (i.e 3DSecure). With the Caligrafy integration of Stripe, you can get card payment up and ready in no time.

The payment page uses the Stripe **Payment Element** (the Card Element is legacy): it shows every payment method enabled in your Stripe dashboard (cards, wallets, bank payments...) and handles 3D Secure. Payment methods that need a redirect come back to the same page, which shows the result.

> [Live Example](https://caligrafy.com/pay)
>
> Test card: `4242 4242 4242 4242`

1. Activate the payment in the `Controller` (Similarly to step 1 from the other technique)
2. Create a payment intent from the inputs

```php
use Caligrafy\Controller;

class PaymentController extends Controller {

    public function index()
    {
        // Activate Stripe Payment
        $this->activatePayment();

        // Create a payment intent from the posted information
        $parameters = $this->request->parameters(); // fetches the inputs from the form

        // The payment intent takes at the very least an amount and a currency
	$result = $this->payment->createPaymentIntent(1000, 'USD'); 
	if ($result['action_success']) {
		$intent = $result['data']->client_secret;
	} else {
		$intent = null;
	}

        // Return a clientSecret and the stripe publicKey to the view
	return view('default/pages/payment', array('clientSecret' => $intent, 'publicKey' => $this->payment->getPublicKey()));
    }
}
```
3. Hand-off the payment intent to the view

The controller needs to hand-off the payment to the view so that the Stripe client handles the entire payment flow. Caligrafy provides a payment page as an example `default/pages/payment.pug` with its script `public/js/services/stripe_client.js` (Payment Element + `stripe.confirmPayment`). 

2 parameters must be returned to that page: `clientSecret` from the intent and `publicKey` which is the stripe publishable key that can already be fetched from the payment attribute of the controller.

```php
   [...]
   // Return a clientSecret and the stripe publicKey to the view
   return view('default/pages/payment', array('clientSecret' => $intent, 'publicKey' => $this->payment->getPublicKey()));
   [...]
```

**Don't forget to create routes to these controllers before testing**

## Method 3: Checkout flow powered by Stripe
The third method is plug and play and it allows you to start accepting different types of payments very quickly without the burden of developing it yourself. Stripe takes care of it all for you.

> [Live Example](https://caligrafy.com/checkout)
>
> Test card: `4242 4242 4242 4242`

1. Activate the payment in the `Controller` (Similarly to step 1 from the other technique)
2. Create a checkout session

```php
use Caligrafy\Controller;

class PaymentController extends Controller {

    public function index()
    {
        // Activate Stripe Payment
	$this->activatePayment();

	// get the current url to bring back the customer to this page upon failure or success. If desired
	$currentUrl = session('base').sanitizePath($_SERVER['REQUEST_URI']);

	$result = $this->payment->createCheckout(2000, 'usd', 1, array('name' => 'T-shirt'), $currentUrl, $currentUrl);

	// $result['url'] is the payment page hosted by Stripe
	return view('default/pages/checkout', array('checkoutUrl' => $result['action_success']? $result['url'] : null));
    }
}
```
3. Send the customer to the checkout page

`createCheckout()` returns the `url` of the Stripe-hosted payment page. Caligrafy provides an example page `default/pages/checkout.pug` that shows a "Check out" button linking to it (pass it as `checkoutUrl`). You can also redirect the customer right away:

```php
   header('Location: ' . $result['url'], true, 303);
   exit;
```

> Stripe.js removed `redirectToCheckout()`: always redirect to the session `url`. Earlier versions of this page passed a `sessionId` to the view, which no longer works.

**Don't forget to create routes to these controllers before testing**

## Payment Methods
This framework uses 3 different methods to execute payments through Stripe. 

```php
// Method 1: Using charges for cards without authorization flows
public function createTransaction($amount, $currency, $card, $receipt_email = null, $metadata = null, $description = '', $transfer = array())

// Method 2: Using payment intents for all types of cards
public function createPaymentIntent($amount, $currency, $metadata = array(), $receipt_email = null, $description = '', $transfer = array())
public function retrieveIntent($intentId) // retrieves a payment intent to check its status

// Method 3: Using an integrated checkout session
public function createCheckout($amount = 1000, $currency = 'usd', $quantity = 1, $productData = array(), $successUrl = '', $cancelUrl = '', $customerEmail = null, $locale = null, $paymentType = null, $payment_intent_data = array(), $vendor = array())
public function retrieveCheckout($sessionId) // retrieves a checkout session to check its status

public function getPublicKey() // returns the publishable key of the current environment

```
+ **`$amount`:** This is the amount in *cents*
+ **`$currency`:** This is the currency string. For example `USD`
+ **`$card`:** This is an array that represents a credit cards, bank account or pii as described in the [Stripe Documentation](https://stripe.com/docs/api/tokens/create_card?lang=php).
+ **`$receipt_email`:**  This is the customer's email. When defined an automatic email will be sent if the email settings in your stripe allow for sending receipts.
+ **`$metadata`:** This is an array that represents any additional metadata that you would want to append to the transaction
+ **`$description`:** This is a text description that can be appended to the transaction
+ **`$productData`**: This is an array that represents any additional information about the product that needs to appear in the checkout process
+ **`$successUrl`**: This defines the url to redirect the checkout flow to upon successful completion
+ **`$cancelUrl`**: This defines the url to redirect the checkout flow to upon incompletion
+ **`$paymentType`**: Leave it `null`: the checkout shows the payment methods enabled in your Stripe dashboard. Current Stripe API versions reject `payment_method_types` on checkout sessions; it is only sent when you pass a value (accounts pinned to an older API version)
+ **`locale`**: Defines the locale for language and formats of the checkout flow
+ **`customerEmail`**: Prepopulates the email of the customer in the checkout flow
+ **`$transfer`**, **`$payment_intent_data`**, **`$vendor`**: Stripe Connect options for marketplaces, for example `array('transfer_data' => ['destination' => 'acct_...'])`, `array('payment_intent_data' => ['application_fee_amount' => 200])` and `array('stripe_account' => 'acct_...')`

All the methods return an array: `array('action_success' => true, 'data' => <Stripe object>)` on success, or `array('action_success' => false, 'error' => '<message>')`. `createCheckout()` also returns `'url'`. `createPaymentIntent()` enables automatic payment methods.

> Method 1 sends raw card numbers to Stripe from your server. Stripe only accepts this for accounts that are allowed to handle raw card data: prefer Method 2 or Method 3 in production.

# ACH Payments
ACH payments are bank transfers. With Caligrafy, you can have your buyers pay directly from their bank accounts in a very user-friendly flow.
Caligrafy uses the ACH payment that Stripe provides. In order to activate ACH with Stripe, you will need to use Method 3 described above and configure your Stripe payment method to support ACH payments.

# Cryptocurrency

Caligrafy accepts crypto payments (USDC on Base) through the **Coinbase Business Checkouts API**: Caligrafy creates a checkout and the customer pays on a page hosted by Coinbase.

> **Coinbase Commerce shut down on March 31, 2026.** Coinbase Business replaces it for merchants in the countries it supports (the United States and Singapore at the time of writing). The previous `CRYPTO_PAY_KEY` setting no longer works.

## Setting up Coinbase Business

1. Open a [Coinbase Business](https://www.coinbase.com/business) account.
2. In the Coinbase Developer Platform, create a **secret API key** for the Business API (Ed25519 is recommended). You get a key name, `organizations/<org_id>/apiKeys/<key_id>`, and a secret.

## Configuring .env
```php
COINBASE_API_KEY_NAME= // organizations/<org_id>/apiKeys/<key_id>
COINBASE_API_KEY_SECRET= // the Ed25519 secret (base64), or the PEM of a legacy ECDSA key written on one line with \n
```
Every request is signed with a JWT that Caligrafy builds from these settings (valid 2 minutes). The secret never leaves your server.

## Creating a Payment

1. Create a checkout in the controller

```php
use Caligrafy\Controller;
use Caligrafy\CryptoPayment; // <- DON'T FORGET TO INCLUDE 

class PaymentController extends Controller {

    public function index()
    {
        $crypto = new CryptoPayment();

        // amount, currency (USDC, or a fiat currency converted to USDC), product, metadata, success and failure urls (HTTPS)
        $transaction = $crypto->createTransaction(10, 'USD', array('name' => 'Product Name', 'description' => 'description goes here'),
                                                  array('order' => '42'), 'https://example.com/thanks', 'https://example.com/cart');

        return view('default/index', array('cryptourl' => $transaction['action_success']? $transaction['url'] : null));
    }
}

```

2. Add a Cryptocurrency Button

Caligrafy provides a ready-to-use button module `default/modules/cryptopayment.pug` that links to `$cryptourl`. Include it in any `view`:

```pug
include path-to-module/cryptopayment
```

Each checkout can be paid once and expires after 24 hours by default.

## Coinbase Business Methods

```php
public function createTransaction($amount, $currency, $charge = array(), $metadata = array(), $redirectUrl = '', $cancelUrl = '', $expiresAt = null)
// returns ['action_success' => true, 'url' => <hosted payment page>, 'data' => <checkout>] (data['hosted_url'] is kept for older code)
public function getCharge($chargeId)            // retrieves a checkout by id
public function getChargeStatus($chargeId)      // ACTIVE, PROCESSING, COMPLETED, EXPIRED, FAILED, DEACTIVATED, REFUNDED, PARTIALLY_REFUNDED
public function getCharges($filters = array())  // lists checkouts. Filters: status, startTime, endTime, descriptionQuery, pageSize, pageToken
public function cancelTransaction($id)          // deactivates an active checkout
public function refundTransaction($id, $amount = null, $currency = 'USDC', $reason = '') // refunds a completed checkout (full refund when $amount is null)
```

Every method returns `array('action_success' => true, 'data' => <response>)`, or `array('action_success' => false, 'error' => '<message>')` (for example when the API key settings are missing).
