# 9.9.5 OpenAI: Assistants

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.5-Open-AI:-Assistants
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - Assistant 2.0 runs on the Responses + Conversations APIs (the Assistants API shut down 2026-08-26): nothing is created on OpenAI except a vector store when files are given; `run()` returns with the answer, read it with `text()`; `retrieveResponse($timeout = 120, $interval = 2)` only waits for queued/in_progress answers (G32).

Artificial Intelligence has made significant strides in the last couple of years especially - unexpectedly - in the creative world. OpenAI has been a major player in bringing generative artificial intelligence to the mass. For those of you who have not heard about generative AI before, it is the ability of the machine to create and produce new ideas from what it already knows.

> **AI in both directions.** This page is about your application calling AI models. The other direction comes with Caligrafy too: AI agents such as Claude use your application's [capabilities](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#service) as tools over [MCP](https://github.com/caligrafy/caligrafy-quill/wiki/11.-Build-Once:-Services,-Capabilities-and-MCP#mcp), with a personal access token that limits what they may do. Build once, experience everywhere: the same capability serves your pages, your apps, your API and the agents.

Caligrafy lets you build AI assistants that hold a conversation, follow your instructions and answer from your own files.

> **Assistant 2.0.** OpenAI shut down its Assistants API on August 26, 2026. The Caligrafy `Assistant` class now runs on the APIs that replace it, the **Responses API** and the **Conversations API**, and keeps the same chainable methods (`start()`, `createMessage()`, `run()`, `retrieveResponse()`, `end()`). The main difference: an assistant is no longer an object stored on OpenAI. Its model, instructions and tools live in your `Assistant` object and are sent with every answer. See [Migrating from version 1](#migrating) below.

## Initializing OpenAI

### Step 1: Get an OpenAI Account

The first thing that needs to be done is to sign up for an [OpenAI account](https://platform.openai.com/).

### Step 2: Get an OpenAI API Key

* [Create a new OpenAI secret key](https://platform.openai.com/api-keys) that will allow you to use the OpenAI APIs
* Copy the API key and paste it into the Caligrafy `.env` file next to the `OPEN_AI_KEY=<paste your key here>`
* Optionally, choose the default model with `OPEN_AI_MODEL=` (`gpt-6-luna` when empty)
* Run `php caligrafer.php doctor --only openai` to check the key and that the model is allowed for its project ([Caligrafer doctor](1.-Getting-Started#doctor))

### Step 3: Prepare the Caligrafy controller

The Assistant class needs to be imported into the Caligrafy controller where the assistant is used.

```php

use Caligrafy\Controller;
use Caligrafy\Assistant; // <-- Make sure to import the Assistant class

class AssistantController extends Controller {

    // your code goes here

}
```

## Configuring an Assistant

An `Assistant` object can be created without any parameters: it then uses the default model (`gpt-6-luna`, or `OPEN_AI_MODEL`) without instructions. Creating the object does not call OpenAI unless you give it files.

```php
use Caligrafy\Controller;
use Caligrafy\Assistant;

class TestController extends Controller {

    public function index() 
    {
        $assistant = new Assistant(array(
            "name" => "Bookstore assistant",
            "instructions" => "You are a helpful bookseller. Answer in two sentences at most.",
            "model" => ASSISTANT_GPT6_ASTRA // optional
        ));
    }

}
```

Here is the list of all the parameters that can be passed to the Assistant object

```php

- name (string): the name of the assistant (also used to name its vector store)

- description (string): what the assistant does (kept locally)

- instructions (string): the system prompt sent with every answer. For example, "You are a helpful assistant and you will use your knowledge to answer the user's questions"

- metadata (array): up to 16 string pairs sent with every conversation and answer

- model (string): the OpenAI model. Constants: ASSISTANT_GPT6_LUNA (default, fastest), ASSISTANT_GPT6_SOL, ASSISTANT_GPT6_ASTRA (flagship)

- tools (array): array(["type" => "file_search"]) by default. Add ["type" => "code_interpreter"] to let the assistant run code on the uploaded files.
  Caligrafy completes file_search with the assistant's vector store and code_interpreter with the uploaded files

- file_paths (array of paths): local files that the assistant can search. Caligrafy uploads them and adds them to a vector store

- file_ids (array of string): files already uploaded to OpenAI

- vector_store_id (string): an existing vector store (reuse the files of a previous assistant without uploading them again)

```

### Answering from your files

When `file_paths` (or `file_ids`) are given, Caligrafy uploads the files (`POST /v1/files`), creates a **vector store** that indexes them and gives it to the `file_search` tool. Save the `vector_store_id` and pass it next time to reuse the same files without uploading them again:

```php
$assistant = new Assistant(array(
    "instructions" => "Answer with the information of the catalog only",
    "file_paths" => array(PUBLIC_PATH . "uploads/catalog.pdf")
));
$vectorStoreId = $assistant->vector_store_id; // save it (database or .env)

// later
$assistant = new Assistant(array("vector_store_id" => $vectorStoreId, "instructions" => "..."));
```

### Deleting an Assistant

There is no assistant stored on OpenAI any more. `delete()` deletes the vector store created for the assistant (the uploaded files stay in your OpenAI file storage until you delete them with `deleteAssistantFile()`).

```php
$assistant->delete();
```

## Engaging with Assistants

### Step 1 - Start a conversation

A conversation contains all the exchanged messages, which form the context of the dialogue. `start()` creates it on OpenAI (`POST /v1/conversations`) and `end()` deletes it.

```php
$assistant = new Assistant(array("name" => "My Assistant"));

// Start a conversation
$assistant->start();

// End a conversation
$assistant->end();
```

### Step 2 - Create Messages

`createMessage()` adds a message that will be sent with the next `run()`. Several messages can be added by chaining the method.

```php
$assistant->createMessage("Hi")
          ->createMessage("I am looking for a science-fiction book");
```

### Step 3 - Run the Assistant

`run()` sends the pending messages and gets the answer (`POST /v1/responses`). The answer is added to the conversation, so the next `run()` knows everything that was said before.

```php
$assistant->start()
          ->createMessage("Hi")
          ->run();
```

### Step 4 - Retrieving the response

The answer is ready when `run()` returns. Read its text with `text()` (or the `response_text` property), or the whole conversation with the `messages` property.

```php
$assistant = new Assistant(array("name" => "My Assistant"));

$answer = $assistant->start()
                    ->createMessage("Hi")
                    ->run()
                    ->text();          // "Hello! How can I help you today?"

$assistant->createMessage("Recommend me a book")->run();
echo $assistant->text();               // the second answer, which knows the first exchange

$assistant->end();
```

`run()` waits for the answer. `retrieveResponse($timeout = 120, $interval = 2)` is kept for code written for version 1: it only polls (every 2 seconds, for at most 120 seconds) when an answer is still `queued` or `in_progress`, and returns at once otherwise. Check `$assistant->status` afterwards (`completed`, `failed`, `incomplete`...). When an answer fails, `$assistant->last_response` holds what OpenAI returned, including its error message.

## Assistant Properties & Methods

### Assistant Properties

```php

public $name;                  // String of the assistant name
public $description;           // String of the assistant description
public $instructions;          // String of the instructions sent with every answer
public $tools;                 // Array of tools, i.e array(["type" => "file_search"], ["type" => "code_interpreter"])
public $file_ids;              // Array of the uploaded file ids
public $file_paths;            // Array of the uploaded local file paths
public $metadata;              // Array of key/value pairs
public $vector_store_id;       // String of the vector store used by file_search
public $thread_id;             // String of the active conversation id (conv_...)
public $run_id;                // String of the last answer id (resp_...)
public $status;                // String of the status of the last answer
public $messages;              // Array of the messages: ['id' => ..., 'role' => 'user'|'assistant', 'content' => [['type' => 'input_text'|'output_text', 'text' => '...']]]
public $response_text;         // String of the text of the last answer
public $last_response;         // Array of the last raw answer returned by OpenAI
public $assistant_id;          // Kept for backward compatibility (no longer used)

```

### Assistant Methods

```php

// Chain-able methods

public function retrieve();          // Kept for backward compatibility: returns the assistant
public function start();             // Starts a conversation
public function end();               // Deletes the conversation

public function createMessage(string $content, array $file_ids = [], array $metadata = null, string $role = "user");  
// Adds a message to send with the next run(). $file_ids are given to the code interpreter.
// $role: user, assistant, system or developer. $metadata is ignored (kept for version 1 code): use the metadata of the constructor or of run()

public function run($additional_instructions = '', $instructions = null, $tools = [], $model = '', $metadata = null);
// Sends the pending messages and reads the answer. The overrides apply to this answer only

public function retrieveResponse($timeout = 120, $interval = 2);   // Kept for version 1 code: run() already waits for the answer

// Non chain-able methods

public function text();                                      // Returns the text of the last answer
public function delete();                                    // Deletes the vector store of the assistant: true on success
public function listMessages();                              // Returns the items of the conversation stored on OpenAI
public function uploadAssistantFiles($specified_paths = []); // Uploads files and adds them to the vector store, returns their ids
public function deleteAssistantFile($file_id);               // Removes a file from the vector store and deletes it

```

### Chaining

Most of the methods can be chained to simplify the syntax and to make the code more readable.

```php

   $assistant = new Assistant(array("name" => "My Assistant"));

   // Chaining
   echo $assistant->start()
                  ->createMessage("Hi")
                  ->run()
                  ->text();

   // End a conversation
   $assistant->end();

```

A chain can no longer be continued when a property or a "non chain-able" method is at the end of the chain:

```php
   $assistant->start()->thread_id;                    // the last item in the chain is a property
   $assistant->createMessage("Hi")->run()->text();    // the last item in the chain is a non-chainable method
```

## Migrating from version 1

| Version 1 (Assistants API) | Version 2 (Responses + Conversations) |
| - | - |
| `new Assistant([...])` created an assistant on OpenAI | Nothing is created on OpenAI: the configuration lives in the object |
| `assistant_id` | Not used. Keep the name, instructions, model and tools in your code (or database) |
| Thread (`thread_id`) | Conversation (`thread_id` holds the `conv_...` id) |
| Run (`run_id`) | Response (`run_id` holds the `resp_...` id) |
| `run()` then `retrieveResponse()` | `run()` returns with the answer; `retrieveResponse()` only waits for background answers |
| `$assistant->messages` held OpenAI thread messages (`content[0]['text']['value']`) | It holds `['role', 'content' => [['type', 'text']]]`; use `text()` for the last answer |
| Files attached to the assistant | Files indexed in a vector store (`vector_store_id`) |
| `retrieval` tool | `file_search` tool (`retrieval` is still accepted and converted) |

Threads created with version 1 can no longer be read from OpenAI. If you need their history, send the stored messages again with `createMessage()` before the first `run()` of a new conversation.
