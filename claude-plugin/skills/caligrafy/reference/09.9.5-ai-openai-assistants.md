# 9.9.5 OpenAI: Assistants

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.9.5-Open-AI:-Assistants
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

> **Verified against framework source (see gotchas.md):**
> - Assistant 2.0 runs on the Responses + Conversations APIs (the Assistants API shut down 2026-08-26): nothing is created on OpenAI except a vector store when files are given; `run()` returns with the answer, read it with `text()`; `retrieveResponse($timeout = 120, $interval = 2)` only waits for queued/in_progress answers (G32).

An **assistant** holds a conversation: it remembers what was said, follows your instructions and can answer from your
own files. `Caligrafy\Assistant` runs on OpenAI's Responses and Conversations APIs (OpenAI shut down its Assistants API
on August 26, 2026; see [Migrating from version 1](#migrating)). You put it in a capability, so the same assistant
answers a web page, a Vue app, the REST API and AI agents. In the Bookshelf example, the capability `ask_librarian`
answers questions about the books, from a catalog file, and remembers the conversation.

Nothing is stored on OpenAI for the assistant itself: its model, instructions and tools live in your code and are sent
with every answer. OpenAI keeps the **conversation** (`conv_...`) and, when you give files, a **vector store** (`vs_...`)
that indexes them.

## With Claude

```text
/caligrafy-quill:new-capability ask_librarian ai:use read-only
A librarian assistant (Caligrafy\Assistant) that answers questions about the books from application/files/catalog.md and
continues a conversation when it gets the conversation id back. A /librarian page to chat with it.
```

Claude scaffolds the services in `application/services/`, a page (Pug view and a script that calls the generated
client), the routes in `web.php` and a test that replaces the assistant.

**Check**
- `OPEN_AI_KEY` is in `.env` only; `docker compose exec dev-box php caligrafer.php doctor --only openai` says OK.
- The conversation id goes back to the caller and comes in again as an input: the capability keeps nothing in the session.
- The capability that uploads files is not reachable by agents (`mcp: false`) and needs an administrator (`level: 1`).
- Answers are shown as text (`textContent`, `{{ }}`), never as HTML.

## By hand

The project is the one of the [OpenAI page](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.4-OpenAI:-ChatGPT,-GPTs,-DALL.E):
`OPEN_AI_KEY` in `.env`, sign-in, `Route::capabilities('/capabilities')` and `Route::mcp('/mcp')`. Without Docker (Composer with MAMP, XAMPP or LAMP), run the same commands without `docker compose exec dev-box` and open your own address.

### Step 1: Write the catalog

Create **`application/files/catalog.md`** (the `application` folder is never served to browsers):

```text
# Bookshelf catalog

- Kindred, Octavia E. Butler, 1979. Shelf B, 2 copies.
- The Dispossessed, Ursula K. Le Guin, 1974. Shelf A, 1 copy.
```

### Step 2: A capability that indexes it

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/IndexCatalog --scope ai:admin
```

Replace **`application/services/Bookshelf/IndexCatalog.php`** with:

```php
<?php
/**
 * IndexCatalog: uploads the catalog file to OpenAI so that the librarian answers from it
 */

use Caligrafy\Assistant;
use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'index_catalog',
    description: 'Uploads application/files/catalog.md to OpenAI and returns the id of its vector store, for LIBRARIAN_STORE in .env.',
    scope: 'ai:admin',
    level: 1,
    mcp: false
)]
class IndexCatalog extends Service
{
    public $rules = array();

    public function __construct(private Assistant $assistant)
    {
    }

    public function handle(array $input, Context $context)
    {
        $file = APP_PATH . 'files/catalog.md';
        if (!is_file($file)) {
            throw ServiceError::notFound('Write the catalog in application/files/catalog.md first');
        }

        $this->assistant->name = 'Bookshelf catalog';
        $uploaded = $this->assistant->uploadAssistantFiles(array($file));
        if (empty($uploaded) || $this->assistant->vector_store_id === '') {
            throw ServiceError::conflict('OpenAI did not take the file: check OPEN_AI_KEY (php caligrafer.php doctor --only openai)');
        }

        return array('vector_store_id' => $this->assistant->vector_store_id, 'file_ids' => $uploaded);
    }
}
```

`uploadAssistantFiles()` sends the file to OpenAI (`POST /v1/files`) and creates a vector store named after the
assistant with it. Run it once from the command line (it has full access there):

```bash
docker compose exec dev-box php caligrafer.php call index_catalog
```

Expected:

```json
{
    "data": {
        "vector_store_id": "vs_...",
        "file_ids": [
            "file-..."
        ]
    }
}
```

Copy the `vs_...` id into **`.env`**:

```text
LIBRARIAN_STORE=vs_...
```

Every `.env` line becomes a constant: the capability below reads `LIBRARIAN_STORE`. Run `index_catalog` again after you
change the catalog (it creates a new store: put its id in `.env`).

### Step 3: The librarian

```bash
docker compose exec dev-box php caligrafer.php service Bookshelf/AskLibrarian --scope ai:use --read-only
```

Replace **`application/services/Bookshelf/AskLibrarian.php`** with:

```php
<?php
/**
 * AskLibrarian: a conversation with an OpenAI assistant that knows the bookshelf
 */

use Caligrafy\Assistant;
use Caligrafy\Capability;
use Caligrafy\Context;
use Caligrafy\Service;
use Caligrafy\ServiceError;

#[Capability(
    name: 'ask_librarian',
    description: 'Asks the bookshelf librarian a question. Send the conversation id it returns to continue the same conversation. Returns {conversation, answer}.',
    scope: 'ai:use',
    readOnly: true
)]
class AskLibrarian extends Service
{
    public $rules = array(
        'question' => 'required|max_len,4000',
        'conversation' => 'alpha_numeric_dash|max_len,100',
    );

    public $filters = array(
        'question' => 'trim',
        'conversation' => 'trim',
    );

    public $descriptions = array(
        'question' => 'The question for the librarian',
        'conversation' => 'The conversation id of an earlier answer, to continue that conversation',
    );

    // the assistant comes through the constructor: a test can replace it ($this->fake(Assistant::class, ...))
    public function __construct(private Assistant $assistant)
    {
    }

    public function handle(array $input, Context $context)
    {
        $assistant = $this->assistant;
        $assistant->instructions = 'You are the librarian of a small bookshelf. Answer in three sentences at most.';
        if (defined('LIBRARIAN_STORE') && LIBRARIAN_STORE !== '') {
            $assistant->vector_store_id = LIBRARIAN_STORE;   // answer from the catalog (index_catalog)
        }

        if (!empty($input['conversation'])) {
            $assistant->thread_id = $input['conversation'];  // continue that conversation
        } else {
            $assistant->start();                              // a new conversation on OpenAI
            if ($assistant->thread_id === '') {
                throw ServiceError::conflict('OpenAI did not start the conversation: check OPEN_AI_KEY (php caligrafer.php doctor --only openai)');
            }
        }

        $assistant->createMessage($input['question'])->run();
        if ($assistant->status !== 'completed') {
            throw ServiceError::conflict('OpenAI did not answer: ' . ($assistant->last_response['error']['message'] ?? $assistant->status));
        }

        return array('conversation' => $assistant->thread_id, 'answer' => $assistant->text());
    }
}
```

What it does:
+ The container gives a new `Assistant` with no settings (creating it calls nothing on OpenAI); `handle()` sets its
  instructions and, when `LIBRARIAN_STORE` is set, its vector store, which the default `file_search` tool searches.
+ The first question opens a conversation (`start()`, `POST /v1/conversations`). The caller sends its id back with the
  next question, so the capability keeps nothing between calls and works the same for a page, REST and an agent.
+ `run()` sends the question with the instructions, the tools and the conversation (`POST /v1/responses`) and returns
  when the answer is there; `text()` is its text.

```bash
docker compose exec dev-box php caligrafer.php call ask_librarian question="Where is Kindred?"
```

Expected (the answer varies):

```json
{
    "data": {
        "conversation": "conv_...",
        "answer": "Kindred is on shelf B; there are 2 copies."
    }
}
```

Continue the same conversation:

```bash
docker compose exec dev-box php caligrafer.php call ask_librarian question="Who wrote it?" conversation=conv_...
```

### Step 4: A page to chat

The conversation id lives in the page, so the page calls the capability with the generated client. Write it:

```bash
docker compose exec dev-box php caligrafer.php client
```

Add to **`application/config/routing/web.php`**, before `Route::run();`:

```php
Route::page('/librarian', 'Bookshelf/librarian', ['signedIn' => true]);
```

**`application/views/Bookshelf/librarian.pug`**:

```pug
extends ../default/master/site

block content
  section.cq-hero.cq-hero--page
    h1.cq-display Ask the librarian

  section.cq-band.cq-band--tight
    .cq-inner.cq-inner--narrow
      ul#answers.cq-rows
      p#error.cq-alert.cq-alert--error(role='alert', hidden)
      form#ask(method='POST')
        .cq-field
          label(for='question') Your question
          input#question.form-control(type='text', name='question', required)
        button.btn.btn-primary(type='submit') Ask

  script(type='module', src="{$home}public/js/librarian.js")
```

**`public/js/librarian.js`**:

```js
import { askLibrarian, CapabilityError } from './capabilities.js'

const form = document.getElementById('ask')
const answers = document.getElementById('answers')
const error = document.getElementById('error')
const button = form.querySelector('button')
let conversation = ''   // the conversation id of the first answer: the next questions continue it

function add (who, text) {
  const row = document.createElement('li')
  row.className = 'cq-row'
  row.textContent = who + ': ' + text   // text, never HTML: the answer comes from a model
  answers.append(row)
}

form.addEventListener('submit', async (event) => {
  event.preventDefault()
  const question = form.elements.question.value.trim()
  if (!question) return
  error.hidden = true
  button.disabled = true
  add('You', question)
  try {
    const input = conversation ? { question, conversation } : { question }
    const answer = await askLibrarian(input)
    conversation = answer.conversation
    add('Librarian', answer.answer)
    form.reset()
  } catch (e) {
    error.textContent = e instanceof CapabilityError ? (Object.values(e.fields || {}).join(' ') || e.message) : 'Something went wrong.'
    error.hidden = false
  } finally {
    button.disabled = false
  }
})
```

Open `http://localhost:8080/librarian`, sign in, ask *Where is Kindred?* then *How many copies?*: both questions and
answers appear in the list, and the second answer knows the first.

### Step 5: Test it without a key

```bash
docker compose exec dev-box php caligrafer.php test make AskLibrarian
```

Replace **`tests/AskLibrarianTest.php`** with:

```php
<?php

use Caligrafy\Assistant;
use Caligrafy\Testing\TestCase;

/**
 * php caligrafer.php test AskLibrarian
 */
final class AskLibrarianTest extends TestCase
{
    public function testItAnswersAndKeepsTheConversation(): void
    {
        // a stand-in for the OpenAI assistant: no request leaves the computer
        $this->fake(Assistant::class, new class extends Assistant {
            public function start() { $this->thread_id = 'conv_test'; return $this; }
            public function run($additional_instructions = '', $instructions = null, $tools = [], $model = '', $metadata = null)
            {
                $this->status = 'completed';
                $this->response_text = 'Kindred is on shelf B.';
                return $this;
            }
        });

        $answer = $this->call('ask_librarian', array('question' => 'Where is Kindred?'), $this->user(1));

        $this->assertSame(array('conversation' => 'conv_test', 'answer' => 'Kindred is on shelf B.'), $answer);
    }

    public function testItNeedsAQuestion(): void
    {
        $this->assertCapabilityFails('invalid', 'ask_librarian', array(), $this->user(1));
    }
}
```

```bash
docker compose exec dev-box php caligrafer.php test AskLibrarian
```

Expected: `OK (2 tests, 2 assertions)`.

**Check**
- `docker compose exec dev-box php caligrafer.php capabilities` lists `ask_librarian` (`ai:use`, read) and `index_catalog` (`ai:admin`, writes).
- An MCP `tools/list` does not show `index_catalog`.
- `docker compose exec dev-box php caligrafer.php call ask_librarian question=x conversation="conv/../x"` is refused: *The Conversation field may
  only contain letters, numbers, dashes and underscores*.
- The page shows the answers as plain text.

## Reference

### `new Assistant($parameters = array())`

Creating an assistant calls nothing on OpenAI, unless you give it files.

| Parameter | Default | What it is |
|---|---|---|
| `name` | none | the name (also the name of its vector store) |
| `description` | none | kept in the object only |
| `instructions` | none | the system prompt sent with every answer |
| `model` | `ASSISTANT_DEFAULT_MODEL` (`gpt-6-luna`, or `OPEN_AI_MODEL`) | `ASSISTANT_GPT6_LUNA`, `ASSISTANT_GPT6_SOL`, `ASSISTANT_GPT6_ASTRA` |
| `tools` | `array(['type' => 'file_search'])` | add `['type' => 'code_interpreter']` to let it run code on the files |
| `metadata` | none | up to 16 string pairs, sent with the conversation and every answer |
| `file_paths` | none | local files: uploaded and indexed in a new vector store at once |
| `file_ids` | none | files already on OpenAI: indexed in a new vector store at once |
| `vector_store_id` | `''` | an existing vector store: reuse its files without uploading them again |

`file_search` gets `vector_store_ids` = the assistant's store (it is left out when there is no store);
`code_interpreter` gets `container: {type: auto, file_ids}`; the old tool name `retrieval` becomes `file_search`.

### Methods

| Method | Chainable | What it does |
|---|---|---|
| `start()` | yes | creates a conversation (`POST /v1/conversations`): `thread_id` = `conv_...` |
| `createMessage($content, $file_ids = [], $metadata = null, $role = "user")` | yes | queues a message for the next `run()`; `$role`: user, assistant, system or developer; `$file_ids` go to the code interpreter; `$metadata` is not used |
| `run($additional_instructions = '', $instructions = null, $tools = [], $model = '', $metadata = null)` | yes | sends the queued messages (`POST /v1/responses`) and waits for the answer; the arguments override the settings for this answer only |
| `retrieveResponse($timeout = 120, $interval = 2)` | yes | for version 1 code: polls only while the answer is `queued` or `in_progress` |
| `end()` | yes | deletes the conversation |
| `retrieve()` | yes | does nothing (version 1 code) |
| `text()` | no | the text of the last answer (`response_text`) |
| `listMessages()` | no | the items of the conversation stored on OpenAI |
| `uploadAssistantFiles($specified_paths = [])` | no | uploads files, adds them to the vector store (creates it when there is none), returns their ids |
| `deleteAssistantFile($file_id)` | no | removes a file from the store and deletes it on OpenAI; `true` when deleted |
| `delete()` | no | deletes the vector store: `true` when deleted (otherwise the assistant itself) |

### Properties

| Property | What it holds |
|---|---|
| `name`, `description`, `instructions`, `tools`, `metadata` | the settings (public: change them after creation) |
| `file_ids`, `file_paths`, `vector_store_id` | the files and their store |
| `thread_id` | the conversation id (`conv_...`): set it to continue a conversation |
| `run_id` | the last answer id (`resp_...`) |
| `status` | the last answer's status: `completed`, `failed`, `incomplete`... |
| `messages` | the messages of this object: `['id', 'role', 'content' => [['type' => 'input_text'|'output_text', 'text']]]` |
| `response_text` | the text of the last answer |
| `last_response` | the last raw answer from OpenAI, with `error.message` when it failed |
| `assistant_id` | not used (version 1) |

## Migrating from version 1

| Version 1 (Assistants API) | Version 2 (Responses + Conversations) |
|---|---|
| `new Assistant([...])` created an assistant on OpenAI | nothing is created: the settings live in the object |
| `assistant_id` | not used: keep the name, instructions, model and tools in your code |
| thread (`thread_id`) | conversation (`thread_id` holds the `conv_...` id) |
| run (`run_id`) | response (`run_id` holds the `resp_...` id) |
| `run()` then `retrieveResponse()` | `run()` returns with the answer; `retrieveResponse()` only waits for background answers |
| `messages` held thread messages (`content[0]['text']['value']`) | `['role', 'content' => [['type', 'text']]]`; use `text()` for the last answer |
| files attached to the assistant | files indexed in a vector store (`vector_store_id`) |
| `retrieval` tool | `file_search` (`retrieval` is still accepted and converted) |

Threads of version 1 can no longer be read. To keep a history, send the stored messages with `createMessage()` before
the first `run()` of a new conversation.

## Other ways

**In a controller.** `$assistant->start()->createMessage('Hi')->run()->text()` works in any controller action, with the
conversation id kept in the session. It serves that one route only, and a REST client or an agent has no session: keep
the assistant in a capability and pass the conversation id, as above.

**Plain chat without OpenAI's memory.** `OpenAI::delegate()` with the earlier messages in `$context` (see the
[OpenAI page](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.4-OpenAI:-ChatGPT,-GPTs,-DALL.E)) keeps the history
on your side, without conversations or files on OpenAI.

## Common mistakes

+ **Expecting the answer in `messages[...]['content'][0]['text']['value']`** (version 1). Use `text()`.
+ **Polling in a loop after `run()`.** `run()` already waits for the answer.
+ **Uploading the files on every question.** Upload once (`index_catalog`), keep the `vector_store_id`, pass it next time.
+ **`alpha_dash` for the conversation id.** In GUMP it refuses digits: use `alpha_numeric_dash`.
+ **Trusting a conversation id from anyone.** Anyone who has an id can continue that conversation: ids are long and
  random, but do not put secrets in a conversation that several people share.
+ **A missing key.** `start()` leaves `thread_id` empty and `run()` ends with `status` `failed`: check them, and run
  `docker compose exec dev-box php caligrafer.php doctor --only openai`.
