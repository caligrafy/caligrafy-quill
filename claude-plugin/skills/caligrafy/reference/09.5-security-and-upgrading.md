# 9.5 Security and Upgrading

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.5-Security-and-Upgrading
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

This page explains how Caligrafy protects your application, what you need to check before going to production and how to bring an existing project up to date with the security fixes of the framework.

## Production checklist

+ **Server files are not served.** `curl -I http://<your-host>/.env` must answer `403` or `404`. The `.htaccess` files of Caligrafy deny the dotfiles, the server-side folders and the tooling files, and prevent the execution of scripts in `public/uploads`. Keep them, allow them with `AllowOverride All`, or write equivalent rules for nginx. Learn more [here](https://github.com/caligrafy/caligrafy-quill/wiki/1.-Getting-Started#protecting-your-server-files).
+ **`APP_ENV=production`** on the production server (Stripe production keys, Google Analytics) and **`APP_DEBUG=false`**.
+ **Keys:** generate an `APP_KEY` and an `API_KEY` for every environment and never commit `.env`. All the API keys generated from an `APP_KEY` are equivalent: change the `APP_KEY` to revoke them (this also logs every user out).
+ **The `API_KEY` is not a secret in the browser:** Caligrafy gives it to the Vue apps that it serves. Protect private data and actions with authentication (`authorized()`, `guard()`), not with the API key alone.
+ **Administrators:** the user administration pages require `permissions >= 1`. New users have `0`. Promote administrators in the database.
+ **AI routes:** the example OpenAI routes call a paid API for anyone who can reach them. Protect them or remove them.
+ **Queries:** use `?` placeholders for every value that comes from a user: `all(['condition' => 'WHERE author = ?', 'bindings' => [$author]])`, `search()` (always bound) or `Database::execute($sql, [$value])`. Never concatenate request data into SQL.
+ **Uploads:** validate files with `check()` and save them with `uploadFile($file, ['png', 'jpg'])`. Scripts, HTML and SVG files are always refused.
+ **Forms:** every `POST`, `PUT` and `DELETE` form needs `=csrf()`.

## What the framework does for you

| Threat | Protection |
| - | - |
| Downloading `.env`, `.git` or source files | `.htaccess` denies dotfiles, `application`, `framework`, `vendor`, `tests`, `qa`, `docker`, `claude-plugin`, `caligrafer.php`, `composer.*`, `docker-compose.yaml` and `.sql`/`.log`/`.ini`/`.sh`/`.env` files |
| Uploading and running a PHP file | `uploadFile()` only accepts an allow-list of extensions and `public/uploads/.htaccess` denies scripts |
| SQL injection | `find()`, `create()`, `update()`, `delete()`, `search()`, the relationships and `all()` with `bindings` use bound parameters. Column names are validated |
| Cross-Site Request Forgery | Form requests must carry the session `_token` (`=csrf()`) |
| Cross-site scripting through Vue apps | The `env` given to Vue apps is escaped: URL parameters cannot inject code |
| Loading arbitrary files through client apps | `?app=` and the app folder only accept letters, digits, `-` and `_`, and only files of `public/<app>/` are served |
| Stolen password database | The authentication module stores `password_hash()` hashes |
| Choosing a secret through a form | The OpenAI example controller only accepts the documented commands and types (`OpenAI::command()`, `OpenAI::type()`) |

## Upgrading an existing project

Updating Caligrafy updates the `framework` folder. The `application` folder, however, was copied from `framework/settings/application` when your project was initialized: the authentication module, the client app view and the example controllers that live there are **your** copies and need to be updated by hand.

**1. Update the framework**
```bash
git pull   # or: composer update / download the new release
```

**2. Copy the root and uploads `.htaccess` files** from the new release (keep your own additions). Then check that `.env` is no longer served: `curl -I http://<your-host>/.env`.

**3. Update the files of your `application` folder** that you have not customized, from `framework/settings/application`:

| File | Why |
| - | - |
| `views/Client/app.pug` | Path traversal through `?app=` and script injection through URL parameters (**required** if you use Vue, bot, FaceDetect or ML apps) |
| `controllers/core/AI/ClientController.php` | Validates the `?app=` parameter |
| `controllers/core/AI/AIController.php` | The previous version let a form select any PHP constant, including your `.env` secrets (**required** if the `/ai` routes are enabled) |
| `controllers/core/Auth/AuthController.php` and `AdminController.php` | Password hashing, exact username lookup (the previous login accepted `%` as a username), admin pages restricted to `permissions >= 1` |
| `models/Auth/User.php` | `findByUsername()`, `hashPassword()`, `verifyPassword()`, `needsRehash()` used by the controllers above |
| `views/Auth/login.pug`, `register.pug`, `manageusers.pug` | Passwords of up to 72 characters |
| `models/Auth/create_db.sql` | No longer drops the `users` table |

If you customized these files, apply the same changes to your versions: compare them with the new files of `framework/settings/application`.

**4. Upgrade the `users` table** (authentication module):
```sql
ALTER TABLE users MODIFY passcode varchar(255) NOT NULL;
```
Existing users keep logging in with their passwords: their passcode is converted to a hash on their next login. Keep the same `APP_KEY` until they have all logged in once.

**5. Promote your administrators**: `UPDATE users SET permissions = 1 WHERE username = '...';`

**6. Review the behavior changes below** in your own code.

## Behavior changes

| Area | Before | Now |
| - | - | - |
| `create()`, `update()`, `save()` | `0`, `''` and `false` were silently dropped | They are saved. Only `null` is skipped |
| `all()` | Raw clauses only | Raw clauses plus `bindings` for `?` placeholders |
| `search()` | Keywords inserted in the SQL | Keywords bound. Invalid column names throw an exception |
| `belongsToMany()` | Pivot creation failed with `INT UNSIGNED` ids or with a second pivot | Pivot columns copy the id type and constraint names are unique |
| `DB_PORT` | Ignored | Used, unless `DB_HOST` contains `;port=` |
| `session()`, `scripts()`, `keywords()`, `copyright()`, `metadata()` | Ignored `0`, `''` and `false` | Store them |
| `endWith()` | Only compared the last character | Compares the whole needle |
| `httpRequest()` | Only sent a body for `POST` | Sends it for every method except `GET` |
| `uploadFile()` | Accepted any extension | Allow-list (`DEFAULT_UPLOAD_EXTENSIONS` or your own list) |
| CSRF | An empty `APPROVED_AGENTS` approved requests without a User-Agent | Empty entries are ignored |
| `Payment::createCheckout()` | Crashed with a locale or a customer email | Works |
| `OpenAI` `COMPLETE` | Dropped the text after `[insert]` | Sends it |
| `GPT4OMINI`, `ASSISTANT_GPT4OMINI` | `gpt-4o mini` (invalid) | `gpt-4o-mini` |
| `Assistant::run()` | Always sent an empty model and no tools, disabling `file_search` | Only sends the overrides that are given |
| `Assistant::retrieveResponse()` | Could wait forever | Gives up after `$timeout` seconds (120) |
| `caligrafer initialize` | Generated new keys on every run | Keeps the keys of a signed project |
| Authentication | Reversible passcodes, any user could manage users | Hashed passwords (8 to 72 characters), administrators need `permissions >= 1` |
| `APP_DEBUG=false` | Still turned the SMTP debug output on (`.env` values are strings) | Parsed as a boolean |
| Bot app | Loaded the latest Vue from a CDN | Pins Vue 2.7.16 |

## Testing the framework

Caligrafy comes with a QA suite that runs the framework, HTTP and tooling tests in an isolated Docker stack (ports 8090 and 3316, so it never clashes with your development server). From a clean checkout of the framework:
```bash
composer install
./qa/run.sh
```
The suite refuses to run when an `application` folder or a `.env` file that it did not create is present.
