# 9.5 Security and Upgrading

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.5-Security-and-Upgrading
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

This page explains how Caligrafy protects your application, what you need to check before going to production and how to bring an existing project up to date with the security fixes of the framework.

## Production checklist

+ **Server files are not served.** `curl -I http://<your-host>/.env` must answer `403` or `404`. The `.htaccess` files of Caligrafy deny the dotfiles, the server-side folders and the tooling files, and prevent the execution of scripts in `public/uploads`. Keep them (they need `mod_rewrite` and `AllowOverride FileInfo` or `All`), or write equivalent rules for nginx. Learn more [here](https://github.com/caligrafy/caligrafy-quill/wiki/1.-Getting-Started#protecting-your-server-files).
+ **`APP_ENV=production`** on the production server (Stripe production keys, Google Analytics) and **`APP_DEBUG=false`**.
+ **Keys:** generate an `APP_KEY` and an `API_KEY` for every environment and never commit `.env`. All the API keys generated from an `APP_KEY` are equivalent: change the `APP_KEY` to revoke them (this also logs every user out).
+ **The `API_KEY` is not a secret in the browser:** Caligrafy gives it to the Vue apps that it serves. Protect private data and actions with authentication (`authorized()`, `guard()`), not with the API key alone.
+ **Administrators:** the user administration pages require `permissions >= 1`. New users have `0`. Promote administrators in the database.
+ **AI routes:** the example OpenAI routes call a paid API for anyone who can reach them. Protect them or remove them.
+ **Queries:** use `?` placeholders for every value that comes from a user: `all(['condition' => 'WHERE author = ?', 'bindings' => [$author]])`, `search()` (always bound) or `Database::execute($sql, [$value])`. Never concatenate request data into SQL.
+ **Uploads:** validate files with `check()` and save them with `uploadFile($file, ['png', 'jpg'])`. Scripts, HTML and SVG files are always refused.
+ **Forms:** every `POST`, `PUT` and `DELETE` form needs `=csrf()`.
+ **Health check:** run `php caligrafer.php doctor --env .env.production` (or `doctor` on the server): Stripe must report live mode and every configured service `OK`.

## What the framework does for you

| Threat | Protection |
| - | - |
| Downloading `.env`, `.git` or source files | `.htaccess` denies dotfiles, `application`, `framework`, `vendor`, `tests`, `qa`, `docker`, `claude-plugin`, `caligrafer.php`, `composer.*`, `docker-compose.yaml` and `.sql`/`.log`/`.ini`/`.sh`/`.env` files |
| Uploading and running a PHP file | `uploadFile()` only accepts an allow-list of extensions and `public/uploads/.htaccess` denies scripts |
| SQL injection | `find()`, `create()`, `update()`, `delete()`, `search()`, the relationships and `all()` with `bindings` use bound parameters. Column names are validated |
| Cross-Site Request Forgery | Form requests must carry the session `_token` (`=csrf()`) |
| Cross-site scripting through Vue apps | The `env` given to Vue apps is escaped: URL parameters cannot inject code |
| Loading arbitrary files through client apps | `?app=` and the app folder only accept letters, digits, `-` and `_`, and only files of `public/<app>/` are served |
| Stolen password database | The authentication module stores `password_hash()` hashes |
| Choosing a secret through a form | The OpenAI example controller only accepts the documented commands and types (`OpenAI::command()`, `OpenAI::type()`) |

## Upgrading an existing project

> **New projects have nothing to do.** A project created or cloned with this release (`composer create-project`, `git clone` + `caligrafer initialize`) already gets the updated `application` files and `.htaccess` files. This section only applies to projects initialized with an earlier version of Caligrafy.

Updating Caligrafy updates the `framework` folder. The `application` folder, however, was copied from `framework/settings/application` when your project was initialized: the authentication module, the client app view and the example controllers that live there are **your** copies.

### Recommended: `php caligrafer.php upgrade`

After updating the framework (step 1 below), let Caligrafer compare your `application` folder with the new templates:

```bash
php caligrafer.php upgrade            # dry run: prints the plan, changes nothing
php caligrafer.php upgrade --apply    # applies it
php caligrafer.php upgrade --force application/views/Auth/login.pug   # replaces one customized file
```
(`.bin/caligrafer upgrade [--apply] [--force <path>]` works too.)

Every file of `framework/settings/application` is reported as:

| Status | Meaning | With `--apply` |
| - | - | - |
| `missing` | new in the framework | copied into `application/` |
| `identical` | already up to date | nothing |
| `outdated` | an older template that you never changed | replaced |
| `customized` | you changed it | **kept**; the new version is written next to it as `<file>.caligrafy-new` for you to merge (or replace it with `--force`) |
| `routes` | `config/routing/web.php` holds your routes | never replaced |

- Every replaced file is first backed up under `backups/caligrafy-upgrade-<timestamp>/` (same paths). `.env`, `public/uploads`, `vendor` and the files you created in `application/` are never touched.
- If your `web.php` still ends with `echo $e->getMessage();`, `--apply` patches the `catch` block to `Errors::handle($e);` (and adds `use Caligrafy\Errors;`) after a backup.
- `initialize` and `upgrade --apply` write `application/.caligrafy-manifest.json` (the hash of each template file as copied): commit it with your project, it is how the next upgrade tells untouched files from customized ones. Projects without a manifest are compared with the template versions of the previous releases (`framework/settings/template-history.json`).
- Client apps created with `php caligrafer.php app|bot|facedetect|ml` are listed with the files that differ from `framework/plugins/<type>`; they are never modified.

Then run `php caligrafer.php doctor` (read-only) to check `.env`, the database and the configured services (see [Caligrafer](1.-Getting-Started#doctor)), run the database steps 4 and 5 below and review the behavior changes. The manual steps below remain the fallback (and the list of what changed).

### Manual upgrade

**1. Update the framework**
```bash
git pull   # or: composer update / download the new release
```

**2. Copy the root and uploads `.htaccess` files** from the new release (keep your own additions). Then check that `.env` is no longer served: `curl -I http://<your-host>/.env`.

**3. Update the files of your `application` folder** that you have not customized, from `framework/settings/application` (`php caligrafer.php upgrade` does this step for you):

| File | Why |
| - | - |
| `views/Client/app.pug` | Path traversal through `?app=` and script injection through URL parameters (**required** if you use Vue, bot, FaceDetect or ML apps) |
| `controllers/core/AI/ClientController.php` | Validates the `?app=` parameter |
| `controllers/core/AI/AIController.php` | The previous version let a form select any PHP constant, including your `.env` secrets (**required** if the `/ai` routes are enabled) |
| `controllers/core/Auth/AuthController.php` and `AdminController.php` | Password hashing, exact username lookup (the previous login accepted `%` as a username), admin pages restricted to `permissions >= 1` |
| `models/Auth/User.php` | `findByUsername()`, `hashPassword()`, `verifyPassword()`, `needsRehash()` used by the controllers above |
| `views/Auth/login.pug`, `register.pug`, `manageusers.pug` | Passwords of up to 72 characters |
| `models/Auth/create_db.sql` | No longer drops the `users` table |
| `controllers/core/AI/*.php`, `controllers/core/Auth/*.php` | The example controllers are declared in the `Caligrafy\Controllers` namespace, so a controller of yours with the same name (`AIController`...) no longer collides with them. Your routes do not need to change: short names such as `'ClientController'` fall back to `Caligrafy\Controllers` |
| `config/routing/web.php` | The `catch` at the end calls `Errors::handle($e);` instead of `echo $e->getMessage();` (add `use Caligrafy\Errors;`), so API clients get JSON errors. Without this change the status codes are still correct but the body stays plain text |

If you customized these files, apply the same changes to your versions: compare them with the new files of `framework/settings/application`.

**4. Upgrade the `users` table** (authentication module):
```sql
ALTER TABLE users MODIFY passcode varchar(255) NOT NULL;
```
Existing users keep logging in with their passwords: their passcode is converted to a hash on their next login. Keep the same `APP_KEY` until they have all logged in once.

**5. Promote your administrators**: `UPDATE users SET permissions = 1 WHERE username = '...';`

**6. Review the behavior changes below** in your own code.

## Behavior changes

| Area | Before | Now |
| - | - | - |
| `create()`, `update()`, `save()` | `0`, `''` and `false` were silently dropped | They are saved. Only `null` is skipped, and only the columns of the table are written (helper properties of a model are ignored) |
| `all()` | Raw clauses only | Raw clauses plus `bindings` for `?` placeholders |
| `search()` | Keywords inserted in the SQL | Keywords bound. Invalid column names throw an exception |
| `belongsToMany()` | Pivot creation failed with `INT UNSIGNED` ids or with a second pivot | Pivot columns copy the id type and constraint names are unique |
| `DB_PORT` | Ignored | Used, unless `DB_HOST` contains `;port=` |
| `session()`, `scripts()`, `keywords()`, `copyright()`, `metadata()` | Ignored `0`, `''` and `false` | Store them |
| `endWith()` | Only compared the last character | Compares the whole needle |
| `httpRequest()` | Only sent a body for `POST` | Sends it for every method except `GET` |
| `uploadFile()` | Accepted any extension | Allow-list (`DEFAULT_UPLOAD_EXTENSIONS` or your own list) |
| CSRF | An empty `APPROVED_AGENTS` approved requests without a User-Agent | Empty entries are ignored |
| `Payment::createCheckout()` | Crashed with a locale or a customer email | Works |
| `OpenAI` `COMPLETE` | Dropped the text after `[insert]` | Sends it |
| `GPT4OMINI`, `ASSISTANT_GPT4OMINI` | `gpt-4o mini` (invalid) | `gpt-4o-mini` |
| `Assistant::run()` | Always sent an empty model and no tools, disabling `file_search` | Only sends the overrides that are given |
| `Assistant::retrieveResponse()` | Could wait forever | Gives up after `$timeout` seconds (120) |
| `caligrafer initialize` | Generated new keys on every run | Keeps the keys of a signed project |
| Authentication | Reversible passcodes, any user could manage users | Hashed passwords (8 to 72 characters), administrators need `permissions >= 1` |
| `APP_DEBUG=false` | Still turned the SMTP debug output on (`.env` values are strings) | Parsed as a boolean |
| Bot app | Loaded the latest Vue from a CDN | Pins Vue 2.7.16 |
| Error responses | HTTP `200` for every error, including PHP fatal errors, with `[ERROR ...]` text | Real status codes: `401` (1004, API key), `403` (3000, CSRF), `404` (1001, controller or action), `405` (1000), `500` (other errors, PHP fatal errors and uncaught exceptions, message only with `APP_DEBUG=true`). API calls get `{"error": {"code": ..., "message": ...}}`. **Clients that expected `200` on errors must check the status** (axios and `fetch().ok` now treat them as failures) |
| Controller names | The example controllers of `application/controllers/core/` were global classes: a controller of yours named `AIController`, `AdminController`, `AuthController`, `ClientController` or `WatsonController` was a fatal error (`Cannot redeclare class`) on every page | They are in `Caligrafy\Controllers`. Routes accept fully qualified controllers (`'Shop\OrderController@show'`, leading `\` allowed); a short name that is not a declared class falls back to `Caligrafy\Controllers`, so old routes keep working and your own class of the same name wins. If your code referenced an example class directly (`new AuthController()`, `extends AIController`), use `Caligrafy\Controllers\...` |
| Relationships with namespaced models | The default foreign key of `hasOne`, `hasMany`, `belongsToMany` included the namespace | Uses the short class name (`Shop\Order` gives `order_id`) |
| Client apps (`?app=`) | Any path, including sub-folders and `../` | A file name of `public/<app>/` only (letters, digits, `-`, `_`): no sub-folders, no symbolic links pointing outside the app |

## Upgrading to the current libraries (October 2026)

This release moves Caligrafy to current versions of every library and service. As with the security fixes, **new projects get everything automatically**; existing projects follow the steps below.

**1. Requirements:** PHP 8.3 or higher (the Docker image uses PHP 8.5), MySQL 8.4, Node.js 20.19+ or 22.12+ for the Vue SPA template. Run `composer update` after pulling the framework.

**2. `.env`:** add the new settings when you use the matching module (see `framework/settings/.env.example`):

| Setting | Module |
| - | - |
| `COINBASE_API_KEY_NAME`, `COINBASE_API_KEY_SECRET` (replace `CRYPTO_PAY_KEY`) | Crypto payments (Coinbase Business) |
| `WATSON_URL` (required), `WATSON_ENVIRONMENT_ID`, `WATSON_API_VERSION` | Watson bots |
| `OPEN_AI_MODEL`, `OPEN_AI_IMAGE_MODEL` (optional) | OpenAI and Assistants |
| `GROQ_MODEL`, `GROQ_VISION_MODEL` (optional) | Groq agents |
| `PWA_SERVICE_WORKER` (optional, `false` by default) | Offline page of installed apps ([Views](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#install)) |

**3. Views (Bootstrap 5):** the layout now loads Bootstrap 5.3 instead of Bootstrap 3.3.7, and no jQuery. Copy the new views of `framework/settings/application/views` (at least `default/master/layoutblocks.pug`, `default/modules/messaging.pug`, `default/modules/cryptopayment.pug`, `default/pages/payment.pug`, `default/pages/checkout.pug` and the `Auth` views) and delete `default/modules/gestures.pug`. Replace `default/modules/install.pug` (add-to-homescreen) with the new one and add `default/modules/serviceworker.pug` (`php caligrafer.php upgrade --apply` does both when you never changed them). If you customized `layoutblocks.pug`, add `meta(name='theme-color', content='#ffffff')` and `link(rel='manifest', href="{$home}public/manifest.webmanifest")` to the headers, and `include ../modules/serviceworker` then `if $install` / `include ../modules/install` after `include ../modules/standalone` (see [install to home screen](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#install)). If you customized the root `.htaccess`, copy its `Service-Worker-Allowed` lines and the `AddType application/manifest+json .webmanifest` block. Update `public/css/theme.css` too: its end keeps the Caligrafy black and white look on Bootstrap 5 (14px text, cards, black `btn-primary`, white `btn-secondary` with black text, black focus rings, readable `a.btn` links). It also keeps the Bootstrap 3 layout: full-width page container, header title centered in the header, grids centered in their wrapper, Caligrafy card borders and colors, Bootstrap 3 text color and button metrics. If you customized `theme.css`, copy everything from the "Bootstrap 5 compatibility layer" comment to the end of the file. Its heading margins apply to `body.caligrafy-layout` (and `body#gesturize`, so older copies of `default/master/layout.pug` keep their look): add `class='caligrafy-layout'` to the body of your own layouts. Client apps that reuse the Caligrafy header can replace a custom `margin: 20px 0 10px` on the header title with the class `caligrafy-header` on the header. In your own views, wrap Bootstrap columns in a `.row` and move them one breakpoint up (`col-sm-6` becomes `col-md-6`, `col-md-4` becomes `col-lg-4`, see [Views](7.-Views)). Single page apps created before October 2026 load Bootstrap 3 and jQuery from their `index.html`: replace those three tags with `https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css` and `https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js` and update the columns of their components the same way. To keep Bootstrap 3 in a project for now, add to `application/config/config.php`:
```php
scripts('bootstrap_css', 'https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/css/bootstrap.min.css');
scripts('bootstrap_script', 'https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/js/bootstrap.min.js');
scripts('bootstrap_jquery', 'https://cdn.jsdelivr.net/npm/jquery@3.7.1/dist/jquery.min.js');
```

**4. Client apps in `public/`:** apps created with Caligrafer are copies. Update their markup to `scripts('vue')` and `scripts('axios')` (pinned versions), and re-create or compare the bot, FaceDetect and ML apps with `framework/plugins`. The shared services (`public/js/services/detect.js`, `mlcore.js`, `face-api.min.js`, `stripe_client.js`) and the models in `public/resources/models` are updated with the framework.

**5. Code that calls the changed APIs:** see the table below.

| Area | Before | Now |
| - | - | - |
| PHP | 7.2+ | 8.3+; deprecation notices are never printed into pages |
| Composer | `dev-master` branches | Stable releases: stripe-php 22, Phug 2, Pug-php 3.6, PHPMailer 7, phpdotenv 5.8, GUMP 2.3, SimpleImage 4.4, groq-php 1.4 |
| Bootstrap / jQuery | Bootstrap 3.3.7 + jQuery 1.12 | Bootstrap 5.3.8, no jQuery (jQuery 4 only for Summernote) |
| Add to home screen | add-to-homescreen.js 3.2.3 (`$install`, `add_to_home` scripts keys) | Web app manifest `public/manifest.webmanifest` linked by the layout, `'install' => true` shows an Install button (`beforeinstallprompt`) or the iOS Share hint, optional offline service worker `PWA_SERVICE_WORKER=true` ([Views](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#install)) |
| Hammer.js gestures | Included in the layout | Removed |
| OpenAI text | `gpt-3.5-turbo` (shut down) with temperature/max_tokens defaults | `gpt-6-luna`, only the model is sent by default |
| OpenAI images | DALL.E (shut down), URLs | `gpt-image-2`, base64 in `b64_json` |
| `Assistant` | Assistants API (shut down Aug 26, 2026) | Responses + Conversations APIs, same methods, vector stores for files ([details](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.5-Open-AI:-Assistants#migrating)) |
| Stripe Checkout | `sessionId` + `redirectToCheckout` (removed) | Redirect to `$result['url']` |
| Stripe card form | Card Element | Payment Element (`stripe.confirmPayment`) |
| `createCheckout()` | `payment_method_types` = `['card']` | Payment methods from the Stripe dashboard (current API versions reject the parameter) |
| `CryptoPayment` | Coinbase Commerce (shut down Mar 31, 2026) | Coinbase Business Checkouts with CDP keys; `$transaction['url']` |
| Groq `Agent` | Llama 3.x defaults (retired) | `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` (vision), `whisper-large-v3` |
| Watson | URL of a fixed instance, version 2021-11-27 | `WATSON_URL`, optional environment, version 2024-08-25 |
| Bot client | BotUI + Vue 2 | Vue 3 chat; `pause` actions call `window.executeBotAction(context)` |
| FaceDetect | face-api.js 0.22 (abandoned) | @vladmandic/face-api 1.7.15; MTCNN removed; `detector.ready` promise; `{ autoStart: false }` + `startStream()` (rejects with camera errors, `streamError`), `stopStream()`, `faceprint()` |
| ML Core | ml5 0.12 (poseNet, uNet) + p5 0.9 | ml5 1.4 (bodyPose, bodySegmentation) + p5 2.3; callbacks receive `(results, error)`; the previous pose shape is kept |
| Vue SPA template | Vite 7, Vuex, ESLint 9 legacy config | Vite 8, Vue Router 5, Pinia, ESLint 10 flat config |
| Docker | php:8.2.2, mysql:latest, phpmyadmin:latest | php:8.5-apache, mysql:8.4, phpmyadmin:5.2.3 |

## Testing the framework

Caligrafy comes with a QA suite that runs the framework, HTTP and tooling tests in an isolated Docker stack (ports 8090 and 3316, so it never clashes with your development server). From a clean checkout of the framework:
```bash
composer install
./qa/run.sh
```
The suite refuses to run when an `application` folder or a `.env` file that it did not create is present. Its stack includes stripe-mock, and the OpenAI, Coinbase, Groq and Watson integrations are tested against local mock servers, so no API key is needed.

The suite also runs the PHPUnit unit tests of the framework core (`qa/unit`: routing, errors, requests, models, validation, upgrade and doctor helpers). They need no web server, database or `.env`, so you can run them on their own with the development dependencies installed:
```bash
composer install
vendor/bin/phpunit
```
