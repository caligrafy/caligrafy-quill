# 9.5 Security and Upgrading

> Source: Caligrafy Quill wiki - https://github.com/caligrafy/caligrafy-quill/wiki/9.5-Security-and-Upgrading
> Bundled with the caligrafy-quill Claude plugin. Content preserved from the wiki; formatting cleaned.

This page has two parts: the settings an application needs before it goes online, with what the framework protects by
itself, and how to bring an existing project to a new release of Caligrafy Quill (`php caligrafer.php update`).

## With Claude

| You want | Ask |
|---|---|
| to know whether the project is ready for production | `/caligrafy-quill:deploy` (a read-only check: Dockerfile, `composer.lock`, scripts safe to run again, no secrets in git, `APP_DEBUG=false` online) |
| a review of your code for security mistakes | "review my code" (the `caligrafy-reviewer` agent: SQL built from input, CSRF, uploads, exposed secrets...) |
| the latest release | `/caligrafy-quill:update` (or `/caligrafy-quill:update 2.19.0`) |

`/caligrafy-quill:update` runs `php caligrafer.php update --check`, shows you what it changes, runs
`php caligrafer.php update`, merges each `<file>.caligrafy-new` into your version, then runs `version`, `doctor`,
`upgrade --local` and `platform install`, and checks the sign-in flows and the forms. It commits only with your OK.

**Check**

+ `php caligrafer.php version` prints the new version.
+ `find . -name '*.caligrafy-new' -not -path './vendor/*' -not -path './backups/*'` prints nothing.
+ `php caligrafer.php doctor` has no `FAIL`.
+ Sign in, sign out, sign up and one form work from a private window.

## By hand: the production settings

**1. The production `.env`.** Online, the app reads its own `.env` (on Caligrafy Cloud the database settings and keys
are written for you; set the rest with `php caligrafer.php cloud secret set <app> KEY=value`). Give it:

```text
APP_ROOT=
APP_ENV=production
APP_PROTOCOL=https
APP_DEBUG=false
APP_URL=https://bookshelf.example.com
LEGACY_API_KEY=false
DB_ACTIVATE=true
```

and its own `APP_KEY` and `API_KEY`: `php caligrafer.php generatekeys` prints a new pair. Never reuse your computer's
keys, never commit a `.env`.

| Setting | Why |
|---|---|
| `APP_ENV=production` | the live Stripe keys, Google Analytics, the class map's production checks |
| `APP_DEBUG=false` | errors show no details to visitors, and Phug's debug mode is off: pages about three times faster (2.19.0) |
| `APP_PROTOCOL=https` | the links the app builds start with `https://` |
| `APP_URL` | the links of emails sent by jobs, the return addresses of payments, `og:url` |
| `LEGACY_API_KEY=false` | only personal access tokens open the API (Caligrafy Cloud sets it) |

**2. Leave the speed settings as they are.** They are on by default; each has a setting that turns it off, for when
something breaks:

| On by default | What it does | Turned off by |
|---|---|---|
| the views cache | each Pug view is compiled to PHP once, again only when it or a file it includes changes (2.17.0) | `VIEW_CACHE=false` |
| the Phug Optimizer | a compiled view runs without building Phug's compiler (2.19.0) | `VIEW_OPTIMIZER=false` |
| lazy sessions | a `GET` without a session cookie gets a session only when it needs one (2.19.0) | `SESSION_LAZY=false` |
| the class map | each class of `application/` is loaded when first used (2.18.0) | `CLASS_MAP=false` |
| `.env.php` | the settings are read from `.env.php` instead of parsing `.env` (2.19.0) | `php caligrafer.php env clear` |

**3. Compile `.env`.** With the production image (Caligrafy Cloud, Coolify, Docker), the deploy step does it at every
start: nothing to do. On a server without the image, run after each change to `.env`:

```bash
php caligrafer.php env cache
```
```text
 .env compiled to .env.php: pages read it without parsing .env (php caligrafer.php env clear removes it)
```

`.env.php` is used only while `.env` is exactly what it was compiled from: an edited `.env` is read as it is (slower,
still right) until the next `env cache`. `.gitignore` lists `.env.php`: never commit it.

**4. Check the server.** Run, with your address:

```bash
curl -I https://bookshelf.example.com/.env
curl -I https://bookshelf.example.com/caligrafer.php
```

Both must answer `403` or `404`. Then run `php caligrafer.php doctor` on the server (or `php caligrafer.php doctor
--env .env.production` on your computer): no `FAIL`, Stripe in live mode when the app takes payments.

**Check**

+ `APP_DEBUG=false`, `APP_ENV=production` and keys of their own in the production `.env`.
+ `.env`, `.env.php` and `caligrafer.php` are not served.
+ `git ls-files | grep -E '(^|/)\.env($|\.)' | grep -v '\.env\.example$'` prints nothing.

## By hand: upgrading an existing project

A project made with the current release has nothing to do. Updating moves the `framework/` folder and the release's
other files to the new version; the `application/` folder, copied from `framework/settings/application` when the
project was made, is **yours**, and `upgrade` brings its untouched files up to date.

The commands run in the Docker server of your project; without Docker, drop `docker compose exec dev-box`.

**1. Start from a clean state.** Run `git status --short`: commit what is there first, so that the update is one change
you can review.

**2. See what changes.**

```bash
docker compose exec dev-box php caligrafer.php update --check
```

It lists what it would replace, add and keep, the new settings and packages. Up to date, it prints
` Caligrafy Quill 2.19.0 is the latest: nothing to update. php caligrafer.php upgrade checks application/.`

**3. Update.**

```bash
docker compose exec dev-box php caligrafer.php update            # the latest release
docker compose exec dev-box php caligrafer.php update 2.19.0     # or a given one
```

Run it whole (not through `| tail`: it exits with `1` when something did not finish, and its last lines run
`upgrade --apply`). Everything it replaces is copied first to `backups/caligrafy-update-<from>-to-<to>-<time>/`.

**4. Merge every `.caligrafy-new`.** A file you changed is kept, with the release's version next to it:

```bash
find . -name '*.caligrafy-new' -not -path './vendor/*' -not -path './backups/*'
```

For each one, compare (`diff <file> <file>.caligrafy-new`), write the merged result into `<file>` (your changes plus the
release's new lines and fixes), then delete the `.caligrafy-new`.

**5. Check.**

```bash
docker compose exec dev-box php caligrafer.php version            # Caligrafy Quill <the new version>
docker compose exec dev-box php caligrafer.php platform install   # the framework tables of the new release; safe to run again
docker compose exec dev-box php caligrafer.php upgrade --local    # nothing outdated left in application/
docker compose exec dev-box php caligrafer.php doctor             # no FAIL
docker compose exec dev-box php caligrafer.php test               # when tests/ has tests
```

Then open the main pages, sign in, sign out and sign up, and send each form from a private window (no session cookie).
Read the release notes of every version you passed
(`https://github.com/caligrafy/caligrafy-quill/wiki/Release-notes:-<version>`) and do what they ask of projects.

**6. Commit and deploy.** Commit (`Caligrafy Quill <from> to <to>`), push, then `docker compose exec dev-box php caligrafer.php cloud deploy <app>`
(or the deploy of your own server). Delete `backups/` once you are done: git ignores it, the production image leaves
it out, and since 2.19.1 the root `.htaccess` refuses it too.

**Check**

+ `php caligrafer.php version` is the new version, here and online.
+ No `.caligrafy-new` file is left.
+ The sign-in flows and the forms work from a fresh session.

**From 2.18 to 2.19.** No new tables. Sessions start only when used: a page with a form must print `=csrf()`, and code
that reads `$_SESSION['token']` on a `GET` reads `session('token')`. A model that declares its own `find()` keeps it for
`$book->find()`, but `Book::find()` then fails: use `Book::query()->find()`. Pug errors show their line only with
`APP_DEBUG=true` (set it on your computer). Moving controllers to `Route::form`, `Route::auth` or `Route::webhook` is
optional.

**From 2.19.7 to 2.19.8.** The session cookie is `HttpOnly`, and `Secure` on HTTPS (directly or behind a load balancer
that sends `X-Forwarded-Proto: https`). Nothing to change, unless JavaScript of yours read the session cookie: use
`X-CSRF-Token` and the session instead.

**From 2.19.0 to 2.19.1.** No new tables. `update` replaces an untouched root `.htaccess` (it now refuses `backups/`)
and adds the new `.gitignore` lines (every `.env.*` file but `.env.example`). Vue apps get `env.request` without the
session cookie or the `Authorization` header (`request()->forClient()`). A Vite SPA made before 2.19.1 keeps its own
`src/common/app.js` and `src/main.js`: remove its `VITE_API_KEY`, as
[the SPA pages](https://github.com/caligrafy/caligrafy-quill/wiki/9.8.1---Setting-up-the-Vue-application) show.

## Reference: the production checklist

+ **Server files are not served.** `curl -I https://<your-host>/.env` answers `403` or `404`. The `.htaccess` files of
  Caligrafy deny dotfiles (`.env`, `.env.php`, `.git`...), the server-side folders and the tooling files, and prevent
  scripts in `public/uploads` from running. Keep them (they need `mod_rewrite` and `AllowOverride FileInfo` or `All`),
  or write the same rules for nginx.
+ **`APP_ENV=production`, `APP_DEBUG=false`**, keys of their own (`generatekeys`), no `.env` or `.env.php` in git
  (the `.gitignore` of the project also leaves out `.env.production`, `.env.testing` and every other `.env.*` but
  `.env.example`, 2.19.1).
  Changing the `APP_KEY` revokes every legacy API key and signs every user out.
+ **Personal access tokens, not the API key.** Give each program or agent its own token with the scopes it needs
  (`php caligrafer.php token create`), let browser apps use the session (the JS client, or `apiHeaders()` for controller
  routes, the session and `X-CSRF-Token` for the Vite SPA template since 2.19.1), then set `LEGACY_API_KEY=false`. The
  `API_KEY` is not a secret in the browser: Caligrafy gives it to the Vue apps it serves (`env.apiKey`, `null` with
  `LEGACY_API_KEY=false`).
+ **AI agents (MCP):** `Route::mcp()` accepts tokens only (a `POST /mcp` without one, session cookie or not, answers
  `401` with `WWW-Authenticate` and a JSON-RPC error, 2.19.1) and shows each agent the capabilities its scopes allow; mark
  capabilities that delete data `destructive: true`, and read `php caligrafer.php audit`.
+ **Administrators:** new users have `permissions` 0; promote administrators in the database.
+ **Queries:** the [query builder](https://github.com/caligrafy/caligrafy-quill/wiki/Queries) binds every value. Elsewhere
  use `?` placeholders (`Database::execute($sql, [$value])`, `all()` with `bindings`); never put request data in SQL.
+ **Uploads:** the `file` rule of a capability (`'cover' => 'required|file|extension,png;jpg|max_size,2mb'`), or
  `uploadFile($file, ['png', 'jpg'])`. Scripts, HTML and SVG files are always refused.
+ **Forms:** every `POST`, `PUT` and `DELETE` form prints `=csrf()`, `Route::form` included. Never write data in a
  closure route: use `Route::form` or a capability route.
+ **Sign-in:** `Route::auth` limits failed sign-ins and gives a new session id at sign-in. Behind a proxy every visitor
  has the proxy's address: the limit is then per username.
+ **Webhooks:** `Route::webhook` needs `verify`; with `'stripe'`, `STRIPE_WEBHOOK_SECRET` is the live endpoint's
  `whsec_...`. The capability refuses other callers and is safe to run twice.
+ **Jobs:** capabilities run by the queue, the scheduler or a webhook have full access: refuse other callers
  (`$context->actorType()`), and check who may ask before pushing a job.
+ **Example routes:** the OpenAI routes of the template call a paid API for anyone who reaches them: protect or remove
  them.
+ **Face login:** never sign in with a single face print; use `FaceLogin::verify()` and a passkey for sensitive accounts,
  with `PASSKEY_RP_ID` and `PASSKEY_ORIGIN` set ([face login](https://github.com/caligrafy/caligrafy-quill/wiki/9.9.2-Face-Detection-and-Face-Recognition#face-login)).
+ **Database changes:** `php caligrafer.php migrate status` shows no `changed` migration; the deploy step runs the
  pending ones.
+ **Health check:** `php caligrafer.php doctor` (or `--env .env.production`): every configured service `OK`, Stripe in
  live mode.

## Reference: what the framework does for you

| Threat | Protection |
| - | - |
| Downloading `.env`, `.git` or source files | `.htaccess` denies dotfiles, `application`, `framework`, `vendor`, `tests`, `qa`, `docker`, `claude-plugin`, `archives`, `backups` (2.19.1), `node_modules`, `caligrafer.php`, `composer.*`, `docker-compose.yaml`, `package(-lock).json` and `.sql`/`.log`/`.bak`/`.ini`/`.sh`/`.env` files |
| Uploading and running a PHP file | `uploadFile()` and the `file` rule accept an allow-list of extensions; `public/uploads/.htaccess` denies scripts |
| SQL injection | The query builder, `find()`, `create()`, `update()`, `delete()`, `search()`, the relationships and `all()` with `bindings` bind every value; column and table names are checked |
| Cross-site request forgery | Forms must carry the session's `_token` (`=csrf()`); JSON writes with the session need `X-CSRF-Token` (`Route::form`, `Route::auth`, capability routes); webhooks have no session: their signature is checked instead |
| Guessing passwords, session fixation | `Route::auth` counts failed sign-ins per username and address (429 after 5 in 15 minutes), answers unknown usernames as slowly as known ones, and gives a new session id and CSRF token at sign-in and sign-out |
| A spreadsheet running a formula from a download | `Route::download` puts `'` before cells that start with `=`, `+`, `-` or `@` |
| Cross-site scripting through Vue apps | The `env` given to Vue apps is escaped: URL parameters cannot inject code |
| A script of the page reading the session | `env.request` of a Vue app is `request()->forClient()` (2.19.1): the method, host, address, route, its values and the query string; never the `Cookie` (the session id) or `Authorization` headers, nor a `POST` body |
| Loading arbitrary files through client apps | `?app=` and the app folder accept letters, digits, `-` and `_` only, and only files of `public/<app>/` are served |
| A stolen password database | The authentication module stores `password_hash()` hashes |
| Signing in with a photo or a replayed face print | `FaceLogin` issues single-use liveness challenges and refuses identical or reused prints; `Passkey` (WebAuthn) checks a device signature bound to the domain |
| Choosing a secret through a form | The OpenAI example controller accepts only the documented commands and types |

## Reference: `php caligrafer.php update`

```bash
php caligrafer.php update --check [<version>]   # what it would change
php caligrafer.php update [<version>] [--yes] [--no-composer]
```

1. `framework/` and `claude-plugin/` are replaced whole.
2. Every other file of the release (`caligrafer.php`, `.bin/`, `Dockerfile`, `index.php`, `public/css`, `public/js`...):
   an untouched copy is replaced, a missing one added, a changed one kept with the new version next to it as
   `<file>.caligrafy-new`. Your documents (`README.md`, `LICENSE`...) are left alone.
3. `composer.json` gets the new packages (then `composer update` for them), `.gitignore` the new lines, `.env` the new
   settings with their defaults (existing values never change).
4. `php caligrafer.php upgrade --apply`, from the new release, brings `application/` up to date.

`application/`, the values of `.env`, `public/uploads` and `vendor/` are never replaced. `upgrade` checks for a newer
release too: when there is one, `upgrade` and `upgrade --apply` do what `update --check` and `update` do. Projects before
2.9.0 have no `update` command: see [Caligrafer: update](https://github.com/caligrafy/caligrafy-quill/wiki/Caligrafer#update).

## Reference: `php caligrafer.php upgrade`

```bash
php caligrafer.php upgrade            # dry run: prints the plan, changes nothing
php caligrafer.php upgrade --apply    # applies it
php caligrafer.php upgrade --local    # compares application/ with the templates of the release the project runs
php caligrafer.php upgrade --force application/views/Auth/login.pug          # replaces one customized file
php caligrafer.php upgrade --apply --keep application/views/default/index.pug   # keeps a default page that is now yours
```

Every file of `framework/settings/application` is reported as:

| Status | Meaning | With `--apply` |
| - | - | - |
| `missing` | new in the framework | copied into `application/` |
| `identical` | already up to date | nothing |
| `outdated` | an older template that you never changed | replaced |
| `kept` | an older template that you keep with `--keep` (remembered in the manifest) | **kept**; the new version is written next to it as `<file>.caligrafy-new` |
| `customized` | you changed it | **kept**; the new version is written next to it as `<file>.caligrafy-new` (or replace it with `--force`) |
| `held` | new files that would clash with how your project works (the user capabilities), and the files that need them | **not added**, with the reason; add one with `--force application/<path>` |
| `routes` | `config/routing/web.php` holds your routes | never replaced (except with `--force application/config/routing/web.php`) |

+ Every replaced file is first copied to `backups/caligrafy-upgrade-<YYYYmmdd-HHMMSS>/`. `.env`, `public/uploads`,
  `vendor` and the files you created in `application/` are never touched.
+ `initialize` and `upgrade --apply` write `application/.caligrafy-manifest.json` (the hash of each template as
  copied): commit it, it is how the next upgrade tells untouched files from yours. Projects without one are compared
  with the templates of the previous releases (`framework/settings/template-history.json`).
+ **Read the `outdated` list before `--apply`.** An untouched default page can be a page of your site: keep it with
  `--keep application/<path>`.
+ The settings of `framework/settings/.env.example` that your `.env` lacks are listed as `new`, obsolete ones as
  `obsolete` with what replaces them. Views and client apps that still use Bootstrap 3 classes are listed.
+ Client apps made with `php caligrafer.php app|bot|facedetect|ml` are listed with the files that differ from
  `framework/plugins/<type>`; they are never changed.
+ **Upgrading to 2.5.0** (the user capabilities): `upgrade --apply` adds `application/services/Users/` and replaces
  `AdminController` and `AuthController` when you never changed them. They are **held** when your `AdminController` is
  customized (set `CaligrafyUsers::ADMIN_LEVEL` to your level, then add the files with `--force`), or when
  `application/` already declares one of those capabilities or class names (rename yours first).

## Reference: behavior changes

| Area | Before | Now |
| - | - | - |
| `create()`, `update()`, `save()` | `0`, `''` and `false` were silently dropped | They are saved. Only `null` is skipped, and only the columns of the table are written (helper properties of a model are ignored) |
| `all()` | Raw clauses only | Raw clauses plus `bindings` for `?` placeholders |
| `search()` | Keywords inserted in the SQL | Keywords bound. Invalid column names throw an exception |
| `belongsToMany()` | Pivot creation failed with `INT UNSIGNED` ids or with a second pivot | Pivot columns copy the id type and constraint names are unique |
| `DB_PORT` | Ignored | Used, unless `DB_HOST` contains `;port=` |
| `session()`, `scripts()`, `keywords()`, `copyright()`, `metadata()` | Ignored `0`, `''` and `false` | Store them |
| `endWith()` | Only compared the last character | Compares the whole needle |
| `httpRequest()` | Only sent a body for `POST` | Sends it for every method except `GET` |
| `uploadFile()` | Accepted any extension | Allow-list (`DEFAULT_UPLOAD_EXTENSIONS` or your own list) |
| CSRF | An empty `APPROVED_AGENTS` approved requests without a User-Agent | Empty entries are ignored |
| `Payment::createCheckout()` | Crashed with a locale or a customer email | Works |
| `OpenAI` `COMPLETE` | Dropped the text after `[insert]` | Sends it |
| `GPT4OMINI`, `ASSISTANT_GPT4OMINI` | `gpt-4o mini` (invalid) | `gpt-4o-mini` |
| `Assistant::run()` | Always sent an empty model and no tools, disabling `file_search` | Only sends the overrides that are given |
| `Assistant::retrieveResponse()` | Could wait forever | Gives up after `$timeout` seconds (120) |
| `caligrafer initialize` | Generated new keys on every run | Keeps the keys of a signed project |
| Authentication | Reversible passcodes, any user could manage users | Hashed passwords (8 to 72 characters), administrators need `permissions >= 1` |
| `APP_DEBUG=false` | Still turned the SMTP debug output on (`.env` values are strings) | Parsed as a boolean |
| Bot app | Loaded the latest Vue from a CDN | Pinned Vue 2.7.16; since the library upgrade, a Vue 3 chat on `scripts('vue')` (Vue 3.5.44) |
| Error responses | HTTP `200` for every error, including PHP fatal errors, with `[ERROR ...]` text | Real status codes: `401` (1004, access denied: since 2.7.0 the message ends with the reason), `403` (3000, CSRF), `404` (1001, controller or action), `405` (1000, for your own `Errors::raise(1000)`: the router does not raise it), `500` (other errors; for PHP fatal errors and uncaught exceptions the message is only shown with `APP_DEBUG=true`). API calls get `{"error": {"code": ..., "message": ...}}`. **Clients that expected `200` on errors must check the status** (axios and `fetch().ok` now treat them as failures) |
| Controller names | The example controllers of `application/controllers/core/` were global classes: a controller of yours named `AIController`, `AdminController`, `AuthController`, `ClientController` or `WatsonController` was a fatal error (`Cannot redeclare class`) on every page | They are in `Caligrafy\Controllers`. Routes accept fully qualified controllers (`'Shop\OrderController@show'`, leading `\` allowed); a short name that is not a declared class falls back to `Caligrafy\Controllers`, so old routes keep working and your own class of the same name wins. If your code referenced an example class directly (`new AuthController()`, `extends AIController`), use `Caligrafy\Controllers\...` |
| Relationships with namespaced models | The default foreign key of `hasOne`, `hasMany`, `belongsToMany` included the namespace | Uses the short class name (`Shop\Order` gives `order_id`) |
| Client apps (`?app=`) | Any path, including sub-folders and `../` | A file name of `public/<app>/` only (letters, digits, `-`, `_`): no sub-folders, no symbolic links pointing outside the app |
| Pug views (2.17.0) | Compiled on every request | Compiled once and kept in a private folder of the temporary directory, again when a view or a file it includes changes (`VIEW_CACHE=false` turns it off) |
| Classes of `application/` (2.18.0) | Every PHP file loaded on the first unknown class of each request | Each class loaded when first used, from a class map; a file with functions or top-level code is still loaded at start (`CLASS_MAP=false` restores the old way) |
| `tests/` (2.18.0) | Every PHP file loaded on each request | Your app's PHPUnit tests (`php caligrafer.php test`), never loaded on a page |
| Capabilities (2.18.0) | Built with `new` | Built by the container: their constructors get what they ask for (`application/config/container.php`) |
| Sessions (2.19.0) | Started on every request | Started when used. A request with a session cookie, and every `POST`, `PUT` and `DELETE`, starts it as before. A `GET` or `HEAD` without one (a first visit, an API client, an agent) gets a session only when it reads the CSRF token (`session('token')`, `csrf()`), writes the session after `config.php`, or prints a page that carries the token. Code that reads `$_SESSION['token']` directly on such a request should call `session('token')`. `SESSION_LAZY=false` starts every session, as before |
| Pug debug mode (2.19.0) | Always on | Only with `APP_DEBUG=true` (Pug line numbers in errors); cached views run through Phug's Optimizer (`VIEW_OPTIMIZER=false` turns it off) |
| Output buffer (2.19.0) | 1 MB reserved for every request | Grows with the page; errors still get their status code |
| Database rows (2.19.0) | Encoded to JSON and back (a row with invalid UTF-8 became `null`) | Fetched as arrays: the same arrays, faster, and such a row is kept |
| `Model::find()` (2.19.0) | A declared method | Provided through `__call()` (`$book->find(1)`, as before) and `__callStatic()` (`Book::find(1)`, the query builder). A model that declares its own `find()` keeps it for instances, but `Book::find()` then fails: use `Book::query()->find(1)`. `method_exists($model, 'find')` is now `false` |
| `.env` (2.19.0) | Parsed on every request | Read from `.env.php` when the deploy step or `php caligrafer.php env cache` compiled it and `.env` has not changed since (`env clear` removes it) |
| `Auth::logout()`, `terminateSession()` (2.19.0) | Always touched the session | Only when one is active |

## Reference: upgrading to the current libraries (October 2026)

This release moves Caligrafy to current versions of every library and service. As with the security fixes, **new projects get everything automatically**; existing projects follow the steps below. The [Release notes: October 2026](https://github.com/caligrafy/caligrafy-quill/wiki/Release-notes:-October-2026) give the same steps as a checklist, with every other change of October 2026.

**1. Requirements:** PHP 8.3 or higher (the Docker image uses PHP 8.5), MySQL 8.4, Node.js 20.19+ or 22.12+ for the Vue SPA template. Run `composer update` after pulling the framework.

**2. `.env`:** add the new settings when you use the matching module (see `framework/settings/.env.example`):

| Setting | Module |
| - | - |
| `COINBASE_API_KEY_NAME`, `COINBASE_API_KEY_SECRET` (replace `CRYPTO_PAY_KEY`) | Crypto payments (Coinbase Business) |
| `WATSON_URL` (required), `WATSON_ENVIRONMENT_ID`, `WATSON_API_VERSION` | Watson bots |
| `OPEN_AI_MODEL`, `OPEN_AI_IMAGE_MODEL` (optional) | OpenAI and Assistants |
| `GROQ_MODEL`, `GROQ_VISION_MODEL` (optional) | Groq agents |
| `PWA_SERVICE_WORKER` (optional, `false` by default) | Offline page of installed apps ([Views](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#install)) |

Copy the new views of `framework/settings/application/views` (at least `default/master/layoutblocks.pug`, `default/modules/messaging.pug`, `default/modules/cryptopayment.pug`, `default/pages/payment.pug`, `default/pages/checkout.pug` and the `Auth` views) and delete `default/modules/gestures.pug`. Replace `default/modules/install.pug` (add-to-homescreen) with the new one and add `default/modules/serviceworker.pug` (`php caligrafer.php upgrade --apply` does both when you never changed them). If you customized `layoutblocks.pug`, add `meta(name='theme-color', content='#ffffff')` and `link(rel='manifest', href="{$home}public/manifest.webmanifest")` to the headers, and `include ../modules/serviceworker` then `if $install` / `include ../modules/install` after `include ../modules/standalone` (see [install to home screen](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#install)). If you customized the root `.htaccess`, copy its `Service-Worker-Allowed` lines and the `AddType application/manifest+json .webmanifest` block. Update `public/css/theme.css` too: its end keeps the Caligrafy black and white look on Bootstrap 5 (14px text, cards, black `btn-primary`, white `btn-secondary` with black text, black focus rings, readable `a.btn` links). It also keeps the Bootstrap 3 layout: full-width page container, header title centered in the header, grids centered in their wrapper, Caligrafy card borders and colors, Bootstrap 3 text color and button metrics. If you customized `theme.css`, copy everything from the "Bootstrap 5 compatibility layer" comment to the end of the file. Its heading margins apply to `body.caligrafy-layout` (and `body#gesturize`, so older copies of `default/master/layout.pug` keep their look): add `class='caligrafy-layout'` to the body of your own layouts. Client apps that reuse the Caligrafy header can replace a custom `margin: 20px 0 10px` on the header title with the class `caligrafy-header` on the header. In your own views, wrap Bootstrap columns in a `.row` and move them one breakpoint up (`col-sm-6` becomes `col-md-6`, `col-md-4` becomes `col-lg-4`, see [Views](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views)). Single page apps created before October 2026 load Bootstrap 3 and jQuery from their `index.html`: replace those three tags with `https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css` and `https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js` and update the columns of their components the same way. To keep Bootstrap 3 in a project for now, add to `application/config/config.php`:
```php
scripts('bootstrap_css', 'https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/css/bootstrap.min.css');
scripts('bootstrap_script', 'https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/js/bootstrap.min.js');
scripts('bootstrap_jquery', 'https://cdn.jsdelivr.net/npm/jquery@3.7.1/dist/jquery.min.js');
```

## Testing the framework

> Contributors: [Testing Caligrafy](https://github.com/caligrafy/caligrafy-quill/wiki/Testing-Caligrafy) explains every phase of the QA suite, the unit tests, how to add a test and the release process.

Caligrafy comes with a QA suite that runs the framework, HTTP and tooling tests in an isolated Docker stack (the first free ports from 8090 and 3316, so it never clashes with your development servers). From a clean checkout of the framework:
```bash
composer install
./qa/run.sh
```
The suite refuses to run when an `application` folder or a `.env` file that it did not create is present. Its stack includes stripe-mock, and the OpenAI, Coinbase, Groq and Watson integrations are tested against local mock servers, so no API key is needed.

If the Docker image cannot be built on your network (see the Docker troubleshooting below), build or obtain the `quillqa-web` image once and run the suite with `QA_NO_BUILD=1 ./qa/run.sh`: it reuses the existing image instead of rebuilding it.

The suite also runs the PHPUnit unit tests of the framework core (`qa/unit`: routing, errors, requests, models, validation, upgrade and doctor helpers, face login checks and passkeys, capabilities, tokens, deploy, the scheduler, the view cache, the class map, migrations, the container, the cache, the query builder, lazy sessions and the declarative routes). They need no web server, database or `.env`, so you can run them on their own with the development dependencies installed:
```bash
composer install
vendor/bin/phpunit
```

**`.env` comments:** write comments on their own line (`# ...`). Some tools and the QA suite read `.env` with PHP's `parse_ini_file`, which fails on text after `true`/`false` (`FLAG=false # comment`) and on parentheses in unquoted values; the QA tooling phase checks the templates.

**Docker image build killed during `apt-get` on slow or proxied networks:** on some corporate networks `apt-get install` in `docker/Dockerfile` grows to several GB while it retries slow downloads and the build fails with "Killed" / "cannot allocate memory". Give Docker Desktop more memory (Settings, Resources), close other containers and retry, or build on another network; for the QA suite, reuse an existing image with `QA_NO_BUILD=1`.

## Other ways

### The manual upgrade

Without `update` (a project you cannot run it in), the steps it does by hand:

**1. Update the framework**
```bash
git pull   # or: composer update / download the new release
```

**2. Copy the root and uploads `.htaccess` files** from the new release (keep your own additions). Then check that `.env` is no longer served: `curl -I http://<your-host>/.env`.

**3. Update the files of your `application` folder** that you have not customized, from `framework/settings/application` (`php caligrafer.php upgrade` does this step for you):

| File | Why |
| - | - |
| `views/Client/app.pug` | Path traversal through `?app=` and script injection through URL parameters (**required** if you use Vue, bot, FaceDetect or ML apps) |
| `controllers/core/AI/ClientController.php` | Validates the `?app=` parameter |
| `controllers/core/AI/AIController.php` | The previous version let a form select any PHP constant, including your `.env` secrets (**required** if the `/ai` routes are enabled) |
| `controllers/core/Auth/AuthController.php` and `AdminController.php` | Password hashing, exact username lookup (the previous login accepted `%` as a username), admin pages restricted to `permissions >= 1` |
| `models/Auth/User.php` | `findByUsername()`, `hashPassword()`, `verifyPassword()`, `needsRehash()` used by the controllers above |
| `views/Auth/login.pug`, `register.pug`, `manageusers.pug` | Passwords of up to 72 characters |
| `models/Auth/create_db.sql` | No longer drops the `users` table |
| `controllers/core/AI/*.php`, `controllers/core/Auth/*.php` | The example controllers are declared in the `Caligrafy\Controllers` namespace, so a controller of yours with the same name (`AIController`...) no longer collides with them. Your routes do not need to change: short names such as `'ClientController'` fall back to `Caligrafy\Controllers` |
| `config/routing/web.php` | The `catch` at the end calls `Errors::handle($e);` instead of `echo $e->getMessage();` (add `use Caligrafy\Errors;`), so API clients get JSON errors. Without this change the framework errors (401, 403, 404) still get their status code, but other exceptions (database errors, your own) still answer `200`, and every body stays plain text |

If you customized these files, apply the same changes to your versions: compare them with the new files of `framework/settings/application`.

**4. Upgrade the `users` table** (authentication module):
```sql
ALTER TABLE users MODIFY passcode varchar(255) NOT NULL;
```
Since 2.18.0, put such a change in a [migration](https://github.com/caligrafy/caligrafy-quill/wiki/Migrations) (`php caligrafer.php migrate make users_passcode_255`) so that every server gets it.
Existing users keep logging in with their passwords: their passcode is converted to a hash on their next login. Keep the same `APP_KEY` until they have all logged in once.

**5. Promote your administrators**: `UPDATE users SET permissions = 1 WHERE username = '...';`

**6. Review the [behavior changes](#changes)** in your own code.

## Common mistakes

+ **Pages are slow online.** `APP_DEBUG=true`: Phug's debug mode makes every page about three times slower.
+ **A setting changed on your own server is ignored.** It is not: an edited `.env` is read as it is until the next
  `php caligrafer.php env cache`. A value that still looks old comes from a `.env.php` compiled from another `.env`:
  run `env cache` again, or `env clear`.
+ **`.env.php` in git.** It holds every secret of `.env`: remove it from git, change the keys, and keep the
  `.gitignore` line.
+ **A form answers `[ERROR 3000]` after the update to 2.19.** Its page does not print `=csrf()`, or code reads
  `$_SESSION['token']` before the session started: use `session('token')`. `SESSION_LAZY=false` brings the old sessions
  back while you fix it.
+ **`update` piped into `tail`.** The pipe hides its exit code and its last lines (`upgrade --apply`): run it whole.
+ **`.caligrafy-new` files committed.** Merge them into your files and delete them before committing.
+ **`backups/` online.** It can hold views and SQL scripts. Before 2.19.1 the root `.htaccess` did not refuse it: take
  the 2.19.1 `.htaccess` (`backups` in its folder rule), delete the folder, or keep it out of the server (the
  production image leaves it out).
